# AUR packaging for `kolir-git`

Status: **draft (phase 2). Not published.** The AUR package does not exist yet;
nothing in this directory has been built, installed, signed or pushed. Treat the
content as a reviewed draft, not as an installable package.

- Package: `kolir-git` (VCS package, `provides=('kolir')`, `conflicts=('kolir')`)
- Upstream: <https://github.com/ZaViBiS/kolir> (from `git remote get-url origin`,
  normalised to `git+https://github.com/ZaViBiS/kolir.git`)
- Licence: GPL-3.0-or-later (matches `LICENSE`)
- Architecture: `any` (only shell scripts, Python, QML and text files)

## Installed layout

| Repository path            | Installed path                                  |
| -------------------------- | ----------------------------------------------- |
| `config/`                  | `/usr/share/kolir/config/`                      |
| `tools/kolir.py`           | `/usr/bin/kolir` (`0755`)                       |
| `zshrc`                    | `/usr/share/kolir/zshrc`                        |
| `dice.zsh-theme`           | `/usr/share/kolir/dice.zsh-theme`               |
| `LICENSE`                  | `/usr/share/licenses/kolir/LICENSE`             |
| `$pkgver`                  | `/usr/share/kolir/.version`                     |

The package never writes into `$HOME`. Files are installed read-only under
`/usr`; every per-user file (Hyprland/Foot/Matugen glue, zsh profile, generated
palette) is created by `kolir setup` running as the user. `README.md` and
`AGENTS.md` are deliberately not packaged. `.git`, `config/quickshell/.qmlls.ini`
and build artefacts are never copied because `package()` runs inside a fresh VCS
checkout that only contains tracked files.

The package ships no systemd units. `kolir setup --auto-reload` renders
`kolir-reload.path` and `kolir-reload.service` into `~/.config/systemd/user`,
using `/usr/bin/kolir` when the checkout copy is absent, and enables the path
unit. This keeps the watched paths tied to the active root and avoids duplicating
units in `/usr/lib`.

`config/foot/colors.ini` and `config/quickshell/colors.json` are tracked
fallback snapshots, not build outputs; they ship with the tree but are not the
files the session uses (`~/.config/foot/colors.ini` and
`~/.config/quickshell/colors.json` are generated by Matugen).

## Build and check locally

```sh
cd packaging/aur
makepkg -f                 # build (VCS clone + package)
namcap PKGBUILD            # metadata / dependency checks
namcap kolir-git-*.pkg.tar.zst
```

`makepkg` clones `source=()` from the URL above, so **unpushed commits are not
included**. Push the branch first, or use a temporary PKGBUILD with a local
source while iterating.

Install the result you just built:

```sh
sudo pacman -U kolir-git-r<count>.<hash>-1-any.pkg.tar.zst
kolir setup                # as your user, once
```

`makepkg -si` does the same build plus install in one step. Neither command is
run automatically by the repository; they are the manual release checks.

## Publishing to the AUR

One-time setup:

1. Create an AUR account at <https://aur.archlinux.org> and add an SSH public key
   under *My Account → SSH Public Key*.
2. Verify access: `ssh aur@aur.archlinux.org help`.

Publish/update:

```sh
git clone ssh://aur@aur.archlinux.org/kolir-git.git
cd kolir-git
cp /path/to/kolir/packaging/aur/{PKGBUILD,kolir.install} .
makepkg --printsrcinfo > .SRCINFO
git add PKGBUILD kolir.install .SRCINFO
git commit -m "Update to r<count>.<hash>"
git push
```

`.SRCINFO` must always be regenerated with `makepkg --printsrcinfo` after any
`PKGBUILD` change; the AUR renders metadata from it, not from the `PKGBUILD`.

If the package is rejected because `kolir` or `kolir-git` already exists, do not
force the push: resolve ownership with the current maintainer first.

## Updating an installed package

`kolir-git` is a VCS package: the version is
`r<commit-count>.<short-hash>` and only changes when the package is rebuilt.
`pacman -Syu` never updates AUR packages.

```sh
paru -Syu                  # with Devel enabled, rebuilds kolir-git
paru -Syu --devel          # force a VCS rebuild regardless of config
```

The author's `/etc/paru.conf` already enables `[options] Devel`, so a plain
`paru -Syu` is enough there. For yay:

```sh
yay -Syu --devel --timeupdate
```

To rebuild by hand without an AUR helper:

```sh
cd packaging/aur && makepkg -f && sudo pacman -U kolir-git-*.pkg.tar.zst
```

After an update, `kolir-reload.path` restarts the shell when it was enabled with
`kolir setup --auto-reload`; otherwise run `kolir reload`.

## Rollback

Keep the previously built `*.pkg.tar.zst` files. Rolling back is a local
downgrade, no AUR interaction:

```sh
sudo pacman -U kolir-git-r<old-count>.<old-hash>-1-any.pkg.tar.zst
```

A VCS rollback also needs the matching upstream commit checked out if you rebuild
instead of reusing an old archive. Since the package only owns files under
`/usr`, downgrading never touches `~/.config`; after a rollback run
`kolir setup` only if the older version expects different glue.

  intentionally unversioned because `matugen-bin` provides it without a version;
  the code needs the 4.x `-t scheme-neutral` CLI. Re-check these at release time.
- **Two dependency adjustments against the starting list.**
  `glib2` is a hard dependency because `toggle-theme.sh` calls `gsettings`
  unguarded; `kconfig` (`kwriteconfig6`, same script) is an optdepend so a plain
  Hyprland install does not pull KDE frameworks. `curl` is used for the solar
  location lookup but is already guaranteed by `pacman`'s own dependency on it.
- **AUR-only optdepends.** `wl-screenrec` and `mocu-xcursor` are not in the
  official repositories, so they stay optional and are documented instead of
  listed as hard dependencies.
- **Local build source.** `makepkg` uses the pushed GitHub branch, not the working
  tree. Push before building the real package, or test `package()` with a local
  source copy.
