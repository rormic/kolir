# AGENTS.md — Desktop Environment Reference

## 1. Overview
`kolir` is an Arch Linux desktop configuration for a Wayland session built on Hyprland (configured with Lua) and a custom Quickshell (QML) shell. The shell is Material Design 3–inspired: the bar is a full-screen top-layer surface that paints the bar strip and hosts an embedded settings popout, while a separate bottom-layer frame surface fills the window gaps and frames the desktop below windows. The shell also owns a separate sound popup and a full-screen wallpaper grid. Matugen extracts a neutral Material 3 palette from the current wallpaper and reactively updates Hyprland, Foot, GTK, and Quickshell colors. Machine-specific Hyprland settings live in `~/.config/hypr/user.lua`; `kolir setup` (from `tools/kolir.py`) deploys the symlinks and per-user glue once, and later updates are just a `git pull`. Packaging is phase 2 and not yet available.

## 2. Directory Map
- [config/hypr/hyprland.lua](file:///home/sakura/.local/share/kolir/config/hypr/hyprland.lua): Shared Hyprland config using the Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.layer_rule`, `hl.animation`). Loads generated `~/.config/hypr/colors.lua` when present, defines keybinds (launcher, screenshots, wallpapers, recording, media/brightness keys), and loads `~/.config/hypr/user.lua` last.
- [config/hypr/user.lua.example](file:///home/sakura/.local/share/kolir/config/hypr/user.lua.example): Template for the untracked machine-specific file (`monitors`, autostart, cursor/env, personal binds, overrides).
- [config/hypr/hyprsunset.conf](file:///home/sakura/.local/share/kolir/config/hypr/hyprsunset.conf): Valid hyprlang config for the blue-light filter. Runtime control and the automatic schedule are owned by Quickshell (`HyprsunsetService`), so native `profile { ... }` blocks should stay commented out.
- [config/hypr/scripts/](file:///home/sakura/.local/share/kolir/config/hypr/scripts): Helper scripts, all `kebab-case`:
  - `lib/root.sh`: POSIX root resolution shared by every helper (`kolir_root [script_dir]`). Order: `$KOLIR_ROOT`, then the physical root above `<dir>/config/hypr/scripts` (works through the `~/.config/hypr/scripts` symlink), then `/usr/share/kolir`. Callers pass `$SCRIPT_DIR`; `KOLIR_DIR` is still accepted as a legacy override by `brightness.sh` and `screen-record.sh`.
  - `qs-ipc.sh` / `launch-shell.sh`: resolve the root through `lib/root.sh` and `exec qs -p <root>/config/quickshell …`; use them instead of hardcoding a checkout path in binds or autostart.
  - `lib/monitors.sh`: shared monitor selection sourced by zsh and sh callers. `kolir_monitor_name` / `kolir_focused_monitor_name` resolve `$KOLIR_MONITOR`, then the focused monitor from `hyprctl monitors -j`, then the first monitor, and only `kolir_monitor_name` falls back to `DP-1`; `kolir_monitor_geometry` / `kolir_focused_monitor_geometry` return `x,y wxh`.
  - `lib/awww.sh`: version-tolerant wallpaper lookup. `kolir_awww_wallpaper_path <monitor>` asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first (also the cache root), decoding both the NUL-separated 0.12.x layout and the older one-piece layout; failures name the awww version, path, and entries found.
  - `set-wallpaper.sh`: applies an image with `awww img -t random --transition-fps 180` (silent exit 0 on an empty/cancelled picker, explicit errors otherwise).
  - `open-wallpaper-picker.sh`: primary wallpaper trigger. Toggles the Quickshell `wallpaper` panel through `qs … ipc call wallpaper toggle`; when no shell answers (or `qs` is missing) it `exec`s `select-wallpaper.sh`, so Zenity remains the fallback.
  - `select-wallpaper.sh` / `random-wallpaper.sh`: pick a wallpaper with Zenity or `find`+`shuf`, then call `set-wallpaper.sh` and `generate-colors.sh`.
  - `generate-colors.sh`: sources `lib/monitors.sh` + `lib/awww.sh` + `lib/theme.sh`, resolves the wallpaper for the selected monitor, applies the persisted Appearance choice (scheme type, contrast, mode), then runs Matugen.
  - `toggle-theme.sh`: flips the resolved light/dark theme, syncs the persisted Appearance mode, applies GTK/KDE theme names through `lib/theme.sh`, and regenerates colors.
  - `lib/theme.sh`: shared light/dark application (`kolir_write_theme_state`, `kolir_apply_theme_mode`, `kolir_apply_system_theme`) plus `kolir_sync_appearance_mode` for the bar toggle. POSIX; sourced by `generate-colors.sh` and `toggle-theme.sh`.
  - `brightness.sh`: forwards `up`/`down` to the Quickshell `brightness` IPC target, which drives both the internal panel (`brightnessctl`) and the external monitor (`ddcutil`); it falls back to `brightnessctl -c backlight -e4 -n2 set 5%±` only when no shell answers.
  - `screen-record.sh`: recording toggle/setup/start with `wf-recorder` (fallback `wl-screenrec`), audio mixing, encoder selection, and state files under `$XDG_RUNTIME_DIR/kolir`. It sources `lib/monitors.sh`, `screen-record/audio.sh`, `screen-record/encoders.sh`, and `screen-record/monitors.sh` through `SCRIPT_DIR=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)`.
- [config/quickshell/shell.qml](file:///home/sakura/.local/share/kolir/config/quickshell/shell.qml): Quickshell `ShellRoot`. Instantiates `Frame`, `Bar`, `Launcher`, `Notification`, `VolumeOsd`, `BrightnessOsd`, `RecordingSetup`, `Shortcuts`, and `WallpaperPicker`; settings is embedded in `Bar`.

## 3. Data Flow
```
Wallpaper (SUPER+CTRL+T grid / SUPER+CTRL+ALT+T random)
        ├─> open-wallpaper-picker.sh
        │     ├─> qs ipc call wallpaper toggle  (WallpaperPicker.qml)
        │     │     ├─> wallpaper-thumbnails.sh  ──> ~/.cache/quickshell/wallpaper-previews
        │     │     └─> selection / Random
        │     └─> select-wallpaper.sh (Zenity fallback when no shell answers)
        └─> set-wallpaper.sh (awww img)
              └─> generate-colors.sh
Theme toggle (Bar ThemeToggle.qml)
        └─> toggle-theme.sh (~/.cache/current_theme, GTK/KDE theme)
              └─> generate-colors.sh
Appearance page (SettingsMenu → AppearancePage.qml)
        └─> AppearanceService.setType/setContrast/setMode
              ├─> ~/.cache/quickshell/appearance.json
              └─> generate-colors.sh with KOLIR_MATUGEN_TYPE/CONTRAST/MODE
                    └─> ~/.config/quickshell/colors.json ──> Colors.qml (live)
generate-colors.sh
  selects the monitor ($KOLIR_MONITOR, then focused, then first, then DP-1)
  resolves the wallpaper (awww query -j, then the version-tolerant cache scan)
  selects the config ($KOLIR_MATUGEN_CONFIG, ~/.config/matugen/config.toml, repo copy)
  pre-validates every template input with python3 + tomllib
  reads ~/.cache/current_theme (creates it as dark when missing)
  reads ~/.cache/quickshell/appearance.json (env KOLIR_MATUGEN_* wins)
    scheme type: one of the ten matugen --type values (default scheme-neutral)
    contrast: -1..1 (default 0)
    mode: auto → sunrise/sunset from HyprsunsetService, light/dark explicit
  runs: matugen image <path> --source-color-index 0 --mode <mode> --type <type> --contrast <c>
        ├─> ~/.config/foot/colors.ini
        ├─> ~/.cache/terminal-sequences  ──> tee /dev/pts/* (live Foot)
        ├─> ~/.config/hypr/colors.lua    ──> hyprctl reload
        ├─> ~/.config/quickshell/colors.json
        ├─> ~/.config/gtk-3.0/colors.css ──> imported by ~/.config/gtk-3.0/gtk.css
        ├─> ~/.config/gtk-4.0/colors.css ──> imported by ~/.config/gtk-4.0/gtk.css
        └─> ~/.config/matugen/…obsidian output (only when setup added the block)
```
- **Wallpaper Trigger**: `SUPER+CTRL+T` runs `config/hypr/scripts/open-wallpaper-picker.sh`, which toggles the Quickshell `wallpaper` panel over IPC and falls back to `select-wallpaper.sh` (Zenity) when the shell is not running. The panel's selection applies `set-wallpaper.sh` (`awww img`) and then `generate-colors.sh`; its Random button and `SUPER+CTRL+ALT+T` run `random-wallpaper.sh`, which does the same. Closing the panel with Escape or an outside click applies nothing.
- **Theme Trigger**: `ThemeToggle.qml` watches `~/.cache/current_theme` and calls `toggle-theme.sh`. The script flips `light`/`dark`, updates GNOME/GTK and KDE theme settings through `lib/theme.sh`, writes the resolved state file, syncs the persisted Appearance mode to the explicit new value, and calls `generate-colors.sh`.
- **Appearance Trigger**: `AppearancePage.qml` (Settings → Appearance) or the `appearance` IPC target changes the Matugen scheme type, contrast or auto/light/dark mode. `AppearanceService` debounces the change, persists one-line JSON in `~/.cache/quickshell/appearance.json`, and reruns `generate-colors.sh` with `KOLIR_MATUGEN_TYPE`, `KOLIR_MATUGEN_CONTRAST` and `KOLIR_MATUGEN_MODE`. `auto` is a real sunrise/sunset schedule, not a wallpaper guess: it reuses `HyprsunsetService`'s detected location and solar times (the same source as the night-light sheet), resolves to light between sunrise and sunset and dark otherwise, and rechecks every 30 s and when the location arrives. The page always shows the detected location (with a refresh button) and the sunrise/sunset cards, plus a status line such as `Dark until 06:42 tomorrow`; while the location or times are unavailable Auto holds the current theme and the status explains why. Explicit light/dark (and every resolved Auto switch) update `~/.cache/current_theme` and GTK/KDE, so the bar toggle agrees. `Colors.qml` watches `colors.json`, so the palette and the preview swatches update without restarting the shell. The IPC calls are `setType <scheme-…>`, `setContrast <-1..1>`, `setMode auto|light|dark`, `regenerate` and `status`.
- **Shortcut Sheet Trigger**: `SUPER+D` runs `qs-ipc.sh shortcuts toggle`, which opens `Shortcuts.qml`; the panel re-reads `hyprctl binds -j` on every open, so binds added to `hyprland.lua`/`user.lua` show up without a shell restart. The launcher is still opened by tapping `Super` alone. Hyprland reports the dispatcher but not its Lua argument, so each bind in `hyprland.lua` carries a `description` that becomes the row's action text; without one the sheet falls back to a generic dispatcher name.
- **Keep Awake Trigger**: `CaffeineCard` (Settings → main page) or `qs ipc call caffeine …` drives `CaffeineService`. While enabled, `Bar.qml` holds a `Quickshell.Wayland.IdleInhibitor` on the bar surface, so `hypridle` receives no idle events and skips lock, DPMS and suspend. The state and timer live in `$XDG_RUNTIME_DIR/kolir/caffeine.json`.
- **Battery Indicator**: `BatteryService` reads `UPower.displayDevice` (the aggregate of every internal pack) plus `/sys/class/dmi/id/chassis_type` through `ShellPaths.chassisType`. `Battery` is hidden on desktops; on a portable chassis (8/9/10/11/14/30/31/32) it shows the level and percentage, or the red `battery_alert` glyph when UPower reports no usable battery. The chip turns primary while charging and error at 15% or less.
- **Headset Battery**: `DeviceBatteryService` runs `python3 <root>/config/quickshell/scripts/device-battery/main.py --state <cache>` on a 60 s timer through `ShellPaths.deviceBatteryScript` / `deviceBatteryState`. The helper asks BlueZ for connected `audio-*` / Audio-Video-class devices and resolves each one through the provider chain: a fresh exact reading from the cache, exact providers (`sony.py`, MDR v2 `22 00` → `23 00 <percent> <charging>` over the `956c7b26-…` RFCOMM UUID), a stale exact reading, then the generic `org.bluez.Battery1` provider. A device with no reading is omitted, so `[]` hides `DeviceBattery` and the bar is unchanged. `settings/bluetooth/BluetoothDeviceRow.qml` matches its row address against `DeviceBatteryService.devices` and prefers that exact percentage over Quickshell's coarse `BluetoothDevice.battery`; devices without a helper reading keep the BlueZ value, so the row never loses its indicator. The chip turns primary while charging and error at 15% or less; it never shows an OSD or notification. Without `python-dbus`/`python-gobject` the helper prints `[]` and the feature stays dormant.
- **Brightness Trigger**: the bar `Brightness` chip (wheel), `qs ipc call brightness up|down|set <percent>`, and `XF86MonBrightness*` → `brightness.sh` all drive `BrightnessService`. The service adjusts every available backend (internal `brightnessctl`, external `ddcutil` VCP 0x10) and emits `brightnessChangedManually`, which `BrightnessOsd` shows. `brightness.sh` forwards the step over IPC and falls back to `brightnessctl -c backlight -e4 -n2 set 5%±` when no shell answers.
- **Palette Generation**: `generate-colors.sh` is zsh-based. It selects the monitor through `lib/monitors.sh` (`$KOLIR_MONITOR`, focused, first, then `DP-1`) and resolves the wallpaper through `lib/awww.sh`, which prefers `awww query -j` and otherwise scans the version-named cache tolerantly, so neither the output name nor the awww version is hardcoded. Config selection is `$KOLIR_MATUGEN_CONFIG` -> `~/.config/matugen/config.toml` -> `<root>/config/matugen/config.toml`; every template input is pre-validated with python3 + tomllib so a missing template cannot produce a partial palette. A missing `~/.cache/current_theme` is created as `dark`. Appearance selection comes from `KOLIR_MATUGEN_TYPE/CONTRAST/MODE` (set by `AppearanceService`) or `~/.cache/quickshell/appearance.json`; the type must be one of matugen's ten `scheme-*` values, contrast is validated to -1..1, and `mode=auto` keeps the last resolved `current_theme` (the shell owns the sunrise/sunset switch), while light/dark also update the resolved theme. It runs Matugen with `--source-color-index 0 --type <type> --contrast <c> --mode <mode>`, skips the lock palette gracefully when `hyprlock.toml` is absent (the lock run keeps `--mode dark` but follows the selected type/contrast), and makes the `hyprctl reload` hook a no-op when no live Hyprland instance exists. The lock background/glow step is skipped when `ffmpeg` is missing; it renders at the geometry reported by `kolir_monitor_geometry` (falling back to 2560x1440 when Hyprland cannot report a size), which keeps the lock image matched to the monitor after the earlier geometry bug.
- **Consumer Updates**:
  - **Quickshell**: `config/quickshell/theme/Colors.qml` watches `ShellPaths.colorsJson` with `FileView`, parses it in `onLoaded`, and maps snake_case keys to camelCase QML properties without restarting the shell.
  - **Foot**: Matugen writes `~/.cache/terminal-sequences`; its `post_hook` tees ANSI color sequences into open pseudo-terminals. New Foot instances read `~/.config/foot/colors.ini`.
  - **Hyprland**: The Matugen `post_hook` runs `hyprctl reload`; `hyprland.lua` loads `~/.config/hypr/colors.lua` with `dofile()` when it exists.
  - **GTK**: Matugen writes `~/.config/gtk-3.0/colors.css` and `~/.config/gtk-4.0/colors.css`; the import stubs `gtk.css` (`@import url("colors.css");`) are created by `kolir setup` because they are user glue, not package files. `toggle-theme.sh` additionally changes the GTK color-scheme/theme and KDE `ColorScheme`.
- **User Glue**: `kolir setup` creates symlinks for `~/.config/hypr/{hyprland.lua,scripts,hyprsunset.conf,hyprlock.conf,hypridle.conf}`, `~/.config/mpv/mpv.conf`, `~/.config/matugen/hyprlock.toml`, and (when the templates path is absent) `~/.config/matugen/templates`; it writes the Foot loader and empty `colors.ini`, copies `matugen/config.toml`, the GTK stubs, `~/.cache/current_theme`, the Quickshell palette snapshot, `user.lua`, and `hyprlock-colors.conf` only when absent, backs up anything it replaces, creates `~/Pictures/wallpaper`, refreshes `<root>/.version`, and enables `hypridle.service` and `hyprsunset.service` (unless `--no-systemd`, and skipping a unit whose binary is missing). ## 4. Conventions
- **Naming**: QML files and types are `PascalCase`; JavaScript modules are `camelCase`; directories are lowercase except the existing `nightLight/` feature directory; Hyprland shell scripts and `screen-record/` helper modules are `kebab-case`. Preserve IPC targets, layer namespaces, JSON keys, and CLI arguments exactly.
- **Shared Components**: Reusable UI primitives live in `config/quickshell/bar/components/` (`Surface.qml`, `Pill.qml`, `IconButton.qml`, `AppIcon.qml`, `ProgressIndicator.qml`, `VolumeSlider.qml`, `CopyableValue.qml`, `StateLayer.qml`, `EmbeddedSheet.qml`). Prefer these over duplicating surface styling. `CopyableValue` is a read-only `Text` that copies its `value` through `wl-copy` and shows a hover copy glyph that turns into a check; use it for detail strings in settings instead of plain `Text`. Keep the owner's click area off such values: in `EthernetCard` the collapse/expand `MouseArea` covers only the summary row, because a card-wide one renders the values unclickable.
- **Singletons**: Visual tokens live in `config/quickshell/theme/` (`Colors`, `Dimensions`, `Typography`, `Icons`, `Motion`); runtime services and path contracts live in `config/quickshell/services/` (`AppearanceService`, `AudioService`, `BatteryService`, `BrightnessService`, `CaffeineService`, `DeviceBatteryService`, `HyprsunsetService`, `ShellPaths`). Both directories have their own `qmldir`; import both (`../theme` + `../services`, or the matching `../../` path) when a file needs them.
- **Constants**: `Dimensions` holds repeated geometry and shared metrics; `Typography` holds fonts and type scale; `Icons` holds Material Symbols names; `Motion` holds repeated UI animation roles (`color`, `hover`, `press`, `scale`, `fade`, `move`, `rotate`, `spin`, `popupEnter`, `popupExit`, `listEnter`, `listExit`, `osd`). Popup-specific sizes, optical offsets, process intervals and thresholds stay as local `readonly` properties. Domain constants (FPS, bitrate, CRF, temperatures, search scores, NOAA coefficients) stay local to their feature. Do not tokenize `0`/`1`, SVG coordinates, mathematical coefficients, accent-dot coordinates, or one-off optical tweaks.
- **Paths**: Every path outside the shell config goes through `ShellPaths` (`chassisType`, `hyprScripts`, `currentTheme`, `colorsJson`, `appearanceState`, `hyprsunsetState`, `deviceBatteryScript`, `deviceBatteryState`, `runtimeDir`, `runtimeStateDir`, `recordingState`, `caffeineState`, `clipboardPreviewDir`, `wallpaperDir`, `wallpaperPreviewDir`, `palettePreviews`, `palettePreviewsCache`, `cliphistStore`, `cliphistWatch`, `cliphistPreviews`, `pactlSubscribe`, `wallpaperThumbnails`, `completeDirs`). Do not build `HOME`-based paths in QML. Shell scripts resolve the installation root through `config/hypr/scripts/lib/root.sh` (`kolir_root`), and Python through `resolve_root()` in `tools/kolir.py`; never hardcode `~/.local/share/kolir`. Binds and autostart call `sh ~/.config/hypr/scripts/qs-ipc.sh …` or `sh ~/.config/hypr/scripts/launch-shell.sh`.
- **Root & Setup**: `$KOLIR_ROOT` wins, then the physical checkout/package around the script, then `/usr/share/kolir`. `kolir setup` is idempotent: it never silently overwrites user-owned files (`user.lua`, `matugen/config.toml`, real template directories, `gtk.css` stubs, `~/.zshrc`, generated colors) and backs up every managed path it replaces to `<path>.bak.YYYYmmdd-HHMMSS` (`.1`, `.2` on collision). `--dry-run` writes nothing; re-running a configured machine reports "no changes".
- **Styling**: Use `Colors.<role>` (Material Design 3 tokens) with `Colors.withAlpha(color, opacity)` or `Colors.stateLayer(color, opacity)`. Dimensions belong in `Dimensions.*` (including `Dimensions.progress.*` for progress indicators), fonts/weights in `Typography.*`, and icon ligatures in `Icons.*`. Never hardcode colors.
- **Hover State Layers**: A hover/selected tint is a state layer over the container, so `bar/components/StateLayer.qml` paints it as its own fill and fades its `opacity`, instead of animating `color` between the base and `Colors.stateLayer(...)`. `ColorAnimation` interpolates the alpha channel too, so an opaque `surfaceContainerHigh` turning into a 12–16 % state layer passes through a bright, still-opaque grey — the control visibly flashes once on hover-in and once on hover-out. `StateLayer` fills the parent (inheriting its `radius`) and takes `shown`, `tint`, `strength` and `duration`; settings rows (`strength: 0.14`), caffeine chips, the add-device and scan buttons, temperature presets, schedule mode chips, codec chips and the mute button all use it. Put the layer after the container's own colour/border and before the content so the label stays on top.
- **Frame Geometry**: `Frame.qml` assumes `Dimensions.frame.thickness` equals Hyprland's `general.gaps_out` (currently `4`), and `Dimensions.frame.radius` equals `decoration.rounding + border_size` (`28 + 2 = 30`). The frame path starts at `Dimensions.bar.height` because `Bar.qml` paints the 30px bar strip above it. Keep these in sync when changing gaps, rounding, or border size.
- **IPC Handlers**: Modules expose actions via `IpcHandler { target: "<name>" }`. Current targets: `launcher`, `brightness`, `volume`, `settings`, `nowPlaying`, `recording`, `recordingSetup`, `hyprsunset`, `nightLight`, `caffeine`, `appearance` (`setType`, `setContrast`, `setMode`, `regenerate`, `status`), `shortcuts` (`toggle`, `open`, `close`), `wallpaper` (`toggle`, `open`, `close`, `random`, `openDir`, `up`, `home`, `editPath`). Trigger them with `qs -p <config_dir> ipc call <target> <method> [args]`.
- **Layer Namespaces**: `frame`, `bar`, `launcher`, `notifications`, `volume-osd`, `brightness-osd`, `recording-setup`, `shortcuts`, and `wallpaper`. `hyprland.lua` currently adds blur rules for `launcher`, `recording-setup`, and `shortcuts`; `frame` is a Bottom-layer decorative surface and needs no blur rule, `bar` must not have one (its strip and the settings sheet are opaque, and Hyprland's blur eats the layer's painted edge, which let the blurred wallpaper show through the sheet's shoulder), and `wallpaper` deliberately has none because a full-screen blur pass on every scroll frame is what made the grid sluggish. `OsdPanel` receives its namespace from the wrapper (`volume-osd` / `brightness-osd`).
- **Bar vs. Panels**:
  1. For a top-bar widget, add `<Widget>.qml` under `config/quickshell/bar/components/` and instantiate it in `Bar.qml`.
  2. For a standalone overlay, add a component under its own `config/quickshell/<name>/` directory and instantiate it in `ShellRoot` (`shell.qml`); give it a `WlrLayershell.namespace` and add layer rules in `hyprland.lua` when blur/anim is needed. The wallpaper picker and the shortcut sheet follow this pattern with a full-screen Overlay surface and `WlrKeyboardFocus.Exclusive`, so keys reach the panel and an outside click can dismiss it.
  3. Settings belongs inside `SettingsMenu.qml` because the popout is drawn in the bar surface: add a `MainPage.entries` item, a page component, and a height in `heightForPage()`. All three embedded sheets derive from `bar/components/EmbeddedSheet.qml`, which owns the modal scrim, the pour-shaped panel (mirrored for the right-hand sheets), the corner reveal on `Motion.sheetEnter`/`sheetExit` and the dismissal layer, so they cannot drift apart; a sheet keeps only its content and its `open()`/`close()` side effects and drives the motion through `revealOpen()`/`revealClose()`, with `didClose` for state resets and `dismissalRequested` for outside clicks. Keep that height at least as tall as the page's resting content (mirror its `implicitHeight`), otherwise the page opens with a sliver of scroll: the Internet page carries a `Flickable` for the expanded Ethernet details and the connection form, but its resting body (Ethernet, Wi-Fi, actions, 220 px network list) must fit exactly, so `internetHeight` and `InternetPage.implicitHeight` are both `546`; `appearanceHeight` and `AppearancePage.implicitHeight` are both `744`, which fits the ten circular swatches without dead space. The bar expands its input mask and enables `WlrKeyboardFocus.OnDemand` while settings is open. Page navigation inside the settings sheet is a shared-axis slide (`pageProgress`/`incomingPage`/`pageDirection` plus `Motion.pageForward`/`pageBack`), so reverse navigation runs the same transition backwards. `BrightnessPopup.qml` and `VolumePopup.qml` follow the same embedded pattern for the night-light and sound sheets, mirrored to the right screen edge. All sheets are flush with the physical screen edge on their anchor side (settings left, the other two right), so while one is open its opaque body covers the decorative frame ring and the compositor's active-window border instead of outlining the panel with a foreign colour; `Bar.qml` keeps the three sheets mutually exclusive and shares the modal mask/`OnDemand` focus condition between them.
  4. Focus-grabbing popups (for example `TrayMenu`) use `PopupWindow` + `HyprlandFocusGrab` rather than a layer-shell window.
  5. The decorative screen frame belongs in `bar/Frame.qml` on `WlrLayer.Bottom` with an empty `mask`; keep it below windows and click-through. Do not move it into the top-layer `Bar` surface, or the window border is clipped at the rounded cut-out.
- **Recording Helpers**: `screen-record.sh` stays the lifecycle/CLI owner. `lib/monitors.sh` owns shared monitor selection (`KOLIR_MONITOR`, focused, first), `screen-record/audio.sh` owns PipeWire/Pulse helpers, `encoders.sh` owns encoder/quality selection, and `screen-record/monitors.sh` owns Hyprland geometry/FPS helpers. Source them from `SCRIPT_DIR`; do not hardcode repo or home paths.

Keep new scripts on this helper instead of hardcoding an output name.

It asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first, accepts the NUL-separated 0.12.x encoding and the older one-piece encoding, and only returns paths that exist. Tested against awww 0.12.1; older/newer releases still work as long as `awww query -j` or one of those cache encodings is available, otherwise the script prints the version, path, and entries it found and exits 1.
  - **Matugen entries**: The tracked `config/matugen/config.toml` now defines `foot`, `foot-live`, `hyprland`, `quickshell`, `gtk3`, and `gtk4`. A change of `<root>` requires a setup rerun because the symlinks and the Foot loader contain absolute paths.

Because a systemd user unit may not inherit `WAYLAND_DISPLAY`, `reload` warns and skips the shell restart when the graphical environment is absent instead of failing.
  - **Lua Configuration**: Hyprland uses the modern Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.layer_rule`), not traditional `hyprland.conf` directives.
  - **Dispatch from QML**: `Hyprland.dispatch()` forwards its argument to `hyprctl dispatch`, which in Lua-config mode wraps it as `hl.dispatch(<argument>)` and parses it as Lua. Legacy dispatcher strings such as `workspace 3` fail with `')' expected near '3'`, so `bar/components/Workspaces.qml` clicks send `hl.dsp.focus({ workspace = <id> })`. Any new dispatch call must use the Lua `hl.dsp.*` form as well.
  - **Hybrid Brightness**: `services/BrightnessService.qml` is now the only writer for both backends. It probes the internal panel with `brightnessctl -m -c backlight` and the external display with `ddcutil getvcp 10 --brief` at startup and every 30 seconds; `available` is true when either backend answers, and the chip/OSD show the external display when DDC/CI works (desktops, monitor buttons stay authoritative) or the internal panel otherwise (laptops whose eDP panel rejects DDC/CI). `adjust()` moves every available backend by its own 5% step, which preserves the old hybrid behaviour where a laptop changed its panel and a docked DDC monitor together; `setValue()` applies one absolute percentage to every backend. Writes are coalesced through a pending raw value and one `Process`, so a held brightness key cannot spawn one process per repeat. The internal write is `brightnessctl -q -n2 set <raw>` and the displayed percentage is `raw / max`, while `brightness.sh` keeps its old `-e4` curve only for the no-shell fallback. A laptop DDC/CI probe failure is expected and silent; a backend that was working and then fails (for example a monitor powered off) is dropped from `available` with a `console.warn`, and the poll speeds up to 5 seconds while no backend answers so the chip and the panel fallback return quickly.
  - **Battery Authority**: `services/BatteryService.qml` is the only reader of UPower and `/sys/class/dmi/id/chassis_type` (`ShellPaths.chassisType`); `bar/components/Battery.qml` only maps its state to icons. `present` requires a ready UPower DisplayDevice of type `Battery` with `isPresent`; `expected` adds portable chassis types so a missing pack stays visible, and waits for `display.ready` (or a 6 s startup window) before declaring the battery missing, which avoids a false alert on every shell restart. Without the `upower` daemon the service never becomes ready, so the chip appears only after that window on a laptop and never on a desktop; UPower is an optional `kolir doctor` check because desktops do not need it.
  - **Headset Battery Authority**: `DeviceBatteryService` is the only consumer of `scripts/device-battery/main.py`; the helper is the only writer of `~/.cache/quickshell/device-battery.json`. The provider chain is ordered exact-then-generic and each provider is isolated by a per-provider try/except, so a broken brand cannot hide the others. The Sony provider registers a `org.bluez.Profile1` handler for the MDR v2 UUID, performs the `00 00` handshake, asks `22 00`, then unregisters the profile; the RFCOMM channel reports connected slightly before it accepts writes, hence the 400 ms settle delay, and the handshake ACK may arrive before or after the protocol-info frame. BlueZ's `Battery1` value for Sony is typically rounded to 10% steps, which is why `exact` readings win and are cached. The Bluetooth settings row joins the two sources by address (`BluetoothDevice.address` vs the helper's `address`) and falls back to Quickshell's `battery` when the helper has no entry, so a coarse BlueZ device still shows a value. The service never raises the OSD and the chip disappears with the last reading; do not add a notification or a persistent chip for a disconnected device.

Direct CLI changes are reverted to the bar state. The automatic schedule lives in Quickshell; native `hyprsunset.conf` profiles must stay disabled to avoid two planners. `kolir setup` enables `hyprsunset.service`, which starts the daemon with `graphical-session.target` (skipped when the `hyprsunset` binary is missing); until it is up the bar reports "hyprsunset is not running".

This depends on hypridle's `general:ignore_wayland_inhibit` staying at its default `false` (see the comment in `hypridle.conf`), and it does not block logind's lid-close suspend.
  - **Appearance Authority**: `services/AppearanceService.qml` is the only writer of `~/.cache/quickshell/appearance.json`. The file is deliberately compact JSON with exactly `type`, `contrast` and `mode`, because `generate-colors.sh` and `toggle-theme.sh` update the mode with `sed`; do not pretty-print it. `mode` is the user intent: `auto` is a sunrise/sunset schedule that reuses `HyprsunsetService`'s detected location and `Solar.js` times, resolves light between sunrise and sunset and dark otherwise, rechecks every 30 s and when the location loads, and passes the resolved light/dark to `generate-colors.sh` (a bare `auto` run, e.g. from a wallpaper change with the shell down, keeps `current_theme` instead of guessing from the image). The Appearance page always renders the location, a refresh button and the sunrise/sunset cards; when the location is missing Auto holds the current theme and the status line explains why. Explicit `light`/`dark` are authoritative and update `current_theme`, GTK and KDE through `lib/theme.sh`; the bar toggle pins an explicit mode. `generate-colors.sh` precedence is `KOLIR_MATUGEN_*` environment -> state file -> legacy `current_theme` (for mode) with `scheme-neutral`/`0` defaults, so a machine that never opened the Appearance page keeps the old behaviour and every wallpaper change follows the saved choice. The lock palette keeps `--mode dark` but uses the same type and contrast. `AppearanceService` debounces persistence (300 ms) and regeneration (400 ms), runs only one `generate-colors.sh` at a time and queues the last request, so dragging the contrast slider cannot spawn a matugen process per pixel; `regenerating` stays true through the whole chain. The contrast slider is synced imperatively (`syncContrastSlider()` on `AppearanceService.contrastChanged` and when a drag/wheel settle ends): `VolumeSlider` assigns its own `value` while dragging, which destroys a plain `value:` binding after the first drag, so the preset buttons and IPC would otherwise move the label but leave the handle behind.

Do not render the scheme names as the primary control again.

The refresh button in the popup forces a new lookup; without a cached location the service falls back to the saved manual filter state and disables the schedule toggle.
  - **Bar Frame Coupling**: The bar is a full-screen Top-layer surface whose input mask covers only the 30px bar strip (the whole surface while settings is open). The decorative frame is a separate full-screen Bottom-layer surface (`bar/Frame.qml`) with an empty input region; windows are composited above it, so their borders are never clipped by the rounded cut-out. Both the bar strip and the frame ring are filled with the opaque `surfaceContainerLow` (no alpha): the chrome must not tint with the wallpaper, because a translucent ring reads as a see-through outline around the screen in the dark theme, where 6% of a bright wallpaper is clearly visible. `Dimensions.frame.thickness` must match Hyprland `gaps_out`, `Dimensions.frame.radius` must match `decoration.rounding + border_size`, and the frame path starts at `Dimensions.bar.height` because `Bar.qml` paints the strip above it. The settings sheet starts exactly at the bar's bottom edge (`popoutY`) and fills with the same opaque color, so it fuses with the chrome; its top-right shoulder is a concave quarter circle with the same radius as the lower right corner (`panelShoulderRadius` = `panelBottomRadius`, starting at the frame ring's bottom edge and meeting the sheet's right edge `panelShoulderDrop` below it), so both ends of the sheet round alike. That is only safe while the sheet and the ring share the opaque fill (a translucent sheet turned the shoulder into a pale, fringed notch). Both embedded sheets (settings left, night light right) keep their body flush with the physical screen edge on the anchor side, so while either is open it covers the ring and the compositor's window border instead of outlining the panel with a foreign colour. The `bar` layer must not have a blur rule for the same reason the ring must not tint: the strip and the sheet are opaque, and Hyprland's blur eats the painted edge of a layer, exposing the blurred wallpaper along the shoulder.

Both chips flanking it reserve `Dimensions.bar.centerSlot`: `Clock` uses it as a minimum `implicitWidth` (its time uses tabular figures, so the digits keep one width while the clock ticks) and `NowPlaying` takes `slotWidth: clock.implicitWidth`, so a long title still widens the island leftwards but an idle island fills the same slot and shows a muted note in its center instead of unmounting and leaving the bar lopsided. Do not gate `NowPlaying.visible` on `hasPlayer`/`trackText` again; the idle state is the placeholder, and the polling timer already requires a player.

Without it a closed sheet silently kills the pointing-hand cursor in the *settings* sheet: Qt's cursor lookup (`QQuickWindowPrivate::findCursorItemAndHandler`) returns the first item that owns a cursor and only skips children whose effective `visible`/`enabled`/`culled` flags say no — hover delivery takes a different path — so the hidden sheet's full-window dismissal `MouseArea` (every `MouseArea` owns an arrow cursor) won the lookup and the rows kept the default arrow while still highlighting. The two symptoms looked unrelated but share this one cause, so when hover reacts and the cursor does not, check which sheet is still in the tree instead of the item you hover.
  - **Internet Details**: `EthernetCard` and `WifiCard` are the only expanded cards on the Internet page, and both render their values through `CopyableValue` (click copies, hover shows the glyph), so their expand `MouseArea` must not span the values: Ethernet keeps it on the summary row, and `WifiCard` additionally ends it `wifiToggle.width + spacing` short of the right edge so the radio switch stays clickable. `NetworkController` starts `wifiDetailProc` only while connected (`activeWifi` and a device are set) and clears the whole block plus `wifiDetailsExpanded` on disconnect; the address block comes from `nmcli -t device show <wifiDev>` (`parseDeviceDetails`, shared with Ethernet), while SSID/BSSID/security/signal/channel/rate come from the scanned row marked `IN-USE` and `channelLabel` folds `CHAN` + `FREQ` into `36 · 5.18 GHz`. That is why a fresh connection shows the profile name in the summary for a moment before the SSID replaces it. Turning the radio on reads the cached list immediately and then queues a real scan (`--rescan yes`): NetworkManager refuses a scan within 10 s of the previous one and starts its own when the radio comes up, so the first attempt waits `enableScanDelay` (2 s) and a `Scanning not allowed immediately following previous scan` answer retries `enableScanAttempts` times every `enableScanRetryDelay` (2.5 s). `scanning` stays on for the whole chain, so the Refresh button reads `Scanning…` with the spinning glyph from the moment the switch moves until the fresh list lands. Turning Wi-Fi off, leaving the page and a completed rescan cancel that chain; only a rescan clears the counter (`scanProc.rescan`), so a cached poll read that finishes first cannot swallow the pending real scan.

Keep those tokens in sync with `panelHeight`. The fixed-height device lists still scroll internally when there are more devices than fit their 84px viewport.

Keep the wrapper (exact argv `pactl subscribe` match, so one-shot `pactl list/get/set` calls are never touched) and do not run a second shell instance that also imports `AudioService`.

It uses the already-installed `ffmpeg` (no ImageMagick dependency), keys each JPEG by `sha1(path + mtime)` so only new or changed files are encoded, writes to a temporary file and renames, and prints cached entries before generating the rest so the panel never waits for the whole folder. Like `cliphist-watch.sh`, it first kills an identical worker left by a previous shell (whole-argv match in `/proc`) and traps TERM/INT to stop its current `ffmpeg`; keep that wrapper and do not replace the process with a plain loop in QML. The path is built as `home + "/.cache/quickshell/wallpaper-previews"` on purpose: `Quickshell.cachePath()` nests under a per-shell id directory, while the explicit path keeps one predictable cache for checkouts and the package.

It has no layer blur rule on purpose: blurring a full-screen surface on every scroll frame was the main cause of sluggish scrolling, and the dim backdrop rectangle is gone for the same reason. Previews are decoded at the tile's physical width (× `Screen.devicePixelRatio`, never the full 480px preview), Qt caches them, and `cacheBuffer` keeps one extra row ready; wheel `angleDelta` is applied proportionally (120 units = 0.7 row) so a notch stays deliberate and high-resolution wheels remain smooth, with `pixelDelta` only as a fallback. Folder navigation is in-panel: the worker emits visible first-level subdirectories as `dir` records (hidden directories skipped), the grid shows them as folder tiles before the wallpapers, Enter/click opens one, Backspace and the up button go to the parent, and the home button returns to `ShellPaths.wallpaperDir`. The edit button swaps the path line for a text field; Enter normalizes `~`/relative paths, resolves symlinks with `readlink -f`, accepts only readable directories and navigates, while Escape cancels and a missing path keeps the field open with a red border and an error in the footer. In the default library the Random button still runs `random-wallpaper.sh`; in any other folder it picks one of that folder's files and uses the same `set-wallpaper.sh` + `generate-colors.sh` chain. Escape, the close button, an outside click and the IPC `close` method all take the same path and apply nothing; only Enter on a wallpaper, a wallpaper click, the Random button/`random` IPC or the separate `SUPER+CTRL+ALT+T` bind change the wallpaper.   - **Zen Opacity Rule**: `hyprland.lua` defines the named rule `zen-opacity` (`hl.window_rule({ name = "zen-opacity", match = { class = "^(zen|zen-alpha|zen-browser)$" }, opacity = "0.95 0.7" })`), so Zen windows get 0.95 opacity when focused and 0.7 when not. Window rules have no positive `blur` effect (only `no_blur`), so blur is not set per window; `hyprctl keyword` and `setprop` are rejected in Lua-config mode, but `getprop` and `eval` work.
  - **GTK4 Blur**: GTK 4.24 (and newer) creates an `ext_background_effect_surface_v1` on every window and sends an empty blur region, which Hyprland 0.56+ reads as "the client manages its own effects" and therefore skips `decoration:blur` for the whole surface. The result is a translucent inactive GTK4 window (Nautilus, Loupe, GNOME apps) with the wallpaper sharp behind it. `hyprland.lua` sets `hl.env("GDK_WAYLAND_DISABLE", "ext_background_effect_manager_v1")` so GDK never binds the protocol and the compositor's opacity-driven blur comes back. GTK only reads it at process start, so existing GTK4 windows must be restarted (`nautilus -q`); applications started through systemd/dbus need the variable in the user manager (`systemctl --user set-environment …` plus `dbus-update-activation-environment --systemd …`). Verify with `GDK_WAYLAND_DISABLE=help gtk4-query-settings` (the interface is listed as a supported value) and visually behind an inactive GTK4 window. Do not "fix" this with `window { backdrop-filter: blur(...) }` in the GTK theme: it only covers clients that read `~/.config/gtk-4.0/gtk.css` and the file is user-owned.
  - **Launcher on lone SUPER**: `hyprland.lua` binds `SUPER + SUPER_L` (plus the `SUPER_R` twin) with `{ release = true }` to the launcher command, so tapping Super alone toggles the launcher and tapping it again closes it (`SUPER+D` opens the shortcut sheet instead). `release = true` is load-bearing: Hyprland then fires the bind only on the Super release and shadows it when any other key, scroll or mouse button was used while Super was held, which is what keeps `SUPER+Space` (layout switch), `SUPER+1…0` and `SUPER+scroll` (workspaces), `SUPER+drag` and app shortcuts from opening it. A plain bind fires on the Super press and therefore on every SUPER combo. The trigger must be the sided keysyms `SUPER_L`/`SUPER_R` (a modifier mask alone is not a trigger, and `Super_R` does not match a `SUPER_L` bind). Verify after edits with `hyprctl binds` (`key` `SUPER_L`, `release: true`, `modmask` 64) and by tapping Super vs SUPER+Space/SUPER+1/SUPER+scroll and checking `hyprctl layers` for the `launcher` namespace.
  - **Shortcut Sheet**: `SUPER+D` opens the Quickshell cheat sheet, which parses `hyprctl binds -j` (`ShortcutParser.js`) into modifier sections. Under the Lua config, Hyprland reports `dispatcher` and `arg` but the `arg` is an internal index, not the command, so `exec_cmd` rows are only readable through the bind's `description`: every bind in `hyprland.lua` sets one, and `user.lua.example` documents the option. Rows without a description fall back to a generic dispatcher name, which is why new personal binds should carry `{ description = "…" }`. The parser maps modifier bits and gestures (`mouse:272`, `mouse_down`, `XF86*`, lid switch) to readable labels, sorts rows 1…9/0, then letters, then named keys, collapses the two lone-Super binds into one row, and hides `catch_all` binds. Escape, the close button, an outside click and the IPC `close` method all dismiss it; the list is rebuilt on every open and filtered as you type.
