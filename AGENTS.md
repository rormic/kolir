# AGENTS.md — Desktop Environment Reference

## 1. Overview
`kolir` is an Arch Linux desktop configuration for a Wayland session built on Hyprland (configured with Lua) and a custom Quickshell (QML) shell. The shell is Material Design 3–inspired: the bar is a full-screen top-layer surface that paints the bar strip and hosts an embedded settings popout, while a separate bottom-layer frame surface fills the window gaps and frames the desktop below windows. The shell also owns a separate sound popup. Matugen extracts a neutral Material 3 palette from the current wallpaper and reactively updates Hyprland, Foot, Neovim, GTK, and Quickshell colors. Machine-specific Hyprland settings live in `~/.config/hypr/user.lua`; `kolir setup` (from `tools/kolir.py`) deploys the symlinks and per-user glue once, and later updates are just a `git pull`. Packaging is phase 2 and not yet available.

## 2. Directory Map

- [config/hypr/user.lua.example](file:///home/sakura/.local/share/kolir/config/hypr/user.lua.example): Template for the untracked machine-specific file (`monitors`, autostart, cursor/env, personal binds, overrides).
- [config/hypr/hyprsunset.conf](file:///home/sakura/.local/share/kolir/config/hypr/hyprsunset.conf): Valid hyprlang config for the blue-light filter. Runtime control and the automatic schedule are owned by Quickshell (`HyprsunsetService`), so native `profile { ... }` blocks should stay commented out.
- [config/hypr/scripts/](file:///home/sakura/.local/share/kolir/config/hypr/scripts): Helper scripts, all `kebab-case`:
  - `lib/root.sh`: POSIX root resolution shared by every helper (`kolir_root [script_dir]`). Order: `$KOLIR_ROOT`, then the physical root above `<dir>/config/hypr/scripts` (works through the `~/.config/hypr/scripts` symlink), then `/usr/share/kolir`. Callers pass `$SCRIPT_DIR`; `KOLIR_DIR` is still accepted as a legacy override by `brightness.sh` and `screen-record.sh`.
  - `qs-ipc.sh` / `launch-shell.sh`: resolve the root through `lib/root.sh` and `exec qs -p <root>/config/quickshell …`; use them instead of hardcoding a checkout path in binds or autostart.
  - `lib/monitors.sh`: shared monitor selection sourced by zsh and sh callers. `kolir_monitor_name` / `kolir_focused_monitor_name` resolve `$KOLIR_MONITOR`, then the focused monitor from `hyprctl monitors -j`, then the first monitor, and only `kolir_monitor_name` falls back to `DP-1`; `kolir_monitor_geometry` / `kolir_focused_monitor_geometry` return `x,y wxh`.
  - `lib/awww.sh`: version-tolerant wallpaper lookup. `kolir_awww_wallpaper_path <monitor>` asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first (also the cache root), decoding both the NUL-separated 0.12.x layout and the older one-piece layout; failures name the awww version, path, and entries found.
  - `set-wallpaper.sh`: applies an image with `awww img -t random --transition-fps 180` (silent exit 0 on an empty/cancelled picker, explicit errors otherwise).
  - `select-wallpaper.sh` / `random-wallpaper.sh`: pick a wallpaper with Zenity or `find`+`shuf`, then call `set-wallpaper.sh` and `generate-colors.sh`.
  - `generate-colors.sh`: sources `lib/monitors.sh` + `lib/awww.sh`, resolves the wallpaper for the selected monitor, then runs Matugen with the neutral scheme.
  - `toggle-theme.sh`: flips `~/.cache/current_theme`, updates GTK/KDE theme names, and regenerates colors.
  - `brightness.sh`: adjusts the internal panel with `brightnessctl` and the external monitor through Quickshell IPC.
  - `screen-record.sh`: recording toggle/setup/start with `wf-recorder` (fallback `wl-screenrec`), audio mixing, encoder selection, and state files under `$XDG_RUNTIME_DIR/kolir`. It sources `lib/monitors.sh`, `screen-record/audio.sh`, `screen-record/encoders.sh`, and `screen-record/monitors.sh` through `SCRIPT_DIR=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)`.
- [config/quickshell/shell.qml](file:///home/sakura/.local/share/kolir/config/quickshell/shell.qml): Quickshell `ShellRoot`. Instantiates `Frame`, `Bar`, `Launcher`, `Notification`, `VolumeOsd`, `BrightnessOsd`, and `RecordingSetup`; settings is embedded in `Bar`.

## 3. Data Flow
```
Wallpaper (SUPER+CTRL+T select / SUPER+CTRL+ALT+T random)
        └─> select-wallpaper.sh / random-wallpaper.sh
              └─> set-wallpaper.sh (awww img)
                    └─> generate-colors.sh
Theme toggle (Bar ThemeToggle.qml)
        └─> toggle-theme.sh (~/.cache/current_theme, GTK/KDE theme)
              └─> generate-colors.sh
generate-colors.sh
  selects the monitor ($KOLIR_MONITOR, then focused, then first, then DP-1)
  resolves the wallpaper (awww query -j, then the version-tolerant cache scan)
  selects the config ($KOLIR_MATUGEN_CONFIG, ~/.config/matugen/config.toml, repo copy)
  pre-validates every template input with python3 + tomllib
  reads ~/.cache/current_theme (creates it as dark when missing)
  runs: matugen image <path> --source-color-index 0 -m <theme> -t scheme-neutral
        ├─> ~/.config/foot/colors.ini
        ├─> ~/.cache/terminal-sequences  ──> tee /dev/pts/* (live Foot)
        ├─> ~/.local/share/nvim/matugen-colors.lua
        ├─> ~/.config/hypr/colors.lua    ──> hyprctl reload
        ├─> ~/.config/quickshell/colors.json
        ├─> ~/.config/gtk-3.0/colors.css ──> imported by ~/.config/gtk-3.0/gtk.css
        ├─> ~/.config/gtk-4.0/colors.css ──> imported by ~/.config/gtk-4.0/gtk.css
        └─> ~/.config/matugen/…obsidian output (only when setup added the block)
```
- **Wallpaper Trigger**: The Hyprland binds run `config/hypr/scripts/select-wallpaper.sh` or `random-wallpaper.sh`. Both call `set-wallpaper.sh` (`awww img`) and then `generate-colors.sh`.
- **Theme Trigger**: `ThemeToggle.qml` watches `~/.cache/current_theme` and calls `toggle-theme.sh`. The script flips `light`/`dark`, updates GNOME/GTK and KDE theme settings, writes the state file, and calls `generate-colors.sh`.
- **Keep Awake Trigger**: `CaffeineCard` (Settings → main page) or `qs ipc call caffeine …` drives `CaffeineService`. While enabled, `Bar.qml` holds a `Quickshell.Wayland.IdleInhibitor` on the bar surface, so `hypridle` receives no idle events and skips lock, DPMS and suspend. The state and timer live in `$XDG_RUNTIME_DIR/kolir/caffeine.json`.
- **Palette Generation**: `generate-colors.sh` is zsh-based. It selects the monitor through `lib/monitors.sh` (`$KOLIR_MONITOR`, focused, first, then `DP-1`) and resolves the wallpaper through `lib/awww.sh`, which prefers `awww query -j` and otherwise scans the version-named cache tolerantly, so neither the output name nor the awww version is hardcoded. Config selection is `$KOLIR_MATUGEN_CONFIG` -> `~/.config/matugen/config.toml` -> `<root>/config/matugen/config.toml`; every template input is pre-validated with python3 + tomllib so a missing template cannot produce a partial palette. A missing `~/.cache/current_theme` is created as `dark`. It runs Matugen with `--source-color-index 0` and `-t scheme-neutral`, skips the lock palette gracefully when `hyprlock.toml` is absent, and makes the `hyprctl reload` hook a no-op when no live Hyprland instance exists. The lock background/glow step is skipped when `ffmpeg` is missing; it renders at the geometry reported by `kolir_monitor_geometry` (falling back to 2560x1440 when Hyprland cannot report a size), which keeps the lock image matched to the monitor after the earlier geometry bug.
- **Consumer Updates**:
  - **Quickshell**: `config/quickshell/theme/Colors.qml` watches `ShellPaths.colorsJson` with `FileView`, parses it in `onLoaded`, and maps snake_case keys to camelCase QML properties without restarting the shell.
  - **Foot**: Matugen writes `~/.cache/terminal-sequences`; its `post_hook` tees ANSI color sequences into open pseudo-terminals. New Foot instances read `~/.config/foot/colors.ini`.
  - **Neovim**: Matugen writes `~/.local/share/nvim/matugen-colors.lua` from the tracked `nvim-colors.lua` template.
  - **Hyprland**: The Matugen `post_hook` runs `hyprctl reload`; `hyprland.lua` loads `~/.config/hypr/colors.lua` with `dofile()` when it exists.
  - **GTK**: Matugen writes `~/.config/gtk-3.0/colors.css` and `~/.config/gtk-4.0/colors.css`; the import stubs `gtk.css` (`@import url("colors.css");`) are created by `kolir setup` because they are user glue, not package files. `toggle-theme.sh` additionally changes the GTK color-scheme/theme and KDE `ColorScheme`.
- **User Glue**: `kolir setup` creates symlinks for `~/.config/hypr/{hyprland.lua,scripts,hyprsunset.conf,hyprlock.conf,hypridle.conf}`, `~/.config/mpv/mpv.conf`, `~/.config/matugen/hyprlock.toml`, and (when the templates path is absent) `~/.config/matugen/templates`; it writes the Foot loader and empty `colors.ini`, copies `matugen/config.toml`, the GTK stubs, `~/.cache/current_theme`, the Quickshell palette snapshot, `user.lua`, and `hyprlock-colors.conf` only when absent, backs up anything it replaces, refreshes `<root>/.version`, and enables `hypridle.service` (unless `--no-systemd`). `~/.zshrc` is opt-in via `--zsh`; Obsidian is opt-in via `--obsidian`/`--obsidian-output` and has no default vault path.

## 4. Conventions
- **Naming**: QML files and types are `PascalCase`; JavaScript modules are `camelCase`; directories are lowercase except the existing `nightLight/` feature directory; Hyprland shell scripts and `screen-record/` helper modules are `kebab-case`. Preserve IPC targets, layer namespaces, JSON keys, and CLI arguments exactly.
- **Shared Components**: Reusable UI primitives live in `config/quickshell/bar/components/` (`Surface.qml`, `Pill.qml`, `IconButton.qml`, `AppIcon.qml`, `ProgressIndicator.qml`, `VolumeSlider.qml`). Prefer these over duplicating surface styling.
- **Singletons**: Visual tokens live in `config/quickshell/theme/` (`Colors`, `Dimensions`, `Typography`, `Icons`, `Motion`); runtime services and path contracts live in `config/quickshell/services/` (`AudioService`, `BrightnessService`, `CaffeineService`, `HyprsunsetService`, `ShellPaths`). Both directories have their own `qmldir`; import both (`../theme` + `../services`, or the matching `../../` path) when a file needs them.
- **Constants**: `Dimensions` holds repeated geometry and shared metrics; `Typography` holds fonts and type scale; `Icons` holds Material Symbols names; `Motion` holds repeated UI animation roles (`color`, `hover`, `press`, `scale`, `fade`, `move`, `rotate`, `spin`, `popupEnter`, `popupExit`, `listEnter`, `listExit`, `osd`). Popup-specific sizes, optical offsets, process intervals and thresholds stay as local `readonly` properties. Domain constants (FPS, bitrate, CRF, temperatures, search scores, NOAA coefficients) stay local to their feature. Do not tokenize `0`/`1`, SVG coordinates, mathematical coefficients, accent-dot coordinates, or one-off optical tweaks.
- **Paths**: Every path outside the shell config goes through `ShellPaths` (`hyprScripts`, `currentTheme`, `colorsJson`, `hyprsunsetState`, `runtimeDir`, `runtimeStateDir`, `recordingState`, `caffeineState`, `clipboardPreviewDir`, `cliphistStore`, `cliphistWatch`, `cliphistPreviews`, `pactlSubscribe`). Do not build `HOME`-based paths in QML. Shell scripts resolve the installation root through `config/hypr/scripts/lib/root.sh` (`kolir_root`), and Python through `resolve_root()` in `tools/kolir.py`; never hardcode `~/.local/share/kolir`. Binds and autostart call `sh ~/.config/hypr/scripts/qs-ipc.sh …` or `sh ~/.config/hypr/scripts/launch-shell.sh`.
- **Root & Setup**: `$KOLIR_ROOT` wins, then the physical checkout/package around the script, then `/usr/share/kolir`. `kolir setup` is idempotent: it never silently overwrites user-owned files (`user.lua`, `matugen/config.toml`, real template directories, `gtk.css` stubs, `~/.zshrc`, generated colors) and backs up every managed path it replaces to `<path>.bak.YYYYmmdd-HHMMSS` (`.1`, `.2` on collision). `--dry-run` writes nothing; re-running a configured machine reports "no changes".
- **Styling**: Use `Colors.<role>` (Material Design 3 tokens) with `Colors.withAlpha(color, opacity)` or `Colors.stateLayer(color, opacity)`. Dimensions belong in `Dimensions.*` (including `Dimensions.progress.*` for progress indicators), fonts/weights in `Typography.*`, and icon ligatures in `Icons.*`. Never hardcode colors.
- **Frame Geometry**: `Frame.qml` assumes `Dimensions.frame.thickness` equals Hyprland's `general.gaps_out` (currently `4`), and `Dimensions.frame.radius` equals `decoration.rounding + border_size` (`28 + 2 = 30`). The frame path starts at `Dimensions.bar.height` because `Bar.qml` paints the 30px bar strip above it. Keep these in sync when changing gaps, rounding, or border size.
- **IPC Handlers**: Modules expose actions via `IpcHandler { target: "<name>" }`. Current targets: `launcher`, `brightness`, `volume`, `settings`, `nowPlaying`, `recording`, `recordingSetup`, `hyprsunset`, `nightLight`, `caffeine`. Trigger them with `qs -p <config_dir> ipc call <target> <method> [args]`.
- **Layer Namespaces**: `frame`, `bar`, `launcher`, `notifications`, `volume-osd`, `brightness-osd`, and `recording-setup`. `hyprland.lua` currently adds blur rules for `bar`, `launcher`, and `recording-setup`; `frame` is a Bottom-layer decorative surface and needs no blur rule. `OsdPanel` receives its namespace from the wrapper (`volume-osd` / `brightness-osd`).
- **Bar vs. Panels**:
  1. For a top-bar widget, add `<Widget>.qml` under `config/quickshell/bar/components/` and instantiate it in `Bar.qml`.
  2. For a standalone overlay, add a component under its own `config/quickshell/<name>/` directory and instantiate it in `ShellRoot` (`shell.qml`); give it a `WlrLayershell.namespace` and add layer rules in `hyprland.lua` when blur/anim is needed.
  3. Settings belongs inside `SettingsMenu.qml` because the popout is drawn in the bar surface: add a `MainPage.entries` item, a page component, and a height in `heightForPage()`. The bar expands its input mask and enables `WlrKeyboardFocus.OnDemand` while settings is open.
  4. Focus-grabbing popups (for example `VolumePopup`) use `PopupWindow` + `HyprlandFocusGrab` rather than a layer-shell window.
  5. The decorative screen frame belongs in `bar/Frame.qml` on `WlrLayer.Bottom` with an empty `mask`; keep it below windows and click-through. Do not move it into the top-layer `Bar` surface, or the window border is clipped at the rounded cut-out.
- **Recording Helpers**: `screen-record.sh` stays the lifecycle/CLI owner. `lib/monitors.sh` owns shared monitor selection (`KOLIR_MONITOR`, focused, first), `screen-record/audio.sh` owns PipeWire/Pulse helpers, `encoders.sh` owns encoder/quality selection, and `screen-record/monitors.sh` owns Hyprland geometry/FPS helpers. Source them from `SCRIPT_DIR`; do not hardcode repo or home paths.

## 5. How to Verify Changes
- **Quickshell**:
  - Restart shell: `kolir reload` (Hyprland reload + Quickshell restart) or `kolir shell` (exec `qs -p <root>/config/quickshell`). The restart log is `~/.cache/kolir/shell.log`.
  - Check logs: run `kolir shell` in a terminal foreground, or read `~/.cache/kolir/shell.log`; compare against `/home/sakura/.cache/kolir/qml-baseline.log`. New `ReferenceError`, `TypeError`, `is not a type`, `binding loop`, or `Unable to assign` is a regression.
  - Lint: `/usr/lib/qt6/bin/qmllint $(find config/quickshell -name '*.qml' | sort)`; compare categories with `/home/sakura/.cache/kolir/qml-lint-baseline.txt`. `missing-property` warnings for `Dimensions`/`Typography`/`Icons` are known linter false positives.
  - Test IPC:
    - `kolir ipc launcher toggle`
    - `kolir ipc settings toggle`
    - `kolir ipc volume toggle`
    - `kolir ipc nowPlaying playPause`
    - `kolir ipc recordingSetup open`
- **Hyprland**:
  - Reload compositor: `hyprctl reload`.
  - Inspect layer namespaces: `hyprctl layers` (`frame` should be on the Bottom level, `bar` on Top).
  - Read logs: `cat "$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/hyprland.log"`.
- **Pure JS libraries (node comparison)**: keep a verbatim copy of the previous code in `/tmp/opencode/<name>-old.js` plus a wrapper that reads the repo `.js`, strips the `.pragma library` line and appends `module.exports = { ... }`; then compare both implementations on a large matrix (all days of a year, several coordinates/timezones for `Solar.js`; real `pactl -f json list ...` output plus synthetic cases for `AudioParser.js`) with `JSON.stringify` equality. The repo files must stay QML-only; tests live only under `/tmp/opencode/`.
- **Shell scripts**: `zsh -n` for wallpaper/theme/color scripts; `sh -n` for `lib/*.sh` (including `root.sh`), `screen-record.sh`, `screen-record/*.sh`, `qs-ipc.sh`, `launch-shell.sh`, `config/quickshell/scripts/cliphist-watch.sh`, and `config/quickshell/scripts/pactl-subscribe.sh`. Apply the current wallpaper with `set-wallpaper.sh "$(awww query | sed -n 's/.*image: //p')"` and regenerate colors with `generate-colors.sh` (or `kolir reload --colors`). Verify monitor selection without changing the session with `. config/hypr/scripts/lib/monitors.sh; kolir_monitor_name` (try `KOLIR_MONITOR=HDMI-A-1` too). Verify awww tolerance with a fake `XDG_CACHE_HOME` containing an old one-piece cache and/or a stub `awww` whose `query` exits non-zero. Verify root resolution through a symlinked `~/.config/hypr/scripts` with a stub `qs` in `PATH` that prints its argv.
- **Recording**: start `screen-record.sh --start --area full --audio system|mic|both|none`, stop with `screen-record.sh`, and check `ffprobe` streams, `$XDG_RUNTIME_DIR/kolir/recording.json`, leftover recorder processes, and `pactl list short modules | grep kolir_rec_mix`.

## 7. Environment Notes
- **OS & Window Manager**: Arch Linux, Wayland, Hyprland 0.57.2.
- **Quickshell**: Version 0.3.2. Uses `Quickshell.Io` (`Process`, `FileView`, `SplitParser`, `StdioCollector`, `IpcHandler`), `Quickshell.Wayland` (`WlrLayershell`), `Quickshell.Hyprland`, `Quickshell.Services.Notifications`, `Quickshell.Services.Mpris`, `Quickshell.Services.SystemTray`, and `Quickshell.Bluetooth`.
- **Runtime Dependencies**: `kolir doctor` knows the required set (Hyprland/`hyprctl`, Quickshell/`qs`, `matugen`, `awww`, `foot`, `brightnessctl`, `ddcutil`, `grim`, `slurp`, `wl-clipboard`, `libnotify`, `wf-recorder`, `hyprlock`, `hypridle`, `hyprsunset`, `zsh`, `python3`) and the optional ones (`git` for checkout version reporting, `ffmpeg` for the lock background/encoder probing, `cliphist`, NetworkManager/`nmcli`, BlueZ/`bluetoothctl`, `hyprpicker`, `wl-screenrec`, `zenity`, `nautilus`, the `mocu-xcursor` theme, KDE Connect, `playerctl`). Missing required tools are errors; missing optional tools are warnings. Phase 1 installs nothing.
- **Known Quirks & Pitfalls**:
  - **Monitor Selection**: Wallpaper/color scripts and the recorder share `config/hypr/scripts/lib/monitors.sh`; set `KOLIR_MONITOR=<output>` to override detection (`hyprctl monitors -j` focused, then first). Only `kolir_monitor_name` falls back to `DP-1` when Hyprland cannot be queried, so the author's machine keeps working without configuration while other ports are detected. Keep new scripts on this helper instead of hardcoding an output name.
  - **awww Cache Layout**: `lib/awww.sh` never assumes an awww version directory. It asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first, accepts the NUL-separated 0.12.x encoding and the older one-piece encoding, and only returns paths that exist. Tested against awww 0.12.1; older/newer releases still work as long as `awww query -j` or one of those cache encodings is available, otherwise the script prints the version, path, and entries it found and exits 1.
  - **Matugen entries**: The tracked `config/matugen/config.toml` now defines `foot`, `foot-live`, `nvim`, `hyprland`, `quickshell`, `gtk3`, and `gtk4`. Obsidian is template-only (`templates/obsidian.css`) and gets a `[templates.obsidian]` block only when the user enables it; there is no default vault. `zen` entries remain a local customization outside the repo. `kolir setup` copies the tracked config only when `~/.config/matugen/config.toml` is absent, links missing templates into a real local templates directory, and replaces a config symlink with a local copy (with a backup) before adding the Obsidian block, so a checkout is never modified through a link.
  - **Setup gating**: setup refuses to run as root, writes nothing under `--dry-run`, and reports "no changes" on a configured machine. It never overwrites `user.lua`, an existing matugen config, real template files, existing `gtk.css`, or `~/.zshrc` (the latter is opt-in with `--zsh`); managed replacements are backed up to `<path>.bak.YYYYmmdd-HHMMSS`. A change of `<root>` requires a setup rerun because the symlinks and the Foot loader contain absolute paths.
  - **Auto-reload**: `setup --auto-reload` renders the units directly into `~/.config/systemd/user/` (watching `.version` and the git ref, running `python3 <root>/tools/kolir.py reload` in a checkout or `/usr/bin/kolir reload` in a package), verifies them with `systemd-analyze --user verify`, and enables `kolir-reload.path`; `--no-systemd` writes the units but skips systemctl. Because a systemd user unit may not inherit `WAYLAND_DISPLAY`, `reload` warns and skips the shell restart when the graphical environment is absent instead of failing.
  - **Lua Configuration**: Hyprland uses the modern Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.layer_rule`), not traditional `hyprland.conf` directives.
  - **Dispatch from QML**: `Hyprland.dispatch()` forwards its argument to `hyprctl dispatch`, which in Lua-config mode wraps it as `hl.dispatch(<argument>)` and parses it as Lua. Legacy dispatcher strings such as `workspace 3` fail with `')' expected near '3'`, so `bar/components/Workspaces.qml` clicks send `hl.dsp.focus({ workspace = <id> })`. Any new dispatch call must use the Lua `hl.dsp.*` form as well.
  - **Hybrid Brightness**: `brightness.sh` adjusts the internal display via `brightnessctl` and the external display via Quickshell IPC calling `services/BrightnessService.qml`, which throttles `ddcutil setvcp 10`.
  - **Hyprsunset Authority**: `services/HyprsunsetService.qml` queries `hyprctl hyprsunset identity get/temperature` and reconciles the live CTM every 30 seconds. Direct CLI changes are reverted to the bar state. The automatic schedule lives in Quickshell; native `hyprsunset.conf` profiles must stay disabled to avoid two planners.
  - **Keep Awake Authority**: `services/CaffeineService.qml` owns the switch/timer and persists it in `$XDG_RUNTIME_DIR/kolir/caffeine.json`. `Bar.qml` attaches a `Quickshell.Wayland.IdleInhibitor` to the bar surface while it is enabled, so hypridle receives no idle events at all; manual `loginctl lock-session` and `systemctl suspend` still work. This depends on hypridle's `general:ignore_wayland_inhibit` staying at its default `false` (see the comment in `hypridle.conf`), and it does not block logind's lid-close suspend.
  - **Sun Schedule Location**: The sunrise/sunset mode computes NOAA solar times from coordinates detected through `https://ipwho.is/` (`curl`, max 8 s) and cached in the state file for seven days. The refresh button in the popup forces a new lookup; without a cached location the service falls back to the saved manual filter state and disables the schedule toggle.
  - **Bar Frame Coupling**: The bar is a full-screen Top-layer surface whose input mask covers only the 30px bar strip (the whole surface while settings is open). The decorative frame is a separate full-screen Bottom-layer surface (`bar/Frame.qml`) with an empty input region; windows are composited above it, so their borders are never clipped by the rounded cut-out. `Dimensions.frame.thickness` must match Hyprland `gaps_out`, `Dimensions.frame.radius` must match `decoration.rounding + border_size`, and the frame path starts at `Dimensions.bar.height` because `Bar.qml` paints the strip above it.
  - **Volume Popup Focus**: `VolumePopup.qml` is a `PopupWindow` anchored to the volume pill and uses `HyprlandFocusGrab` to close on outside clicks; it is not a layer-shell namespace.
  - **MPRIS Workaround**: `NowPlaying.qml` sends raw `busctl` Play/Pause calls because some players (Firefox/Zen) report stale `PlaybackStatus`, which breaks Quickshell's `togglePlaying()`.
  - **Clipboard Watchers**: `ClipboardController.qml` starts one `wl-paste --watch` per MIME type through `scripts/cliphist-watch.sh` in a root `Scope`, so capture continues while the launcher is closed. Quickshell does not terminate `Quickshell.Io` children when it is killed; the wrapper terminates the identical watcher left behind by the previous shell (exact argv match in `/proc`) and only then execs `wl-paste`, so exactly one pair survives any number of restarts or QML reloads. Do not replace the wrapper with a plain `wl-paste` command, and do not move the controller back into `PanelWindow`.
  - **Audio Subscriber**: `AudioService.qml` starts its `pactl subscribe` listener through `scripts/pactl-subscribe.sh` for the same reason: the old listener survives a shell restart, and every restart used to add one more connected client to `pipewire-pulse`. That leak is what exhausts the server's client slots (`too many client application connections: Connection refused` in the user journal); `pactl` then exits 1 with empty stdout, which used to clear the device model and log `failed to parse` warnings. Keep the wrapper (exact argv `pactl subscribe` match, so one-shot `pactl list/get/set` calls are never touched) and do not run a second shell instance that also imports `AudioService`.
  - **Deferred Service Split**: `hyprsunset/Schedule.js` and `hyprsunset/StateStore.qml` are planned but not created; `HyprsunsetService.qml` still owns schedule helpers and persistence inline, so do not assume those files exist. `audio/AudioParser.js` and `hyprsunset/Solar.js` do exist (steps 85/84) and must stay stateless: every input (parsed JSON, device kind, calendar date, coordinates, `locationAvailable`) arrives as a parameter, and `AudioService.parseDevices/parseCards` keep the JSON guards, `null` returns and `failed to parse` diagnostics in QML.
  - **Pure JS Testability**: Both `.js` libraries start with `.pragma library` and are loaded through QML imports (`import "audio/AudioParser.js" as AudioParser`, `import "hyprsunset/Solar.js" as Solar`). Do not add `require`, QML types, timers, service properties or `console.warn` to them; the services wrap them instead. To compare changes under node, strip only the `.pragma` line in a `/tmp/opencode/` wrapper (never the repo file) and expose the functions via `module.exports`.
  - **Zen Opacity Rule**: `hyprland.lua` defines the named rule `zen-opacity` (`hl.window_rule({ name = "zen-opacity", match = { class = "^(zen|zen-alpha|zen-browser)$" }, opacity = "0.95 0.7" })`), so Zen windows get 0.95 opacity when focused and 0.7 when not. It must stay a call: an earlier version assigned the table (`hl.window_rule = { ... }`), which registered nothing and replaced the API function with a table for the rest of the config, including `user.lua`. Verify after edits with `hyprctl configerrors` (empty), `hyprctl eval 'error("TYPE=" .. type(hl.window_rule))'` (`function`, not `table`) and `hyprctl getprop class:zen opacity` (`0.95`). Window rules have no positive `blur` effect (only `no_blur`), so blur is not set per window; `hyprctl keyword` and `setprop` are rejected in Lua-config mode, but `getprop` and `eval` work.
