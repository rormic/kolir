# AGENTS.md — Desktop Environment Reference

## 1. Overview
`kolir` is an Arch Linux desktop configuration for a Wayland session built on Hyprland (configured with Lua) and a custom Quickshell (QML) shell. The shell is Material Design 3–inspired: the bar is a full-screen top-layer surface that paints the bar strip and hosts an embedded settings popout, while a separate bottom-layer frame surface frames the desktop below windows in either the classic bar-coloured ring or a corner-only style (bar-coloured top corners, black bottom corners). The shell also owns a separate sound popup, and its single file picker doubles as the full-screen wallpaper grid. Matugen extracts a neutral Material 3 palette from the current wallpaper and reactively updates Hyprland, Foot, GTK, and Quickshell colors. Machine-specific Hyprland settings live in `~/.config/hypr/user.lua`; `kolir setup` (from `tools/kolir.py`) deploys the symlinks and per-user glue once, and later updates are just a `git pull`. Packaging is phase 2 and not yet available.

## 2. Directory Map
- [config/hypr/hyprland.lua](config/hypr/hyprland.lua): Shared Hyprland config using the Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.layer_rule`, `hl.animation`). Loads generated `~/.config/hypr/colors.lua` when present, reads `~/.cache/quickshell/frame.json` to pick the initial `general.gaps_out` for the saved screen-frame style, defines keybinds (launcher, screenshots — `SUPER+X` and `Print` both run the frozen-frame region pick — capture history, wallpapers, recording, media/brightness keys), and loads `~/.config/hypr/user.lua` last.
- [config/hypr/user.lua.example](config/hypr/user.lua.example): Template for the untracked machine-specific file (`monitors`, autostart, cursor/env, personal binds, overrides).
- [config/hypr/hyprsunset.conf](config/hypr/hyprsunset.conf): Valid hyprlang config for the blue-light filter. Runtime control and the automatic schedule are owned by Quickshell (`HyprsunsetService`), so native `profile { ... }` blocks should stay commented out.
- [config/hypr/scripts/](config/hypr/scripts): Helper scripts, all `kebab-case`:
  - `lib/root.sh`: POSIX root resolution shared by every helper (`kolir_root [script_dir]`). Order: `$KOLIR_ROOT`, then the physical root above `<dir>/config/hypr/scripts` (works through the `~/.config/hypr/scripts` symlink), then `/usr/share/kolir`. Callers pass `$SCRIPT_DIR`; `KOLIR_DIR` is still accepted as a legacy override by `brightness.sh` and `screen-record.sh`.
  - `qs-ipc.sh` / `launch-shell.sh`: resolve the root through `lib/root.sh` and `exec qs -p <root>/config/quickshell …`; use them instead of hardcoding a checkout path in binds or autostart.
  - `lib/monitors.sh`: shared monitor selection sourced by zsh and sh callers. `kolir_monitor_name` / `kolir_focused_monitor_name` resolve `$KOLIR_MONITOR`, then the focused monitor from `hyprctl monitors -j`, then the first monitor, and only `kolir_monitor_name` falls back to `DP-1`; `kolir_monitor_geometry` / `kolir_focused_monitor_geometry` return `x,y wxh`.
  - `lib/awww.sh`: version-tolerant wallpaper lookup. `kolir_awww_wallpaper_path <monitor>` asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first (also the cache root), decoding both the NUL-separated 0.12.x layout and the older one-piece layout; failures name the awww version, path, and entries found.
  - `lib/mpvpaper.sh`: video-wallpaper lifecycle. One mpvpaper process owns an output; `kolir_mpvpaper_start/restart/stop` track its pid in `$XDG_RUNTIME_DIR/kolir/mpvpaper.pid`, validate the live process through `/proc` before signalling it, run it as `mpvpaper -o 'no-audio loop hwdec=auto-safe panscan=1.0' <monitor> <video>` with a log at `~/.cache/kolir/mpvpaper.log`, and report a failed start instead of saving it. mpvpaper has no stop command, so the pid file is the only owner.
  - `lib/wallpaper.sh`: backend state and dispatch. The state file `~/.cache/quickshell/wallpaper.json` (`{"backend":"awww","image":"…","video":"…"}`) is written only by `set-wallpaper.sh`/`wallpaper-backend.sh`; `kolir_wallpaper_backend`, `kolir_wallpaper_is_video/kind`, `kolir_wallpaper_source` (live video when mpvpaper is really playing, otherwise awww with the saved image as fallback) and `kolir_wallpaper_image` (caches a one-second video frame under `~/.cache/kolir/wallpaper-frames` for Matugen) live here. Callers source `lib/awww.sh` and `lib/mpvpaper.sh` first.
  - `set-wallpaper.sh`: dispatches on the extension. Images use `awww img -t random --transition-fps 180` after stopping mpvpaper; videos restart mpvpaper and save the video path; both write the backend state. Silent exit 0 on an empty/cancelled picker, explicit errors otherwise.
  - `wallpaper-backend.sh`: switches `awww`/`mpvpaper` without touching the files. Switching to video replays the saved clip, switching to images stops the player and restores the last image, and the script is idempotent so `WallpaperService` can call it on every shell start to restore a live video.
  - `open-wallpaper-picker.sh`: primary wallpaper trigger. Toggles the Quickshell `wallpaper` panel through `qs … ipc call wallpaper toggle`; when no shell answers (or `qs` is missing) it `exec`s `select-wallpaper.sh`, so Zenity remains the fallback.
  - `select-wallpaper.sh` / `random-wallpaper.sh`: pick a wallpaper with Zenity or `find`+`shuf` (videos too), then call `set-wallpaper.sh` and `generate-colors.sh`; Random follows the active backend and falls back to an image when the video library is empty.
  - `generate-colors.sh`: sources `lib/monitors.sh` + `lib/awww.sh` + `lib/mpvpaper.sh` + `lib/wallpaper.sh` + `lib/theme.sh`, resolves the active wallpaper for the selected monitor (a cached frame for video), applies the persisted Appearance choice (scheme type, contrast, mode), then runs Matugen.
  - `toggle-theme.sh`: flips the resolved light/dark theme, syncs the persisted Appearance mode, applies GTK/KDE theme names through `lib/theme.sh`, and regenerates colors.
  - `lib/theme.sh`: shared light/dark application (`kolir_write_theme_state`, `kolir_apply_theme_mode`, `kolir_apply_system_theme`) plus `kolir_sync_appearance_mode` for `toggle-theme.sh`. POSIX; sourced by `generate-colors.sh` and `toggle-theme.sh`.
  - `brightness.sh`: forwards `up`/`down` to the Quickshell `brightness` IPC target, which drives both the internal panel (`brightnessctl`) and the external monitor (`ddcutil`); it falls back to `brightnessctl -c backlight -e4 -n2 set 5%±` only when no shell answers.
  - `screen-record.sh`: recording toggle/setup/start with `wf-recorder` (fallback `wl-screenrec`), audio mixing, encoder selection, and state files under `$XDG_RUNTIME_DIR/kolir`. It sources `lib/monitors.sh`, `screen-record/audio.sh`, `screen-record/encoders.sh`, and `screen-record/monitors.sh` through `SCRIPT_DIR=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)`.
  - `screenshot-region.sh`: `SUPER+X`/`Print` region capture. Under one `flock` it grabs the focused monitor with `grim -o <mon> -l 0`, opens the Quickshell `screenshot` overlay with that PNG, waits for the `screenshot` layer in `hyprctl layers -j` (up to 100 × 5 ms), lets `slurp` draw the region over the frozen frame, closes the overlay, scales the logical slurp coordinates by the monitor scale and crops with `ffmpeg`; the crop goes to `wl-copy -t image/png` and a copy is saved as `shot_<YYYY-mm-dd_HH-MM-SS>.png` under `~/Pictures/Screenshots` (`KOLIR_SHOT_DIR`). Without a shell/overlay it falls back to live `slurp` + `grim -g`, and without `ffmpeg` it re-grabs the scaled region from the live screen. Escape/cancel exits silently; the lock makes a second SUPER+X during a selection a no-op.
- [config/quickshell/shell.qml](config/quickshell/shell.qml): Quickshell `ShellRoot`. Instantiates `Frame`, `Bar`, `CaptureHistory`, `FilePicker`, `Launcher`, `Notification`, `VolumeOsd`, `BrightnessOsd`, `RecordingSetup`, `ScreenshotOverlay`, and `Shortcuts`; settings is embedded in `Bar`.
- [config/quickshell/bar/](config/quickshell/bar): Top panel and screen frame. [Bar.qml](config/quickshell/bar/Bar.qml) is a full-screen Top-layer `PanelWindow` that paints and accepts input only on the 30px bar strip (the whole surface while settings is open). Layout: settings trigger, active window (currently disabled: `Bar.showActiveWindow` is `false`, so the chip is hidden but its component and slot stay in the tree for an easy re-enable), now playing, workspaces, a flat clock/keyboard-layout block, then a status zone (recording alert, the caffeine indicator only while active, and the Bluetooth capsule only while a device is connected), then the control row (tray, battery only when a battery is expected, brightness, volume, notification bell, power). Controls are filled pills or hoverable icon buttons; statuses are flat and never open a menu. A hairline `statusDivider` separates the two zones. It also hosts `SettingsMenu` as an overlay so the popout shares the bar surface. While the night-light or sound sheet is open the brightness or volume chip lifts out of the control row, stretches over the sheet's width and becomes its header (see the Chip Header Morph quirk). [Frame.qml](config/quickshell/bar/Frame.qml) is a full-screen Bottom-layer `PanelWindow` that paints the screen frame below windows; it is click-through and its corners cannot clip window borders. `FrameService` selects `ring` (the original full frame in `surfaceContainerLow`, with `gaps_out = 4`) or `corners` (only four spandrels, no side/bottom strips, `gaps_out = 0`): the upper two reuse the bar colour and the lower two are black.
- [config/quickshell/bar/components/](config/quickshell/bar/components): UI primitives and widgets. Primitives: `Surface`, `Pill` (filled control capsule), `HeaderPill` (a `Pill` that stretches into its sheet's header; the brightness and volume chips derive from it), `StatusItem` (flat status icon + label; no container or hover scale, and no menu affordance), `IconButton`, `AppIcon`, `ProgressIndicator`, `VolumeSlider`, `CopyableValue` (read-only text that copies itself on click and shows a hover copy glyph / brief check), `TextField` (single-line input with a placeholder, an invalid-state border and Return/Escape signals; the calendar event form uses it), `PopupHeader` (shared title/subtitle block for the embedded sheets). Widgets: `ActiveWindow` (present in `Bar.qml` but hidden while `Bar.showActiveWindow` is `false`), `Workspaces`, `NowPlaying` (expandable MPRIS island that keeps a clock-wide slot, expands on hover, pauses/resumes playback on a click on the capsule, shows a muted note while idle, and replaces the scrubber/times with a live badge for broadcasts), `Clock` (flat date/time/keyboard layout; only the date is interactive and opens `CalendarPopup`, the rest is information), `CalendarPopup` (floating embedded sheet with the month grid, centered under the clock's date), `KeyboardLayout`, `Tray` (the status-notifier icon row; its menu is the shared floating `TrayMenu` sheet), `TrayButton` (one icon: left click opens the item's menu when it has one and otherwise activates it, middle click secondary-activates, wheel forwarded to the app; right click is unhandled), `TrayMenu` (the DBusMenu tree as a floating `EmbeddedSheet` whose root card is centered under the clicked icon — the decorative right shoulder extends one `panelFlare` past the card; each open submenu adds a framed column to the left, and Escape or an outside click closes it), `TrayMenuPane` (one column: check/radio glyphs, themed icons and a scrollable row list), `RecordingStatus` (flat red alert; clicking stops the recording), `CaffeineIndicator` (flat status, only while active; clicking turns keep-awake off and holds a struck-through `Off` answer before it fades), `BluetoothChip` (control capsule in the status zone next to `CaffeineIndicator`, naming the connected Bluetooth device the bar leads with, a `+N` for the rest and the battery percentage/glyph; hidden while nothing is connected, opens Settings → Bluetooth), `Battery` (control pill, only when a battery is expected), `ChargeBloom` (the one-shot halo, ring and bar-edge streak `Battery` plays when the charger connects), `Brightness`, `Volume`, `NotificationBell` (unread badge, `notifications_off` glyph under DND, toggles the notification sheet), `NotificationCenter` (the mirrored notification sheet), `NotificationHistoryCard` (one history row; a same-app run folds into the leader row with a `N ⌄` control), `PowerTile` (one action card in the power sheet, normal or full-width destructive), `PowerPopup` (the mirrored power sheet: lock, suspend, log out, restart and shut down with an inline confirmation), `Toggle`. `VolumePopup` + `SoundControls` implement the sound sheet, opened by a left click on the volume chip (its mute lives inside the output card), and like the night-light sheet it has no title block: the volume chip stretches into its header; `BrightnessPopup` is the night-light sheet opened by a left click on the brightness chip, likewise headed by its chip (see the Chip Header Morph quirk for both); `BatteryPopup` + `battery/BatteryDetails` show the aggregate UPower level, state, time, power, energy and health from a left click on the battery chip; `NotificationCenter` is the notification sheet the bell opens, with the grouped history list, a `Clear all` pill and the DND card, sized to `min(560, max(320, screen height − bar height − 8))`; `CalendarPopup` is the calendar sheet the clock's date opens, with a `PopupHeader` and two cards: the month grid (up to three dots on a day with events, a small count pill once it has more than three, the selected day ringed, today filled with `Colors.primary`) and the selected day's event list, whose `+` opens an inline form (title, all-day toggle, start/end time). A local row carries a delete button; a Google row is read-only, so it hides the trash, names its source calendar in muted text, tints the accent bar with `calendarColor` and dims while an insert is pending. A failed sync or insert shows as a red line under the day list (the card grows by `formErrorHeight + detailsSpacing` while it is visible). It reads and writes `CalendarService` and calls `CalendarService.refresh()` on open, so adding an event immediately paints the day's dots. All are drawn inside the bar surface like `SettingsMenu`, mirrored to the right edge: their opaque `surfaceContainerLow` body runs to the physical screen edge (shoulder on the left, pour into the bottom-right corner), so while one is open it covers the decorative frame ring and the compositor's active-window border instead of outlining the panel with a foreign colour, and it closes with Escape or an outside click instead of `HyprlandFocusGrab`. The brightness and volume chips adjust on wheel scroll and ignore every other mouse button. `SunTimeCard` renders read-only solar times. Subdirectories: `media/` (`MarqueeText`, `MprisController`), `sound/` (`AudioDeviceCard`, `AudioDeviceList`, `CodecChip`), `nightLight/` (`TemperatureCard`, `ScheduleCard`, `TimeField`), `battery/` (`BatteryDetails`).
- [config/quickshell/theme/](config/quickshell/theme): Visual-only singletons declared in `qmldir`: `Colors`, `Dimensions`, `Typography`, `Icons`, `Motion`. No services or path contracts here. Every palette entry in `Colors` crossfades through `Motion.theme` when Matugen rewrites `colors.json`; `Motion` also carries the shared timing tokens (including `theme` and `themeEasing`).
- [config/quickshell/services/](config/quickshell/services): Runtime singletons and path contracts declared in `qmldir`: `AppearanceService`, `AudioService`, `BatteryService`, `BluetoothDevicesService`, `BrightnessService`, `CaffeineService`, `CalendarService`, `CaptureHistoryService`, `DeviceBatteryService`, `EventSoundService`, `FrameService`, `HyprsunsetService`, `NotificationService`, `PowerService`, `ShellPaths`, `WallpaperService`. `FrameService` owns the screen-frame choice (`ring`/`corners`), persists it in `~/.cache/quickshell/frame.json` and exposes IPC target `frame`; `Frame.qml` watches it for the painted style and pushes the matching `gaps_out` with `hyprctl eval`, while `hyprland.lua` reads the same file on every reload so startup never flashes the other style. `WallpaperService` reads `~/.cache/quickshell/wallpaper.json` (the scripts are the only writers), mirrors the active `awww`/`mpvpaper` backend and the last image/video paths, relays a switch to `wallpaper-backend.sh` (rolling the optimistic value back on failure) and replays a video on shell start through the idempotent script. `AppearanceService` owns the Matugen scheme type, contrast, auto/light/dark mode and the palette-crossfade switch, persists them in `~/.cache/quickshell/appearance.json`, reruns `generate-colors.sh` with `KOLIR_MATUGEN_*` overrides, and runs the scheme-palette preview worker while the Appearance page is visible; `Colors.qml` then crossfades to the palette without a shell restart. `DeviceBatteryService` runs the one-shot `scripts/device-battery/main.py` helper once a minute and exposes the first reading (plus all readings) to the bar; the helper owns the provider chain, the exact-reading cache and the `cached`/`stale`/`age` metadata, while the service forces a read on a fresh audio connection (1 s snapshot of `Bluetooth.devices`), retries once 6 s later, and kills a helper that has not answered after 25 s. `BluetoothDevicesService` mirrors the connected subset of `Bluetooth.devices` with a 1 s snapshot (sorted audio → input → other), merges `DeviceBatteryService`'s exact percentage with BlueZ's coarse `battery`, and exposes the primary device, the `+N` count and the battery state to `BluetoothChip`; its `bluetoothDevices status` IPC returns the merged array. `BatteryService` is the UPower reader for the chip and the battery sheet, exposing the display device's raw detail values (`chargeState`, `timeToEmpty`, `timeToFull`, `powerDraw`, `energy`, `energyCapacity`, `healthSupported`, `health`) alongside the chip state, and emits the one-shot `chargerConnected` event when AC power starts; the first UPower state after the shell starts is recorded silently. `BrightnessService` owns both brightness backends (internal `brightnessctl` and external DDC/CI `ddcutil`) and coalesces writes; it is the only writer behind the bar chip, the OSD and the brightness keys. `CalendarService` owns the calendar events; persistence sits behind a swappable backend ([calendar/CalendarGoogleBackend.qml](config/quickshell/services/calendar/CalendarGoogleBackend.qml), contract `load`/`create`/`update`/`remove`/`refresh` plus `loaded`/`changed`/`failed`). That default is a hybrid: the local file ([calendar/CalendarLocalBackend.qml](config/quickshell/services/calendar/CalendarLocalBackend.qml), the only writer of `~/.cache/quickshell/calendar.json`) keeps the events created while no account is connected, and the Google helper adds the account's calendars to the same snapshot. The helper ([scripts/google-calendar/main.py](config/quickshell/scripts/google-calendar/main.py)) is the only writer of `~/.cache/quickshell/google-calendar.json` and the only component that talks to Google: `status` (cached account, calendars and events), `auth` (OAuth 2.0 loopback with PKCE; scopes `calendar.events` + `calendar.calendarlist.readonly`, and the granted scope set is verified so a consent that dropped event access is rejected instead of leaving an account with zero events), `sync` (every non-deleted calendar, `singleEvents`, a −30 days…+12 months window, deduped by iCalUID with the primary first) and `add` (insert into the primary calendar). It never calls `events.update`, `events.patch` or `events.delete`, so the sync is read-plus-add; Google events arrive with `readOnly: true` (the service refuses `updateEvent`/`removeEvent` for them) plus `calendarId`/`calendarSummary`/`calendarColor`. `CalendarService` also exposes the sync state (`googleConfigured`, `googleHasSecret`, `googleConnected`, `googleSyncing`, `googleNeedsReauth`, `googleAccount`, `googleClientId`, `googleLastSync`, `googleCalendarCount`) and `refresh(force)`. The canonical event shape lives in [calendar/CalendarModel.js](config/quickshell/services/calendar/CalendarModel.js) (`dayKey`, `parseDayKey`, `parseTime`, `timeLabel`, `buildEvent`, `normalizeEvent`, `parseState`, `serializeState`, `eventsOn`, `eventsInMonth`, …) and maps onto Google's Events resource / iCalendar VEVENT (uid ↔ iCalUID, all-day `date` with an exclusive end, timed `dateTime` + IANA `timeZone`, unknown metadata preserved); the service resolves the machine's IANA zone once at startup and exposes `eventsOn`, `dayCounts`, `addEvent`, `updateEvent` and `removeEvent`. Subdirectories hold pure JS libraries with `.pragma library` and no state: [audio/AudioParser.js](config/quickshell/services/audio/AudioParser.js) (`clampPercent`, `volumePercent`, `channelList`, `describeDevice`, `deviceIcon`, `devicesFromList`, `cardsFromList`, `cardNameForSink`), [bluetooth/Devices.js](config/quickshell/services/bluetooth/Devices.js) (`rankOf`, `isAudio`, `sortDevices`, `glyph`; the glyph mapping is shared with the Bluetooth settings row) and [hyprsunset/Solar.js](config/quickshell/services/hyprsunset/Solar.js) (`computeSunTimes`, `calculateSunEvent`); `calendar/` holds `CalendarGoogleBackend.qml` (the default hybrid backend) and `CalendarLocalBackend.qml` next to its pure model. The services keep thin same-name wrappers; JSON guards, `console.warn` diagnostics and all service state stay in QML. `EventSoundService` plays the short notification, USB and low-battery chimes through `scripts/event-sound.sh`, coalesces a burst into one process and watches USB attaches through `scripts/usb-watch.sh`; do-not-disturb silences the notification and USB chimes but not the low-battery warning. `NotificationService` owns the single `NotificationServer` (`keepOnReload`), the persisted newest-first history (50 entries) in `~/.cache/quickshell/notifications.json`, the unread counter and the DND flag: every non-transient arrival is recorded and chimes, DND or an open center suppresses only the live card (and opening the center suppresses the cards already on screen), and `transient` notifications never enter the history. `CaptureHistoryService` owns the capture model, the 5 s poll that runs only while its panel is open, and the copy/open/delete `Process`es; it runs `scripts/capture-history.sh` with the 50-entry limit and the two source directories, streams the `total` line plus `path/thumb/kind/mtime` records, and rebuilds the model only when the `path + mtime` signature changes so a running selection survives a poll.
- [config/quickshell/settings/](config/quickshell/settings): Embedded settings popout (`SettingsMenu.qml`) with `MainPage`, Bluetooth, Internet, Appearance and Calendar pages, `SettingsPageHeader`, the shared `PasswordField`, `CaffeineCard` (`Keep awake` switch plus 15/30/60 min/∞ presets on the main page), and `FrameCard` (`Screen frame` visual previews for the full frame and corner-only modes at the bottom of the Appearance page; each `FramePreview.qml` tile is a miniature screen drawn on a Canvas with the mode name and a one-line effect underneath, the selected tile carrying a primary outline and check mark). `AppearancePage.qml` shows the live palette swatches, a 5×2 grid of segmented circular scheme swatches (primary top half, secondary/tertiary bottom quarters; the selected/hovered name appears in the card header), a -1…+1 contrast slider with -1/0/+1 preset buttons, Auto/Light/Dark mode chips with the detected location and sunrise/sunset times, and a `Crossfade palette` switch that lets slow machines apply palette changes instantly. `internet/` contains `NetworkController`, `EthernetCard` (its detail values are click-to-copy `CopyableValue`s; only the summary row toggles the card), `WifiCard` (same pattern, plus the radio switch and the details of the associated access point), `WifiConnectionForm`, `WifiNetworkRow`; `bluetooth/` contains `BluetoothDeviceRow`. `CalendarPage.qml` is the Google Calendar page: an account card (the connected address, `N calendars · synced HH:mm`, `Sync now` and `Disconnect`, plus the last sync error in red), an always-visible OAuth client card (client ID field, `PasswordField` secret, `Connect with Google`/`Reconnect`, the helper's error or the connected address inline) and a read/add help card; it runs the `auth` helper itself and then calls `CalendarService.refresh(true)`, so it never holds a token. Sound settings are not a page here; they live in the bar volume sheet.
- [config/quickshell/launcher/](config/quickshell/launcher): App launcher with scored search, math evaluation, clipboard mode (`;` prefix) and quick tasks (`.` prefix). A `.` query shows one card with the typed text and the resolved Obsidian daily note; Enter appends a checkbox `- [ ] <text>` through `scripts/quick-note.py` and closes silently, while a missing vault keeps the card open with the helper's error. `ClipboardController.qml` lives in a root `Scope` and owns the `cliphist-watch.sh` clipboard watchers and clipboard model; `SearchLogic.js` holds pure search/calculator functions; `LauncherResultRow.qml` renders rows. The launcher `PanelWindow` is a full-screen Overlay surface with `ExclusionMode.Ignore` (so it also covers the 30px bar strip) and the card animated inside it: the transparent rest is the dismissal layer, and a click anywhere outside the card — bar included — closes the launcher. A card-sized window never saw those clicks, so outside clicks used to do nothing.
- [config/quickshell/notification/](config/quickshell/notification): The live notification stack. `Notification.qml` is a root `Scope` with one Overlay `PanelWindow` on the `notifications` namespace at the top-right (`ExclusionMode.Ignore`, hidden while DND is on or the notification sheet is open) that renders Quickshell's tracked notifications; `NotificationCard.qml` is one card. Consecutive arrivals from the same app share a card: the first of a run owns it and folds in every following notification with the same `appName`, while a notification from another app starts a new card, so the stack keeps arrival order. The card shows the newest message and, for a run, a `N ⌄` control that expands the older messages in place (newest first, capped at `maxExpandedOthers: 4`); one or two quieter, narrower sheets peek 4 px below it as stack edges and fade away as the card opens. A run of one is the plain card. `Critical` urgency (any member of the run) tints the card with `error`; the slot animates the card in and collapse-fades it on close; a folded member draws no card and owns no expiry timer. The card (and its stack edges) is frosted: a translucent 0.80 `surfaceContainerLow` fill over the `notifications` layer blur, because a 0.96 fill hid the effect completely. The server, history, unread counter and DND flag live in `services/NotificationService.qml`.
- [config/quickshell/osd/](config/quickshell/osd): Shared `OsdPanel` plus the bottom-center `VolumeOsd` and `BrightnessOsd` with wavy Material 3 progress indicators.
- [config/quickshell/recording/](config/quickshell/recording): One-shot recording setup panel (`RecordingSetup.qml`) with `RecordingOptions.qml` and `OptionRow.qml`; passes choices to `screen-record.sh --start`.
- [config/quickshell/capture/](config/quickshell/capture): Capture history (`SUPER+SHIFT+V`). `CaptureHistory.qml` is a root `Scope` with IPC target `captureHistory` and one full-screen Overlay `PanelWindow` on the `capture-history` namespace (`WlrKeyboardFocus.Exclusive`, `ExclusionMode.Ignore`) holding a 1120×780 (clamped to screen minus 48 px margins) panel of a 4-column `GridView`: header with title, live count and refresh/close buttons, footer with the key hints and the scan progress, newest-first screenshots and recordings from `CaptureHistoryService`. Arrows move the selection (wrap on, hover follows), Enter opens through `xdg-open`, `C` copies (image bytes through `wl-copy -t <mime>`, the absolute path for a recording), Delete arms an in-panel confirmation for 6 s and a second Delete removes the file, Escape cancels a pending delete before it closes, an outside click closes. Footer status messages clear after 2.6 s. `CaptureTile.qml` is one card: cached 16:9 poster (a play badge for video), file name and time, hover copy/open/delete actions, and the delete confirmation drawn over the poster.
- [config/quickshell/screenshot/](config/quickshell/screenshot): `ScreenshotOverlay.qml` is a root `Scope` with IPC target `screenshot` and a full-screen Top-layer `PanelWindow` on the `screenshot` namespace that shows the PNG frozen by `screenshot-region.sh` as one synchronously decoded `Image`. It is click-through (`mask: Region {}`), takes no keyboard focus (`WlrKeyboardFocus.None`), uses `ExclusionMode.Ignore`, and its `screenshot-no-anim` layer rule makes the frame appear and disappear instantly; slurp draws the selection on the Overlay layer above it, so Escape and the pointer reach slurp.
- [config/quickshell/shortcuts/](config/quickshell/shortcuts): Keyboard shortcut cheat sheet opened with `SUPER+D`. `Shortcuts.qml` is a root `Scope` with IPC target `shortcuts` (`toggle`, `open`, `close`), a centered Overlay `PanelWindow` on the `shortcuts` namespace, a filter field, Escape/outside-click dismissal and a scrollable list grouped by modifier set. Every open re-reads `hyprctl binds -j`; `ShortcutParser.js` is a stateless `.pragma library` that turns the JSON into groups/rows (modifier labels, friendly key names, description fallback, key sorting, filtering), and `ShortcutRow.qml` renders one key chip plus its action.
- [config/quickshell/filepicker/](config/quickshell/filepicker): The shell's single file/folder picker (`FilePicker.qml`) and its cell (`FileTile.qml`), used by the XDG Desktop Portal FileChooser backend and by the wallpaper hotkey. `FilePicker` is a root `Scope` with two IPC targets: `filePicker` (`open <json>`, `cancel <id>`, `accept`, `toggleIndex <n>`, `search <query>`, `closeSearch`, `newFolder <name>`, `showHidden <bool>`, `status`) and `wallpaper` (`toggle`, `open`, `close`, `random`, `openDir <path>`, `up`, `home`, `editPath`, `setBackend <awww|mpvpaper>`, `backendStatus`, `status`). It is a full-screen Overlay `PanelWindow` on the `filepicker` namespace with an inline path field driven by `complete-dirs.sh`, filter chips, a footer **Show hidden files** checkbox (dot entries are filtered inside `list-files.sh`/`search-files.sh`, not in QML), recursive type-to-search, single/multi selection and the portal modes `openFile`/`openDirectory`/`saveFile`/`saveFiles`. It streams one directory from `list-files.sh` into a `ListModel`, remembers the portal's last folder separately in `lastFileDir` (browsing wallpapers never moves the next file dialog into the library), and writes `{"uris":[...],"writable":true}` or `{"cancelled":true}` to the `resultPath` supplied by the portal backend. The extra `wallpaper` mode is the wallpaper picker (there is no separate component): it starts in `ShellPaths.wallpaperDir`, keeps the browsed folder in `wallpaperDir` for the shell lifetime, lists only the active engine's extensions (jpg/jpeg/png/gif, or mp4/webm/mkv/mov/m4v/avi for mpvpaper), and hides the new-folder row, accept/cancel pills and portal result. A click/Enter applies through `set-wallpaper.sh` + `generate-colors.sh` (the library Random still runs `random-wallpaper.sh`); the header keeps the **Images**/**Videos** chips and Random, with the chips driving `WallpaperService.setBackend`, so the grid re-filters without a restart. Both modes share the search, path completion, folder navigation and lazy 16:9 posters from `file-thumbnail.sh`: only visible tiles ask for one, stored under `~/.cache/quickshell/file-previews`. The `filepicker-blur` layer rule frosts the panel area only; the panel is a 0.80 `surfaceContainerLow`, while the transparent outside stays sharp and click-through. Escape, an outside click and the close button close a wallpaper pick without applying anything; in portal modes they take the cancellation path, and only Enter/click on a file, the accept button or the `accept` IPC finish a request.
- [config/quickshell/scripts/](config/quickshell/scripts): Helpers bundled with the shell: `favicon.py`, `cliphist-store.py`, `cliphist-previews.py`, the `cliphist-watch.sh` singleton wrapper around `wl-paste --watch`, the `pactl-subscribe.sh` singleton wrapper around `pactl subscribe`, `file-thumbnail.sh`, `capture-history.sh`, `complete-dirs.sh`, `list-files.sh`, `search-files.sh`, `portal-filechooser.py`, `palette-previews.sh` + `palette-previews.py`, `quick-note.py`, `event-sound.sh`, the `usb-watch.sh` singleton wrapper around `udevadm monitor`, and `device-battery/` (`main.py` plus the `providers/` package), plus `google-calendar/main.py` (the Google Calendar helper behind Settings → Calendar and the calendar sheet: OAuth 2.0 loopback with PKCE, `status`/`sync`/`add`/`disconnect`, one JSON object per run, Python standard library only, and the only writer of `~/.cache/quickshell/google-calendar.json`). `portal-filechooser.py` is the D-Bus-activated `org.freedesktop.impl.portal.FileChooser` backend: it parses the portal options, calls `qs … ipc call filePicker open <json>`, waits asynchronously for the shell's result file and answers the portal (`0` with `file://` URIs or `1` on cancellation/timeout). `list-files.sh` takes `<dir> [show-hidden]` (`1`/`0`, default `1` for older callers) and prints one `dir`/`file` record per entry; `search-files.sh` takes `<dir> <query> [show-hidden]` and prunes dot entries when hidden is off, so a recursive search cannot leak out of `~/.config` while the picker's footer checkbox is cleared. Both stop an identical worker left by a previous shell. `quick-note.py` resolves the Obsidian vault (`KOLIR_OBSIDIAN_VAULT`, then `~/.config/obsidian/obsidian.json`, then the Matugen `[templates.obsidian]` output path), reads the vault's `.obsidian/daily-notes.json` (folder, Moment-style date format, optional template) and either reports the target note (`target`) or appends a checkbox line `- [ ] <text>` (`add <text>`), creating the note from the template on first use; every answer is one JSON object and failures exit 1 with `{"ok":false,"error":"…"}` so the launcher can show why. `palette-previews.sh` resolves the current wallpaper through `lib/monitors.sh`/`lib/mpvpaper.sh`/`lib/wallpaper.sh` (a cached frame for video) and `palette-previews.py` runs Matugen `--dry-run --json hex` for all ten schemes in parallel, extracting primary/secondary/tertiary/error/surface colors and caching them by wallpaper mtime + mode + contrast in `~/.cache/quickshell/palette-previews.json`. `device-battery/main.py` prints a JSON array of connected Bluetooth audio battery readings; providers are brand modules (`providers/bluez.py` for `org.bluez.Battery1`, `providers/sony.py` for exact Sony MDR v2 values) registered in `providers/__init__.py`, and its README documents adding a brand. It is one-shot, exits 0 with `[]` when nothing is connected or a dependency is missing, and caches exact readings in `~/.cache/quickshell/device-battery.json`. Every reading carries `cached`/`stale`/`age`: `stale` means the device did not answer and the last known sample was reused. The cache file also stores the addresses seen connected on the previous run, so a reconnect never reuses the previous session's level; the shell passes `--force` for the same reason, and the helper bounds its GLib loop with a watchdog. `file-thumbnail.sh` takes `<cache-dir> <path>` and prints one `<thumb>\timage|video` record for a single image or video, so the picker runs it only for tiles that become visible and a huge folder never pre-generates posters; the cache key is `sha1(path + mtime)`, the poster is a 16:9 JPEG (a one-second frame for clips), and unsupported types fail before `ffmpeg` starts. `capture-history.sh` takes `<cache-dir> <limit> <dir>...`, scans each directory one level deep for images and video extensions, sorts by mtime newest-first, prints one `total<TAB>n` line and then one `<path><TAB><thumb><TAB>image|video<TAB>mtime` record per file, and encodes only missing 480×270 posters with ffmpeg (the 0.5 s frame for video) into the cache keyed by `sha1(path + mtime)`; it kills an identical worker left by a previous shell, writes posters through a temp file plus rename, and prints an empty thumb for a file ffmpeg cannot decode so the card stays openable. `event-sound.sh` maps a named event (`notification`, `usb`, `battery-low`, `battery-critical`) to a freedesktop theme sound and plays it with `pw-play`/`paplay`, falling back to `canberra-gtk-play` and reporting a failure as a notification; `usb-watch.sh` stops an identical `udevadm monitor` left by a previous shell and then execs it with `--udev --subsystem-match=usb --property`. QML reaches them through `ShellPaths`.
- [config/matugen/config.toml](config/matugen/config.toml): Tracked Matugen outputs for Foot, live terminal sequences, Hyprland, Quickshell, GTK3, and GTK4. Obsidian is deliberately absent: it needs a per-user vault path and `kolir setup --obsidian` appends the optional `[templates.obsidian]` block to the user's copy. `zen` templates remain a local customization.
- [config/matugen/templates/](config/matugen/templates): Tracked templates: `foot-colors.ini`, `terminal-sequences`, `hyprland-colors.lua`, `quickshell-colors.json`, `gtk3-colors-template.css`, `gtk4-colors-template.css`, `obsidian.css` (an Obsidian CSS snippet, copied to the vault only when opted in), and the lock-screen template `hyprlock-colors.conf` (used through `config/matugen/hyprlock.toml`).
- [config/foot/](config/foot): Foot base config (`foot.ini`) and a bundled fallback `colors.ini`.
- [config/mpv/mpv.conf](config/mpv/mpv.conf): MPV configuration.
- [tools/kolir.py](tools/kolir.py): The phase-1 CLI (Python 3.11+, stdlib only). `setup` creates the per-user glue with timestamped backups and `--dry-run`, creates `~/Pictures/wallpaper`, and offers to install the missing optional packages (never the required ones), `doctor` checks commands, links, generated files, Matugen inputs/outputs, Hyprland config errors, and the reload units (screen recording is satisfied by `wf-recorder` or `wl-screenrec`, reported as `ok screen recording (<found>)`, an error only when both are missing, and the `wl-screenrec` optional row is suppressed while `wf-recorder` is absent because the required row already reports it); `reload` regenerates colors/reloads Hyprland/restarts the shell; `shell` and `ipc` exec `qs` from the resolved root; `wallpaper` reads/writes the same state as the picker (`status`, `backend awww|mpvpaper`, `set <file>`, `random`, with `--no-colors` on the first two), so the engine can be switched from a terminal without the shell; `version` prints `<root>/.version` or `git describe`; `uninstall-user` removes only glue that still points into `<root>`. Root resolution is `$KOLIR_ROOT` -> physical checkout around the script -> `/usr/share/kolir`.
- [bin/kolir](bin/kolir): POSIX dev wrapper that execs `python3 <root>/tools/kolir.py "$@"`; the phase-2 package will install the Python file as `/usr/bin/kolir` instead.
- [tools/check.sh](tools/check.sh): Repository check script (POSIX, executable). It resolves the root through `config/hypr/scripts/lib/root.sh`, then runs qmllint over every `config/quickshell/**/*.qml` (prefers `/usr/lib/qt6/bin/qmllint`, then `PATH`, skips when absent), `python3 -m py_compile` over `tools/kolir.py` and `config/quickshell/scripts/**/*.py` with `PYTHONPYCACHEPREFIX` redirected outside the tree, and `sh -n`/`zsh -n`/`bash -n` per file, picking the interpreter from each shebang, over `bin/kolir`, `config/hypr/scripts/**/*.sh` and `config/quickshell/scripts/**/*.sh`. - **Auto-reload units**: no unit files are shipped. `kolir setup --auto-reload` renders `kolir-reload.path` + `kolir-reload.service` into `~/.config/systemd/user/` for the active root (watching `<root>/.version` and the current git ref), verifies them with `systemd-analyze --user verify`, and enables the path unit; `reload` is a no-op with a warning when no Wayland session is available. ## 3. Data Flow
```
Wallpaper (SUPER+CTRL+T grid / SUPER+CTRL+ALT+T random)
        ├─> open-wallpaper-picker.sh
        │     ├─> qs ipc call wallpaper toggle  (FilePicker.qml wallpaper mode)
        │     │     ├─> list-files.sh / search-files.sh + file-thumbnail.sh
        │     │     └─> selection / Random
        │     └─> select-wallpaper.sh (Zenity fallback when no shell answers)
        └─> set-wallpaper.sh (awww img for images, mpvpaper for videos)
              └─> generate-colors.sh
Theme toggle (Settings → Appearance, or toggle-theme.sh directly)
        └─> toggle-theme.sh (~/.cache/current_theme, GTK/KDE theme)
              └─> generate-colors.sh
Appearance page (SettingsMenu → AppearancePage.qml)
        └─> AppearanceService.setType/setContrast/setMode
              ├─> ~/.cache/quickshell/appearance.json
              └─> generate-colors.sh with KOLIR_MATUGEN_TYPE/CONTRAST/MODE
                    └─> ~/.config/quickshell/colors.json ──> Colors.qml (live)
generate-colors.sh
  selects the monitor ($KOLIR_MONITOR, then focused, then first, then DP-1)
  resolves the wallpaper (awww query -j, then the version-tolerant cache scan)
  selects the config ($KOLIR_MATUGEN_CONFIG, ~/.config/matugen/config.toml, repo copy)
  pre-validates every template input with python3 + tomllib
  reads ~/.cache/current_theme (creates it as dark when missing)
  reads ~/.cache/quickshell/appearance.json (env KOLIR_MATUGEN_* wins)
    scheme type: one of the ten matugen --type values (default scheme-neutral)
    contrast: -1..1 (default 0)
    mode: auto → sunrise/sunset from HyprsunsetService, light/dark explicit
  runs: matugen image <path> --source-color-index 0 --mode <mode> --type <type> --contrast <c>
        ├─> ~/.config/foot/colors.ini
        ├─> ~/.cache/terminal-sequences  ──> tee /dev/pts/* (live Foot)
        ├─> ~/.config/hypr/colors.lua    ──> hyprctl reload
        ├─> ~/.config/quickshell/colors.json
        ├─> ~/.config/gtk-3.0/colors.css ──> imported by ~/.config/gtk-3.0/gtk.css
        ├─> ~/.config/gtk-4.0/colors.css ──> imported by ~/.config/gtk-4.0/gtk.css
        └─> ~/.config/matugen/…obsidian output (only when setup added the block)
```
- **Wallpaper Trigger**: `SUPER+CTRL+T` runs `config/hypr/scripts/open-wallpaper-picker.sh`, which toggles the shared `FilePicker` in wallpaper mode over IPC (`wallpaper toggle`) and falls back to `select-wallpaper.sh` (Zenity) when the shell is not running. The header's **Images**/**Videos** chips switch the backend through `WallpaperService` → `wallpaper-backend.sh` (Images stops a playing video, Videos replays the saved clip) and re-filter the grid with the matching extensions. The panel's selection applies `set-wallpaper.sh` (awww for images, mpvpaper for videos) and then `generate-colors.sh`; its Random button and `SUPER+CTRL+ALT+T` run `random-wallpaper.sh`, which follows the active backend. The grid supports the same recursive search as portal requests, and closing the panel with Escape or an outside click applies nothing.
- **File Picker Trigger**: every GTK/Qt application that uses `xdg-desktop-portal` (`GTK_USE_PORTAL=1`, `QT_QPA_PLATFORMTHEME=xdgdesktopportal`, both set by `hyprland.lua`, plus Firefox's default `widget.use-xdg-desktop-portal.file-picker=2`) asks the kolir backend instead of the GTK dialog. `xdg-desktop-portal` calls `portal-filechooser.py`, which parses the `OpenFile`/`SaveFile`/`SaveFiles` options and runs `qs -p <root>/config/quickshell ipc --any-display call filePicker open <json>`. `FilePicker.qml` shows the same grid the wallpaper hotkey opens and writes `{"uris":[...],"writable":true}` or `{"cancelled":true}` to the result path; the backend answers the portal with `file://` URIs (`0`) or cancellation (`1`). Closing the picker, an outside click, the backend's `Request.Close` and the 10-minute timeout all cancel. If the shell is not running, the backend answers `1` and raises a notification (only visible while a notification daemon is alive); the wallpaper hotkey keeps its Zenity fallback.
- **Screenshot Trigger**: `SUPER+X` or `Print` runs `screenshot-region.sh`. It freezes the focused monitor into a temp PNG (`grim -o <mon> -l 0`), calls `qs ipc call screenshot open <png>`, waits for the `screenshot` layer, lets `slurp` select over the frozen frame, closes the overlay, scales the logical coordinates by the monitor scale and crops with `ffmpeg`; the PNG goes on the clipboard and a copy is saved under `~/Pictures/Screenshots` (`KOLIR_SHOT_DIR`) for the capture history. Without the shell or `ffmpeg` it falls back to live `slurp` + `grim`, and only one capture runs at a time (`flock` on `$XDG_RUNTIME_DIR/kolir/screenshot.lock`). Escape cancels without writing anything.
- **Capture History Trigger**: `SUPER+SHIFT+V` runs `qs-ipc.sh captureHistory toggle`; `CaptureHistory.qml` opens the `capture-history` overlay and `CaptureHistoryService.setActive(true)` starts the 5 s poll. The grid reads the newest screenshots from `ShellPaths.screenshotDir` and recordings from `ShellPaths.recordingsDir`; Enter opens, `C` copies, `Delete` twice removes, Escape/outside click closes, and closing stops the poll. A capture that lands while the panel is open appears on the next tick without a shell restart.
- **Notification Flow**: an app's notification reaches `NotificationService.server`; a non-transient notification is prepended to the persisted history (50 entries), increments `unread` unless the center is open and chimes through `EventSoundService`, then shows a live card unless DND or the center is open. Consecutive arrivals from one app fold into a single card. The bar bell opens `NotificationCenter`, which clears `unread`, suppresses the live cards, lists the history with same-app runs folded, and offers per-run and per-row delete, `Clear all` and the DND switch through the `notifications` IPC target. DND keeps recording history and silences only the cards and chimes.
- **Quick Task Trigger**: typing `.` in the launcher switches it to task mode. The card resolves the destination once per open with `quick-note.py target` (status shows `Daily note · <folder>/<file>` or `New daily note · …`), and Enter or a click on the card runs `quick-note.py add <text>`, appends a checkbox `- [ ] <text>` to the vault's daily note and closes the launcher. A leading `.` deliberately shadows the calculator for inputs like `.5+2`, which now become a task; that is the accepted trade-off for a one-key capture prefix. The helper owns the vault lookup and the daily-note format, so the launcher never builds a vault path; a resolution or write failure keeps the card open with the red error line instead of losing the text. `WlrLayerShell` note mode replaces the app/clipboard list, and `win.isNoteMode` must not be read inside `onTextChanged` (its forward-reference binding is still stale there), so that handler tests `search.text.startsWith(".")` directly.
- **Theme Trigger**: the bar has no theme-toggle chip; light/dark is chosen in Settings → Appearance (`AppearancePage.qml` → `AppearanceService.setMode`), and `toggle-theme.sh` remains available from a terminal. The script flips `light`/`dark`, syncs the persisted Appearance mode to the explicit new value, writes the resolved state file first, then calls `generate-colors.sh` and applies the GNOME/GTK and KDE theme names through `lib/theme.sh` afterwards. That order keeps the shell first: `Colors.qml` crossfades the regenerated palette before the instant GTK/KDE switch, instead of GTK snapping to the new theme seconds ahead of the bar.
- **Appearance Trigger**: `AppearancePage.qml` (Settings → Appearance) or the `appearance` IPC target changes the Matugen scheme type, contrast or auto/light/dark mode. `AppearanceService` debounces the change, persists one-line JSON in `~/.cache/quickshell/appearance.json`, and reruns `generate-colors.sh` with `KOLIR_MATUGEN_TYPE`, `KOLIR_MATUGEN_CONTRAST` and `KOLIR_MATUGEN_MODE`. `auto` is a real sunrise/sunset schedule, not a wallpaper guess: it reuses `HyprsunsetService`'s detected location and solar times (the same source as the night-light sheet), resolves to light between sunrise and sunset and dark otherwise, and rechecks every 30 s and when the location arrives. The page always shows the detected location (with a refresh button) and the sunrise/sunset cards, plus a status line such as `Dark until 06:42 tomorrow`; while the location or times are unavailable Auto holds the current theme and the status explains why. Explicit light/dark (and every resolved Auto switch) update `~/.cache/current_theme` and GTK/KDE, so the stored theme state agrees. `Colors.qml` watches `colors.json`, so the palette and the preview swatches update without restarting the shell, and the palette crossfades over `Motion.theme` unless the page's `Crossfade palette` switch is off (the switch only persists `crossfade`; it never reruns Matugen). The IPC calls are `setType <scheme-…>`, `setContrast <-1..1>`, `setMode auto|light|dark`, `setCrossfade true|false`, `regenerate` and `status`.
- **Shortcut Sheet Trigger**: `SUPER+D` runs `qs-ipc.sh shortcuts toggle`, which opens `Shortcuts.qml`; the panel re-reads `hyprctl binds -j` on every open, so binds added to `hyprland.lua`/`user.lua` show up without a shell restart. The launcher is still opened by tapping `Super` alone. Hyprland reports the dispatcher but not its Lua argument, so each bind in `hyprland.lua` carries a `description` that becomes the row's action text; without one the sheet falls back to a generic dispatcher name.
- **Calendar Trigger**: a left click on the date in `Clock` emits `dateClicked`, and `Bar.qml` toggles `CalendarPopup`; the `calendar` IPC target (`toggle`, `open`, `close`, `eventAdd`, `eventRemove`, `eventList`, `status`) drives the same sheet. It uses the same `EmbeddedSheet` as the other sheets (surface, scrim, reveal, dismissal) but in its floating mode: `anchorCenterX` is the date's center in bar coordinates, so the panel is a symmetric tab under the date with the edge sheets' shoulder fillet mirrored on both sides, rounded bottom corners and no pour, instead of a screen-edge sheet. It opens on the current month every time with today selected; the card header's chevrons move one month, the `Today` action appears while another month is on screen (and also returns the selection to today), today is filled with the primary colour, the selected day carries a primary tint and ring when it is not today, and the days of the neighbouring months are dimmed. Days with events carry up to three primary dots under the numeral, and a day with more than three carries a small primary count pill (`4`, `12`, `99+`) instead of the dots, because three dots could not tell "three" from "many" (the marker sits below the day circle, so it stays primary on today's filled cell); clicking a day selects it, and a tail/head day also moves the grid to that month. The lower card lists the selected day's events with `CalendarModel.timeLabel` (`All day` or `09:30 – 10:30`), a delete button per row and a `+` that swaps the list for the inline form: title (`TextField`), an `All day` `Toggle`, and start/end `TextField`s accepting `9:30`, `09:30`, `930` and `9.30`; Return in the title saves, Escape cancels the form first and closes the sheet on the second press, and an empty title or invalid/backwards time shows a red line with the field border marked (`formErrorField`). The form writes through `CalendarService.addEvent`, rows delete through `CalendarService.removeEvent`, and the card plus the panel height animate to the form (`Motion.move`). Escape, an outside click (the shared dismissal layer) and the same date click close it. Opening it closes settings, the night-light, sound, battery and notification sheets and the expanded now-playing island; opening any of those closes it. It adds no layer namespace: the panel lives in the bar surface and reads `CalendarService`.
- **Calendar Sync Trigger**: Settings → Calendar (or `qs ipc call settings openCalendar`) connects a Google account. The page runs `python3 scripts/google-calendar/main.py auth --client-id … --timeout 300`: the helper binds a loopback server on a random 127.0.0.1 port, opens the consent page, exchanges the code for a refresh token (PKCE, `calendar.events` + `calendar.calendarlist.readonly`) and stores it with the client credentials (0600) in `~/.cache/quickshell/google-calendar.json`. The granted scopes are part of that document: a consent that dropped the event scope is rejected instead of leaving an account with zero events. `CalendarService.refresh(true)` then runs `status` (cached snapshot → `CalendarGoogleBackend` merges it with the local file and paints immediately) and `sync` (full refetch of every non-deleted calendar in the −30 days…+12 months window, deduped by iCalUID). While connected the backend re-syncs every 5 minutes; opening the sheet calls `CalendarService.refresh()` and is throttled to one network attempt a minute (`refreshFloor`), so repeated opens cannot poll Google. Adding an event posts `events.insert` and swaps the optimistic `pending` row for Google's answer; a failed insert rolls the row back and shows the helper's error under the day list. Google rows stay read-only: the trash is hidden, `CalendarService.updateEvent`/`removeEvent` refuse them, and the helper never calls update or delete. `Disconnect` clears the tokens and the remote snapshot but keeps the local events and the client credentials.
- **Keep Awake Trigger**: `CaffeineCard` (Settings → main page) or `qs ipc call caffeine …` drives `CaffeineService`. While enabled, `Bar.qml` holds a `Quickshell.Wayland.IdleInhibitor` on the bar surface, so `hypridle` receives no idle events and skips lock, DPMS and suspend. The state and timer live in `$XDG_RUNTIME_DIR/kolir/caffeine.json`; a click on the bar's `CaffeineIndicator` turns keep-awake off there, and the status holds a struck-through `Off` answer so it does not simply vanish under the pointer.
- **Power Menu Trigger**: the bar's power `IconButton` (after the notification bell) toggles `PowerPopup` through the `power` IPC target; `SUPER+Escape` and `SUPER+M` run `qs-ipc.sh power toggle`. The sheet is a right-edge `EmbeddedSheet` with five actions: Lock and Suspend run at once, Log out/Restart/Shut down enter an inline confirmation that auto-cancels after 6 seconds. `PowerService` runs `loginctl lock-session`, `systemctl suspend` (after a lock, then turns the displays back on after resume), `hyprctl dispatch hl.dsp.exit()`, `systemctl reboot` and `systemctl poweroff`, one command at a time, and keeps the failure text for the sheet header. The sheet adds no layer namespace and closes with Escape or an outside click; direct IPC actions (`power lock`, `power reboot`, …) bypass the UI confirmation for scripts.
- **Screen Frame Trigger**: `FrameCard` (Settings → Appearance) or `qs ipc call frame setStyle ring|corners` sets `FrameService.style` and writes `~/.cache/quickshell/frame.json`. The card renders one labelled `FramePreview` mock-up per entry in `FrameService.styles`; hovering one shows its hint in the card header, and the IPC `toggle` cycles the list. `Frame.qml` switches between the full ring and the four corner spandrels (bar-coloured top pair, black bottom pair), and pushes `gaps_out = 4|0` through `hyprctl eval`; `hyprland.lua` reads the same file on every reload, so a restart starts in the saved style.
- **Battery Indicator**: `BatteryService` reads `UPower.displayDevice` (the aggregate of every internal pack) plus `/sys/class/dmi/id/chassis_type` through `ShellPaths.chassisType`. `Battery` is hidden on desktops; on a portable chassis (8/9/10/11/14/30/31/32) it shows the level and percentage, or the red `battery_alert` glyph when UPower reports no usable battery. The chip turns primary while charging and error at 15% or less. When AC power starts (UPower `onBattery` true→false), `BatteryService` emits `chargerConnected` and `Battery`/`ChargeBloom` play a one-shot bloom: a soft primary halo, a thin expanding ring behind the chip, a primary streak that travels across the whole bar along its bottom edge and a 1.06 scale pulse. The first state after UPower becomes ready is recorded silently, so a shell restart with the charger already connected does not replay it; nothing animates after the ~1.2 s effect and a desktop with no system battery never shows it. A left click on the chip opens the battery sheet (`BatteryPopup` → `battery/BatteryDetails`), which shows the hero percentage with the wavy bar, the charge state plus remaining/until-full time, and only the Power, Energy and Health rows UPower actually provides; a missing battery shows the explanation card instead, and Escape or an outside click closes it without changing anything. The `battery` IPC target exposes `toggle`, `open`, `close` and `status`.
- **Event Sounds**: `EventSoundService` owns the short chimes. Notification arrivals call `playNotification()` from `NotificationService.handleNotification` (a `sound-file` hint overrides the theme sound); USB attaches come from `scripts/usb-watch.sh` → `udevadm monitor --udev --subsystem-match=usb --property`, and only `ACTION=add` + `DEVTYPE=usb_device` records play, so a device's interfaces stay silent; low battery comes from `BatteryService.lowBattery(threshold)` at 15%, 10% and 5%, edge-triggered per discharge cycle (the first reading at shell start is primed silent, charging above 15% arms a new cycle, and a drop that skips thresholds warns once at the most urgent level). One `Process` plus a 200 ms debounce coalesce a burst, and `NotificationService.dnd` silences notification and USB chimes but not the low-battery warning. `scripts/event-sound.sh` maps the event to the freedesktop theme file and plays it with `pw-play`, then `paplay`, then `canberra-gtk-play`.
- **Headset Battery**: `DeviceBatteryService` runs `python3 <root>/config/quickshell/scripts/device-battery/main.py --state <cache>` on a 60 s timer through `ShellPaths.deviceBatteryScript` / `deviceBatteryState`; after a Bluetooth audio device connects, a 1 s snapshot of `Bluetooth.devices` forces an immediate `--force` read and one retry 6 s later (the first read can land before BlueZ finishes the connection), and a 25 s watchdog kills a helper that never exits. The helper asks BlueZ for connected `audio-*` / Audio-Video-class devices and resolves each one through the provider chain: a fresh exact reading from the cache (only when the device was connected on the previous run), exact providers (`sony.py`, MDR v2 `22 00` → `23 00 <percent> <charging>` over the `956c7b26-…` RFCOMM UUID), a stale exact reading, then the generic `org.bluez.Battery1` provider. A device with no reading is omitted, so `[]` hides the capsule's percentage (and the whole capsule when nothing is connected). Every reading carries `cached`, `stale` and `age`; `stale` means the device did not answer and the last known sample was reused, which the capsule marks with a small clock and the settings row spells out as `cached N min ago`. `settings/bluetooth/BluetoothDeviceRow.qml` matches its row address against `DeviceBatteryService.devices` and prefers that exact percentage over Quickshell's coarse `BluetoothDevice.battery`; devices without a helper reading keep the BlueZ value, so the row never loses its indicator. The bar `BluetoothChip` names the primary connected device (audio first, then input), appends `+N` for the rest, shows the percentage in its trailing slot (the name elides first), turns the icon and percentage primary while charging and error at 15% or less, marks a stale sample with the clock glyph, and opens Settings → Bluetooth on click; the page forces a fresh `--force` read when it becomes visible, so the capsule itself does not raise an OSD or a notification. Without `python-dbus`/`python-gobject` the helper prints `[]`; the capsule still shows the connected device and only loses the percentage when BlueZ reports no battery either.
- **Brightness Trigger**: the bar `Brightness` chip (wheel), `qs ipc call brightness up|down|set <percent>`, and `XF86MonBrightness*` → `brightness.sh` all drive `BrightnessService`. The service adjusts every available backend (internal `brightnessctl`, external `ddcutil` VCP 0x10) and emits `brightnessChangedManually`, which `BrightnessOsd` shows. `brightness.sh` forwards the step over IPC and falls back to `brightnessctl -c backlight -e4 -n2 set 5%±` when no shell answers. A left click (or a click anywhere on the stretched header) toggles the night-light sheet, which the chip itself heads (see the Brightness Header Morph quirk).
- **Palette Generation**: `generate-colors.sh` is zsh-based. It selects the monitor through `lib/monitors.sh` (`$KOLIR_MONITOR`, focused, first, then `DP-1`) and resolves the active wallpaper through `lib/wallpaper.sh`: a live mpvpaper video (sampled to a cached frame with ffmpeg), otherwise awww's image (`awww query -j` first, then the version-named cache), so neither the output name, the awww version nor the wallpaper engine is hardcoded. Config selection is `$KOLIR_MATUGEN_CONFIG` -> `~/.config/matugen/config.toml` -> `<root>/config/matugen/config.toml`; every template input is pre-validated with python3 + tomllib so a missing template cannot produce a partial palette. A missing `~/.cache/current_theme` is created as `dark`. Appearance selection comes from `KOLIR_MATUGEN_TYPE/CONTRAST/MODE` (set by `AppearanceService`) or `~/.cache/quickshell/appearance.json`; the type must be one of matugen's ten `scheme-*` values, contrast is validated to -1..1, and `mode=auto` keeps the last resolved `current_theme` (the shell owns the sunrise/sunset switch), while light/dark also update the resolved theme. It runs Matugen with `--source-color-index 0 --type <type> --contrast <c> --mode <mode>`, skips the lock palette gracefully when `hyprlock.toml` is absent (the lock run keeps `--mode dark` but follows the selected type/contrast), and makes the `hyprctl reload` hook a no-op when no live Hyprland instance exists. The lock background/glow step is skipped when `ffmpeg` is missing; it renders at the geometry reported by `kolir_monitor_geometry` (falling back to 2560x1440 when Hyprland cannot report a size), which keeps the lock image matched to the monitor after the earlier geometry bug.
- **Consumer Updates**:
  - **Quickshell**: `config/quickshell/theme/Colors.qml` watches `ShellPaths.colorsJson` with `FileView`, parses it in `onLoaded`, and maps snake_case keys to camelCase QML properties without restarting the shell.
  - **Foot**: Matugen writes `~/.cache/terminal-sequences`; its `post_hook` tees ANSI color sequences into open pseudo-terminals. New Foot instances read `~/.config/foot/colors.ini`.
  - **Hyprland**: The Matugen `post_hook` runs `hyprctl reload`; `hyprland.lua` loads `~/.config/hypr/colors.lua` with `dofile()` when it exists.
  - **GTK**: Matugen writes `~/.config/gtk-3.0/colors.css` and `~/.config/gtk-4.0/colors.css`; the import stubs `gtk.css` (`@import url("colors.css");`) are created by `kolir setup` because they are user glue, not package files. `toggle-theme.sh` additionally changes the GTK color-scheme/theme and KDE `ColorScheme`.
- **User Glue**: `kolir setup` creates symlinks for `~/.config/hypr/{hyprland.lua,scripts,hyprsunset.conf,hyprlock.conf,hypridle.conf}`, `~/.config/mpv/mpv.conf`, `~/.config/matugen/hyprlock.toml`, and (when the templates path is absent) `~/.config/matugen/templates`; it writes the Foot loader and empty `colors.ini`, copies `matugen/config.toml`, the GTK stubs, `~/.cache/current_theme`, the Quickshell palette snapshot, `user.lua`, and `hyprlock-colors.conf` only when absent, writes the user-level XDG Desktop Portal FileChooser glue (`kolir.portal`, the D-Bus `.service`, and `hyprland-portals.conf` only when absent), backs up anything it replaces, creates `~/Pictures/wallpaper`, refreshes `<root>/.version`, and enables `hypridle.service` and `hyprsunset.service` (unless `--no-systemd`, and skipping a unit whose binary is missing). It also lists the optional packages that are missing and installs them only after an explicit "yes": `--yes` leaves them alone, `--optional` installs unattended via `paru`/`yay` (which also covers the AUR-only `wl-screenrec` and `mocu-xcursor`) or `pacman`, and `--no-optional` skips the question. `~/.zshrc` is opt-in via `--zsh`; Obsidian is opt-in via `--obsidian`/`--obsidian-output` and has no default vault path, and setup prints that the generated snippet still has to be enabled inside Obsidian (`Settings → Appearance → CSS snippets`); `doctor` warns while the configured snippet is missing or disabled.

## 4. Conventions
- **Naming**: QML files and types are `PascalCase`; JavaScript modules are `camelCase`; directories are lowercase except the existing `nightLight/` feature directory; Hyprland shell scripts and `screen-record/` helper modules are `kebab-case`. Preserve IPC targets, layer namespaces, JSON keys, and CLI arguments exactly.
- **Shared Components**: Reusable UI primitives live in `config/quickshell/bar/components/` (`Surface.qml`, `Pill.qml`, `IconButton.qml`, `AppIcon.qml`, `ProgressIndicator.qml`, `VolumeSlider.qml`, `CopyableValue.qml`, `TextField.qml`, `StateLayer.qml`, `EmbeddedSheet.qml`). Prefer these over duplicating surface styling. `CopyableValue` is a read-only `Text` that copies its `value` through `wl-copy` and shows a hover copy glyph that turns into a check; use it for detail strings in settings instead of plain `Text`. Keep the owner's click area off such values: in `EthernetCard` the collapse/expand `MouseArea` covers only the summary row, because a card-wide one renders the values unclickable.
- **Singletons**: Visual tokens live in `config/quickshell/theme/` (`Colors`, `Dimensions`, `Typography`, `Icons`, `Motion`); runtime services and path contracts live in `config/quickshell/services/` (`AppearanceService`, `AudioService`, `BatteryService`, `BluetoothDevicesService`, `BrightnessService`, `CaffeineService`, `CalendarService`, `CaptureHistoryService`, `DeviceBatteryService`, `EventSoundService`, `FrameService`, `HyprsunsetService`, `NotificationService`, `PowerService`, `ShellPaths`, `WallpaperService`). Both directories have their own `qmldir`; import both (`../theme` + `../services`, or the matching `../../` path) when a file needs them.
- **Constants**: `Dimensions` holds repeated geometry and shared metrics; `Typography` holds fonts and type scale; `Icons` holds Material Symbols names; `Motion` holds repeated UI animation roles (`color`, `theme`, `press`, `scale`, `fade`, `move`, `workspace`, `rotate`, `spin`, `popupEnter`, `popupExit`, `listEnter`, `listExit`, `osd`) plus the shared easings (`themeEasing`). Popup-specific sizes, optical offsets, process intervals and thresholds stay as local `readonly` properties. Domain constants (FPS, bitrate, CRF, temperatures, search scores, NOAA coefficients) stay local to their feature. Do not tokenize `0`/`1`, SVG coordinates, mathematical coefficients, accent-dot coordinates, or one-off optical tweaks.
- **Paths**: Every path outside the shell config goes through `ShellPaths` (`chassisType`, `hyprScripts`, `currentTheme`, `colorsJson`, `appearanceState`, `frameState`, `hyprsunsetState`, `deviceBatteryScript`, `deviceBatteryState`, `eventSound`, `usbWatch`, `runtimeDir`, `runtimeStateDir`, `recordingState`, `notificationState`, `calendarState`, `googleCalendarScript`, `googleCalendarState`, `screenshotDir`, `recordingsDir`, `captureHistoryThumbnails`, `capturePreviewDir`, `caffeineState`, `clipboardPreviewDir`, `wallpaperDir`, `wallpaperState`, `palettePreviews`, `palettePreviewsCache`, `cliphistStore`, `cliphistWatch`, `cliphistPreviews`, `pactlSubscribe`, `quickNoteScript`, `completeDirs`, `listFiles`, `searchFiles`, `fileThumbnail`, `filePreviewDir`). Do not build `HOME`-based paths in QML. Shell scripts resolve the installation root through `config/hypr/scripts/lib/root.sh` (`kolir_root`), and Python through `resolve_root()` in `tools/kolir.py`; never hardcode an install path (the root comes from `$KOLIR_ROOT`, the checkout layout or `/usr/share/kolir`). Binds and autostart call `sh ~/.config/hypr/scripts/qs-ipc.sh …` or `sh ~/.config/hypr/scripts/launch-shell.sh`.
- **Root & Setup**: `$KOLIR_ROOT` wins, then the physical checkout/package around the script, then `/usr/share/kolir`. `kolir setup` is idempotent: it never silently overwrites user-owned files (`user.lua`, `matugen/config.toml`, real template directories, `gtk.css` stubs, `~/.zshrc`, generated colors) and backs up every managed path it replaces to `<path>.bak.YYYYmmdd-HHMMSS` (`.1`, `.2` on collision). `--dry-run` writes nothing; re-running a configured machine reports "no changes".
- **Styling**: Use `Colors.<role>` (Material Design 3 tokens) with `Colors.withAlpha(color, opacity)` or `Colors.stateLayer(color, opacity)`. Dimensions belong in `Dimensions.*` (including `Dimensions.progress.*` for progress indicators), fonts/weights in `Typography.*`, and icon ligatures in `Icons.*`. Never hardcode colors. Palette changes crossfade through `Colors.qml` itself (one `Behavior` per color, `Motion.theme` plus `Motion.themeEasing`), so never duplicate that animation in a component: a component-level `Behavior on color` must stay for its own hover/press transitions only. `on*` colors (`onPrimary`, `onSurface`, …) cannot carry `Behavior on onPrimary` (QML reads it as a signal handler), which is why their animated value lives in a private `_on*` property with a public writable alias.
- **Controls vs. Status**: The bar has one visual contract. A filled `Pill` or a hoverable `IconButton` is a control: it opens an embedded sheet/menu or performs an action, and it carries hover/scale/pointer feedback. A `StatusItem` is information drawn flat on the strip: no container, no hover scale, muted `onSurfaceVariant` text, with `error` only for a real warning (low headset, recording). Statuses live in the separated zone left of the control row (`Bar.qml` `statusRow`, hairline `statusDivider`), never inside the control row, and `Clock` is flat for the same reason; only its date carries a hover state layer and opens `CalendarPopup` (the embedded calendar sheet), while the time and keyboard layout stay inert. Statuses never open a sheet. A status may carry a direct action that matches its value: `RecordingStatus` stops the recording on click; that action never turns it into a pill or a menu. Bluetooth devices are the exception on the other side of the contract: `BluetoothChip` is a control capsule because clicking it opens Settings → Bluetooth, while the charge it shows is information. It deliberately sits in the status zone next to `CaffeineIndicator`, because a device readout belongs with the session statuses rather than the brightness/volume cluster. `CaffeineIndicator` turns keep-awake off on click: it holds for a beat with a diagonal strike over its glyph and an `Off` label, then dims, sinks and leaves the strip, so the status explains the state change instead of vanishing under the pointer. Its switch, presets and re-enabling live in Settings.
- **Hover State Layers**: A hover/selected tint is a state layer over the container, so `bar/components/StateLayer.qml` paints it as its own fill and fades its `opacity`, instead of animating `color` between the base and `Colors.stateLayer(...)`. `ColorAnimation` interpolates the alpha channel too, so an opaque `surfaceContainerHigh` turning into a 12–16 % state layer passes through a bright, still-opaque grey — the control visibly flashes once on hover-in and once on hover-out. `StateLayer` fills the parent (inheriting its `radius`) and takes `shown`, `tint`, `strength` and `duration`; settings rows (`strength: 0.14`), caffeine chips, the add-device and scan buttons, temperature presets, schedule mode chips, codec chips and the mute button all use it. Put the layer after the container's own colour/border and before the content so the label stays on top.
- **Frame Geometry**: `Dimensions.frame.thickness` is the ring width and, in the `ring` style, the Hyprland `general.gaps_out` value (`4`); the `corners` style uses `gaps_out = 0` and hides every strip. `FrameService` persists which one is active in `~/.cache/quickshell/frame.json`; `hyprland.lua` reads that file for its default `gaps_out`, and `Frame.qml` re-applies the value at runtime with `hyprctl eval` when the selected mode changes. `Dimensions.frame.radius` equals `decoration.rounding + border_size` (`28 + 2 = 30`) in both styles. The frame path starts at `Dimensions.bar.height` because `Bar.qml` paints the 30px bar strip above it; the top corner spandrels reuse the bar fill so the bar and the top corners are one surface. Keep these in sync when changing gaps, rounding, or border size.
- **IPC Handlers**: Modules expose actions via `IpcHandler { target: "<name>" }`. Current targets: `launcher`, `brightness`, `volume`, `battery` (`toggle`, `open`, `close`, `status`), `settings`, `nowPlaying`, `recording`, `recordingSetup`, `hyprsunset`, `nightLight`, `caffeine`, `appearance` (`setType`, `setContrast`, `setMode`, `setCrossfade`, `regenerate`, `status`), `frame` (`setStyle ring|corners`, `toggle`, `status`), `bluetoothDevices` (`status`), `shortcuts` (`toggle`, `open`, `close`), `calendar` (`toggle`, `open`, `close`, `eventAdd <yyyymmdd> <title> <allDay> <start> <end>`, `eventRemove <uid>`, `eventList <yyyymmdd>`, `sync`, `status`), `notifications` (`toggle`, `open`, `close`, `clear`, `setDnd <bool>`), `power` (`toggle`, `open`, `close`, `lock`, `suspend`, `logout`, `reboot`, `poweroff`, `status`), `captureHistory` (`toggle`, `open`, `close`, `refresh`), `screenshot` (`open <path>`, `close`, `toggle`), `wallpaper` (`toggle`, `open`, `close`, `random`, `openDir`, `up`, `home`, `editPath`, `setBackend <awww|mpvpaper>`, `backendStatus`, `status`), and `filePicker` (`open <json>`, `cancel <id>`, `accept`, `toggleIndex <n>`, `search <query>`, `closeSearch`, `newFolder <name>`, `showHidden <true|false>`, `status`). `bluetoothDevices` lives in `BluetoothDevicesService.qml`, `notifications` lives in `NotificationCenter.qml`, `captureHistory` in `CaptureHistory.qml` and `screenshot` in `ScreenshotOverlay.qml`; `wallpaper` and `filePicker` both live in `FilePicker.qml`, and `wallpaper` must stay that target's only handler (Quickshell keeps the first registration and warns for a second, which is why the removed separate `WallpaperPicker` warned on every reload). Keep their names and arguments stable so the hotkey, the portal backend and the documented test commands stay valid. Trigger them with `qs -p <config_dir> ipc call <target> <method> [args]`.
- **Layer Namespaces**: `frame`, `bar`, `workspace-wash`, `launcher`, `notifications`, `volume-osd`, `brightness-osd`, `recording-setup`, `shortcuts`, `filepicker`, `capture-history`, and `screenshot`. `hyprland.lua` adds blur rules for `launcher`, `recording-setup`, `shortcuts`, `filepicker` and the live `notifications` cards, and `no_anim` rules (`notifications-no-anim`, `screenshot-no-anim`) for `notifications` (the stack animates its own card exit and layer height; a compositor fade stretches the previous card buffer into a ghost band) and `screenshot` (a layer fade would reveal the live screen and delay the frozen frame); `notifications-no-anim` carries `blur = true` + `ignore_alpha = 0` together with `no_anim`, so the same rule frosts the cards and quietens the layer. `frame` is a Bottom-layer decorative surface and needs no blur rule, `bar` must not have one (its strip and the settings sheet are opaque, and Hyprland's blur eats the layer's painted edge, which let the blurred wallpaper show through the sheet's shoulder), `workspace-wash` is a small opaque click-through Top-layer surface over the workspaces pill that also needs no blur, and `capture-history` is an opaque full-screen panel that needs no blur rule either. `filepicker` keeps its blur on the translucent panel itself (0.80 `surfaceContainerLow`); the full-screen layer stays transparent outside the panel, so the desktop around the picker is neither blurred nor dimmed. Both portal requests and the wallpaper grid share that panel. `OsdPanel` receives its namespace from the wrapper (`volume-osd` / `brightness-osd`).
- **Bar vs. Panels**:
  1. For a top-bar widget, add `<Widget>.qml` under `config/quickshell/bar/components/` and instantiate it in `Bar.qml`.
  2. For a standalone overlay, add a component under its own `config/quickshell/<name>/` directory and instantiate it in `ShellRoot` (`shell.qml`); give it a `WlrLayershell.namespace` and add layer rules in `hyprland.lua` when blur/anim is needed. The shortcut sheet, the file/wallpaper picker and the capture history follow this pattern with a full-screen Overlay surface and `WlrKeyboardFocus.Exclusive`, so keys reach the panel and an outside click can dismiss it. The screenshot overlay is the deliberate exception: a Top-layer full-screen still with an empty mask and `WlrKeyboardFocus.None`, because slurp owns the pointer and Escape above it.
  3. Settings belongs inside `SettingsMenu.qml` because the popout is drawn in the bar surface: add a `MainPage.entries` item, a page component, and a height in `heightForPage()`. All embedded sheets derive from `bar/components/EmbeddedSheet.qml`, which owns the modal scrim, the pour-shaped panel (mirrored for the right-hand sheets), the corner reveal on `Motion.sheetEnter`/`sheetExit` and the dismissal layer, so they cannot drift apart; a sheet keeps only its content and its `open()`/`close()` side effects and drives the motion through `revealOpen()`/`revealClose()`, with `didClose` for state resets and `dismissalRequested` for outside clicks. Keep that height at least as tall as the page's resting content (mirror its `implicitHeight`), otherwise the page opens with a sliver of scroll: the Internet page carries a `Flickable` for the expanded Ethernet details and the connection form, but its resting body (Ethernet, Wi-Fi, actions, 220 px network list) must fit exactly, so `internetHeight` and `InternetPage.implicitHeight` are both `546`; `mainHeight` and `MainPage.implicitHeight` are both `460` (the four entries — Bluetooth, Internet, Appearance and Calendar — plus the Keep Awake card); `calendarHeight` is `630` and `CalendarPage.implicitHeight` is derived from its cards (629 at the current copy: the account card, the always-visible OAuth client card and the read/add help card), so connecting or disconnecting never resizes the sheet; `appearanceHeight` and `AppearancePage.implicitHeight` are both `1016`, which fits the palette, scheme, contrast and mode cards plus the Screen frame preview card without dead space. The bar expands its input mask and enables `WlrKeyboardFocus.OnDemand` while settings is open. Page navigation inside the settings sheet is a shared-axis slide (`pageProgress`/`incomingPage`/`pageDirection` plus `Motion.pageForward`/`pageBack`), so reverse navigation runs the same transition backwards. `BrightnessPopup.qml`, `VolumePopup.qml`, `BatteryPopup.qml`, `NotificationCenter.qml`, `PowerPopup.qml`, `CalendarPopup.qml` and `TrayMenu.qml` follow the same embedded pattern for the night-light, sound, battery, notification, power, calendar and tray-menu sheets; the first five are mirrored to the right screen edge, while `CalendarPopup` and `TrayMenu` use the floating mode: the same surface revealed as a symmetric tab under a bar widget, with the edge sheets' shoulder fillet on both sides, rounded bottom corners and no pour. `CalendarPopup` centers on the date's `anchorCenterX`; `TrayMenu` centers its root card on the clicked tray icon (the panel's right shoulder extends `panelFlare` past the card) and grows left with each submenu column. All edge sheets are flush with the physical screen edge on their anchor side (settings left, the other five right), so while one is open its opaque body covers the decorative frame ring and the compositor's active-window border instead of outlining the panel with a foreign colour; `Bar.qml` keeps the sheets mutually exclusive and shares the modal mask/`OnDemand` focus condition between them.
  4. The system-tray menu is not a `PopupWindow`: `TrayMenu` is a floating `EmbeddedSheet` inside the bar surface (no layer namespace), with `mirror` off and `anchorCenterX` derived from the clicked icon's center. It shares the bar mask, `OnDemand` focus and the shared dismissal layer; submenus are columns, not separate windows. A future popup that genuinely needs its own focus grab (a client-owned xdg_popup) still uses `PopupWindow` + `HyprlandFocusGrab`.
  5. The decorative screen frame belongs in `bar/Frame.qml` on `WlrLayer.Bottom` with an empty `mask`; keep it below windows and click-through. Do not move it into the top-layer `Bar` surface, or the window border is clipped at the rounded cut-out.
- **Recording Helpers**: `screen-record.sh` stays the lifecycle/CLI owner. `lib/monitors.sh` owns shared monitor selection (`KOLIR_MONITOR`, focused, first), `screen-record/audio.sh` owns PipeWire/Pulse helpers, `encoders.sh` owns encoder/quality selection, and `screen-record/monitors.sh` owns Hyprland geometry/FPS helpers. Source them from `SCRIPT_DIR`; do not hardcode repo or home paths. The capture helpers follow the same split: `screenshot-region.sh` owns the frozen-frame flow and the saved copy, `scripts/capture-history.sh` owns the listing and the poster cache, and `CaptureHistoryService`/`CaptureHistory.qml` only orchestrate them.
- **Commits**: Run `git commit`, `git commit --amend` or `git rebase` only when the user explicitly asks for that action in the current request; finishing an edit, a fix or a subagent's work is not an instruction to commit. Otherwise leave every change in the working tree (including untracked files) for review.

  - Now Playing: with a YouTube live stream open in Zen, `busctl --user call <bus> /org/mpris/MediaPlayer2 org.mpris.MediaPlayer2.Player Play|Pause` must flip the island glyph (play on pause, pause on play) even though Zen keeps `PlaybackStatus=Playing`; a left click on the compact capsule must send the same call (the island expands on hover, so the click lands on the capsule strip of the already-expanded card and must toggle playback instead of opening it), while the compact play button, the wheel skip and the compact seek strip keep their own actions. - **Quickshell**: Version 0.3.2. Uses `Quickshell.Io` (`Process`, `FileView`, `SplitParser`, `StdioCollector`, `IpcHandler`), `Quickshell.Wayland` (`WlrLayershell`), `Quickshell.Hyprland`, `Quickshell.Services.Notifications`, `Quickshell.Services.Mpris`, `Quickshell.Services.SystemTray`, and `Quickshell.Bluetooth`.

Missing required tools are errors; missing optional tools are warnings. Phase 1 installs nothing.
- **Known Quirks & Pitfalls**:
  - **Monitor Selection**: Wallpaper/color scripts and the recorder share `config/hypr/scripts/lib/monitors.sh`; set `KOLIR_MONITOR=<output>` to override detection (`hyprctl monitors -j` focused, then first). Only `kolir_monitor_name` falls back to `DP-1` when Hyprland cannot be queried, so the author's machine keeps working without configuration while other ports are detected. Keep new scripts on this helper instead of hardcoding an output name.
  - **awww Cache Layout**: `lib/awww.sh` never assumes an awww version directory. It asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first, accepts the NUL-separated 0.12.x encoding and the older one-piece encoding, and only returns paths that exist. Tested against awww 0.12.1; older/newer releases still work as long as `awww query -j` or one of those cache encodings is available, otherwise the script prints the version, path, and entries it found and exits 1.
  - **Matugen entries**: The tracked `config/matugen/config.toml` now defines `foot`, `foot-live`, `hyprland`, `quickshell`, `gtk3`, and `gtk4`. Obsidian is template-only (`templates/obsidian.css`) and gets a `[templates.obsidian]` block only when the user enables it; there is no default vault. `zen` entries remain a local customization outside the repo. `kolir setup` copies the tracked config only when `~/.config/matugen/config.toml` is absent, links missing templates into a real local templates directory, and replaces a config symlink with a local copy (with a backup) before adding the Obsidian block, so a checkout is never modified through a link.
  - **Setup gating**: setup refuses to run as root, writes nothing under `--dry-run`, and reports "no changes" on a configured machine. It never overwrites `user.lua`, an existing matugen config, real template files, existing `gtk.css`, or `~/.zshrc` (the latter is opt-in with `--zsh`); managed replacements are backed up to `<path>.bak.YYYYmmdd-HHMMSS`. A change of `<root>` requires a setup rerun because the symlinks and the Foot loader contain absolute paths.
  - **Auto-reload**: `setup --auto-reload` renders the units directly into `~/.config/systemd/user/` (watching `.version` and the git ref, running `python3 <root>/tools/kolir.py reload` in a checkout or `/usr/bin/kolir reload` in a package), verifies them with `systemd-analyze --user verify`, and enables `kolir-reload.path`; `--no-systemd` writes the units but skips systemctl. Because a systemd user unit may not inherit `WAYLAND_DISPLAY`, `reload` warns and skips the shell restart when the graphical environment is absent instead of failing.
  - **Lua Configuration**: Hyprland uses the modern Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.layer_rule`), not traditional `hyprland.conf` directives.
  - **Dispatch from QML**: `Hyprland.dispatch()` forwards its argument to `hyprctl dispatch`, which in Lua-config mode wraps it as `hl.dispatch(<argument>)` and parses it as Lua. Legacy dispatcher strings such as `workspace 3` fail with `')' expected near '3'`, so `bar/components/Workspaces.qml` clicks send `hl.dsp.focus({ workspace = <id> })`. Any new dispatch call must use the Lua `hl.dsp.*` form as well.
  - **Hybrid Brightness**: `services/BrightnessService.qml` is now the only writer for both backends. It probes the internal panel with `brightnessctl -m -c backlight` and the external display with `ddcutil getvcp 10 --brief` at startup and every 30 seconds; `available` is true when either backend answers, and the chip/OSD show the external display when DDC/CI works (desktops, monitor buttons stay authoritative) or the internal panel otherwise (laptops whose eDP panel rejects DDC/CI). `adjust()` moves every available backend by its own 5% step, which preserves the old hybrid behaviour where a laptop changed its panel and a docked DDC monitor together; `setValue()` applies one absolute percentage to every backend. Writes are coalesced through a pending raw value and one `Process`, so a held brightness key cannot spawn one process per repeat. The internal write is `brightnessctl -q -n2 set <raw>` and the displayed percentage is `raw / max`, while `brightness.sh` keeps its old `-e4` curve only for the no-shell fallback. A laptop DDC/CI probe failure is expected and silent; a backend that was working and then fails (for example a monitor powered off) is dropped from `available` with a `console.warn`, and the poll speeds up to 5 seconds while no backend answers so the chip and the panel fallback return quickly.
  - **Chip Header Morph**: the night-light and sound sheets have no title block of their own — the chip that opens them *becomes* the header, so the bar and the sheet read as one surface instead of a small pill above a separate `PopupHeader`. `bar/components/HeaderPill.qml` is the shared primitive (a `Pill` with the morph, the header text and the progress line); `Brightness` and `Volume` derive from it and only supply their icon, level, wheel step (`adjust`), header icon/title/status. `Bar.qml` binds each chip to its sheet (`headerReveal: <sheet>.reveal`, `barX: rightRow.x + <chip>.x`, `headerX: <sheet>.panelLeft`, `headerWidth: <sheet>.popupWidth`, `headerInset: <sheet>.contentLeftInset`), and `EmbeddedSheet` exposes `panelLeft` (`mirror ? width - popupWidth : 0`) as the body edge on the physical screen edge. The stretched band is a child of the chip that starts as the exact chip rect (same fill, height, radius and border) and interpolates on `stretch = min(1, reveal * 1.35)` — the same width-first curve as the sheet, so the header reaches the panel edge as the body drops. It stays a capsule the whole way: both caps keep `height / 2`, at full stretch it is `popupWidth` wide and its right cap is tangent to the physical screen edge, and it grows from `Dimensions.control.height` to the full 30 px strip so it is flush with the sheet's top edge.   - **Text Field Cursor**: Qt Quick's `TextInput` never sets a cursor shape of its own (it only paints the caret), so a field keeps the arrow while every button around it shows a pointing hand. Each text input therefore carries `HoverHandler { cursorShape: Qt.IBeamCursor }` inside it: the shared `TextField` and `PasswordField`, plus the launcher search, the shortcut filter, the Wi-Fi SSID field and the file picker's path/search/new-folder inputs. Use the handler rather than a covering `MouseArea`: a handler takes no part in press delivery, so click, drag selection and Return still reach the input.
  - **Closed Sheet Input**: `EmbeddedSheet` gates every sheet root with `visible: modal` (`opened || reveal > 0.001`). Without it a closed sheet silently kills the pointing-hand cursor in the *settings* sheet: Qt's cursor lookup (`QQuickWindowPrivate::findCursorItemAndHandler`) returns the first item that owns a cursor and only skips children whose effective `visible`/`enabled`/`culled` flags say no — hover delivery takes a different path — so the hidden sheet's full-window dismissal `MouseArea` (every `MouseArea` owns an arrow cursor) won the lookup and the rows kept the default arrow while still highlighting. The two symptoms looked unrelated but share this one cause, so when hover reacts and the cursor does not, check which sheet is still in the tree instead of the item you hover.
  - **Internet Details**: `EthernetCard` and `WifiCard` are the only expanded cards on the Internet page, and both render their values through `CopyableValue` (click copies, hover shows the glyph), so their expand `MouseArea` must not span the values: Ethernet keeps it on the summary row, and `WifiCard` additionally ends it `wifiToggle.width + spacing` short of the right edge so the radio switch stays clickable. `NetworkController` starts `wifiDetailProc` only while connected (`activeWifi` and a device are set) and clears the whole block plus `wifiDetailsExpanded` on disconnect; the address block comes from `nmcli -t device show <wifiDev>` (`parseDeviceDetails`, shared with Ethernet), while SSID/BSSID/security/signal/channel/rate come from the scanned row marked `IN-USE` and `channelLabel` folds `CHAN` + `FREQ` into `36 · 5.18 GHz`. That is why a fresh connection shows the profile name in the summary for a moment before the SSID replaces it. Turning the radio on reads the cached list immediately and then queues a real scan (`--rescan yes`): NetworkManager refuses a scan within 10 s of the previous one and starts its own when the radio comes up, so the first attempt waits `enableScanDelay` (2 s) and a `Scanning not allowed immediately following previous scan` answer retries `enableScanAttempts` times every `enableScanRetryDelay` (2.5 s). `scanning` stays on for the whole chain, so the Refresh button reads `Scanning…` with the spinning glyph from the moment the switch moves until the fresh list lands. Turning Wi-Fi off, leaving the page and a completed rescan cancel that chain; only a rescan clears the counter (`scanProc.rescan`), so a cached poll read that finishes first cannot swallow the pending real scan.
  - **Sound Sheet Height**: `VolumePopup.qml` sizes itself to `SoundControls.contentHeight` plus `contentTopMargin` (the shoulder inset plus `contentTopGap`), the column's bottom margin and a bottom reserve (clamped to the screen), so every card, codec chip row and device list fits without outer scrolling and keeps the same bottom gap as the night-light sheet. There is no title block — the volume chip stretches into the sheet's header (see Chip Header Morph) — so the cards start right under the shoulder. The reveal starts immediately; if the async audio model changes the content after it (a codec row or device arriving), `panelHeight` fades to the new height instead of jumping. Keep those tokens in sync with `panelHeight`. The fixed-height device lists still scroll internally when there are more devices than fit their 84px viewport.
  - **MPRIS Workaround**: `MprisController.qml` sends raw `busctl` Play/Pause and `SetPosition` calls because some players (Firefox/Zen) report stale `PlaybackStatus`, which breaks Quickshell's `togglePlaying()`, and not every player implements seeking through Quickshell. Real playback evidence is `playbackState == Playing && rate > 0`: Firefox/Zen keep `PlaybackStatus` "Playing" after a pause but flip `Rate` to 0, and the optimistic toggle is only a fallback for players that report neither. `Rate` defaults to 1 when omitted, so a player without MPRIS `Rate` support is unaffected. Quickshell normalizes `player.position`/`player.length` to seconds while the raw `mpris:length` metadata stays in microseconds: divide only the metadata length (`rawLength / 1e6`) and compare it with `player.position`, or the progress ratio collapses to ~0 and the bar's progress line never appears. A confirmed broadcast has two independent markers. The sentinel marker is an `mpris:length` near `INT64_MAX` (Twitch in Zen reports `9223372036854000000` µs, which Quickshell normalizes to `9223372036854` s): `rawMetadataLength >= 9.0e15` µs, or `lengthSupported && player.length >= 9.0e12` s, after 2 s of real playback. The frozen-position marker covers a YouTube live that Zen exposes like an ordinary track with no usable duration: the raw MPRIS `Position` (queried once a second with `busctl --user get-property <bus> /org/mpris/MediaPlayer2 org.mpris.MediaPlayer2.Player Position`; Quickshell's `player.position` is extrapolated as last sample + elapsed × rate, so it cannot be used) stays within 1 s of its anchor for 10 s while `Playing` and `rate > 0`. `frozenLive` records which marker raised the badge; the sentinel path is never cleared by the frozen path. The anchor is kept while the badge is visible, so a raw move of >=1 s clears `live`/`frozenLive` immediately; before latching, the same movement restarts the 10 s window. The probe runs only while the current track has no usable duration. A missing length is still not evidence: Zen also drops `mpris:length` for ordinary YouTube videos, and `player.length` mirrors `position` when `lengthSupported` is false. `hasLength` uses `rawLength` or `lengthSupported && player.length`, but a web duration above 12 h (YouTube's upload cap) is an uptime, not a length (Lofi Girl reports ~14 h); the filter also applies while `xesam:url` is still empty, while local `file://` media keeps its real duration. `sawLengthForTrack` is set only when the current track actually reports a usable duration and resets on track change, so the frozen marker cannot fire in the metadata gap after a pre-roll ad; cached lengths are deliberately not used for it because an ad length can be cached under the content URL. `stickyLength` keeps the last real duration for the current track, and `knownLengths` caches a seen duration by `xesam:url` for the shell session, so switching tabs or players (or a later gap) cannot reclassify the same media; a paused player that re-reports a duration also clears a stale live flag when the remaining time is meaningful (`position > 0 && length - position > 30 s`), while a paused broadcast at position 0 or at the live edge keeps it. The flag is otherwise kept for the rest of the track and the island hides the scrubber/times in favor of a red `LIVE` badge whose dot dims while paused (the compact pill shows the same badge). An unknown length alone is not live: until the length arrives (or a cached one is restored) the expanded card leaves the bottom row empty instead of showing a false `LIVE`. A real length that stays present during playback clears the flag (late-metadata players). Seeking is disabled for live tracks. The capsule is itself a transport: a left click on the compact pill, and on the bar-strip part of the expanded card (where the pointer already sits after hover opened it), calls the same toggle, so hover and the `media` IPC own expansion. Known limitation: a markerless broadcast whose raw `Position` advances, or whose uptime is under 12 h and therefore looks like a real duration, is deliberately shown as an unknown-length track instead of LIVE; the same applies after a shell restart before the frozen window completes. This is the cost of never showing a false LIVE.
  - **Clipboard Watchers**: `ClipboardController.qml` starts one `wl-paste --watch` per MIME type through `scripts/cliphist-watch.sh` in a root `Scope`, so capture continues while the launcher is closed. Quickshell does not terminate `Quickshell.Io` children when it is killed; the wrapper terminates the identical watcher left behind by the previous shell (exact argv match in `/proc`) and only then execs `wl-paste`, so exactly one pair survives any number of restarts or QML reloads. Do not replace the wrapper with a plain `wl-paste` command, and do not move the controller back into `PanelWindow`.
  - **Audio Subscriber**: `AudioService.qml` starts its `pactl subscribe` listener through `scripts/pactl-subscribe.sh` for the same reason: the old listener survives a shell restart, and every restart used to add one more connected client to `pipewire-pulse`. That leak is what exhausts the server's client slots (`too many client application connections: Connection refused` in the user journal); `pactl` then exits 1 with empty stdout, which used to clear the device model and log `failed to parse` warnings. Keep the wrapper (exact argv `pactl subscribe` match, so one-shot `pactl list/get/set` calls are never touched) and do not run a second shell instance that also imports `AudioService`.
  - **Wallpaper Ownership**: `awww` owns still images and `mpvpaper` owns videos; `config/hypr/hyprland.lua` sets `misc.disable_hyprland_logo = true`, because Hyprland otherwise paints its own built-in logo/anime background (`/usr/share/hypr/wall*.png`, `misc:disable_hyprland_logo` defaults to `false`) whenever no client covers the desktop: that is what a fresh machine shows until the first `awww img`, and it flashes through at every login until the daemon restores its cache. With the logo off, the desktop shows the chosen awww image or mpvpaper video (or a plain background until one is picked). `force_default_wallpaper` keeps its default and no longer matters once the logo is disabled. `kolir setup` never sets a wallpaper: it creates an empty `~/Pictures/wallpaper`, and `kolir doctor` notes the empty folder instead of failing it. Verify with `hyprctl getoption misc:disable_hyprland_logo` (`bool: true`), `hyprctl configerrors` (empty), `hyprctl layers` (a background layer for the active engine) and `kolir doctor` (`desktop background: awww/mpvpaper layers`).
  - **Video Wallpapers**: `set-wallpaper.sh` picks the engine from the extension; `wallpaper-backend.sh` switches without a file and is idempotent. mpvpaper has no stop command, so `lib/mpvpaper.sh` owns one process per output through `$XDG_RUNTIME_DIR/kolir/mpvpaper.pid` and validates the live argv before signalling it (a recycled pid is never killed). It runs `mpvpaper -o 'no-audio loop hwdec=auto-safe panscan=1.0' <monitor> <video>` with stdin from `/dev/null`, stdout/stderr in `~/.cache/kolir/mpvpaper.log`, and waits 0.4 s so a rejected output/file is reported instead of saved. The video is a background layer above awww, so stopping mpvpaper reveals the last image again; do not `awww clear` when a video starts, the image is the fallback. `set-wallpaper.sh` writes the state only after the player is alive. `WallpaperService` is a reader, not a writer: it reloads the JSON on every change, rolls an optimistic chip switch back when the script fails, and replays the last video 900 ms after the first load (the script no-ops when the same process is already playing, so a shell restart does not flicker the video). A successful user switch then runs `generate-colors.sh` (a restore deliberately does not), so the palette follows the newly active file instead of keeping the other engine's colors. The shell must not start a second mpvpaper for the same file/output: `kolir_mpvpaper_is_running` compares the `/proc` argv. Video playback has no audio and is not paused for fullscreen windows.
  - **File Picker / Wallpaper Mode**: `FilePicker` is the shell's only grid: portal requests and the wallpaper hotkey share one full-screen Overlay `PanelWindow` on the `filepicker` namespace with `WlrKeyboardFocus.Exclusive`. `wallpaperMode` is `mode === "wallpaper"`; it sets `filters = []`, hides the filter/folder/save bars and the accept/cancel pills, and applies a selection through `set-wallpaper.sh` + `generate-colors.sh` instead of writing a `resultPath`. `matchesFilter` delegates to `matchesWallpaper`, which keeps directories and only the active engine's extension set (the exact sets random-wallpaper.sh and lib/wallpaper.sh use), so the engine chips, search hits and the footer count always agree. The browsed folder is kept in `wallpaperDir` (initialised to `ShellPaths.wallpaperDir`) for the shell's lifetime; `home` returns there, and `openWallpaperPanel` resets `showHidden` to false. `openWallpaperPanel` cancels a pending portal request with `{"cancelled":true}` before switching modes, and a portal request replaces the wallpaper grid; `cancel()` only writes a result in portal modes. `WallpaperService.backendChanged` re-filters the listing (and reruns a live search), so Images/Videos swap without a rescan. The grid uses the shared lazy `file-thumbnail.sh` posters (one at a time, only visible tiles) into `~/.cache/quickshell/file-previews`, so a large wallpaper library is not pre-encoded. The grid is 5 columns; the layer keeps the `filepicker-blur` rule, and every tile decodes its poster at the tile's physical width (× `Screen.devicePixelRatio`, never the full 480px preview), so scrolling stays cheap. Wheel `angleDelta` is applied proportionally (120 units = 0.7 row), with `pixelDelta` only as a fallback. Search is the portal search (`search-files.sh`, 400-record cap, hidden pruning from the footer checkbox), streamed and filtered by `matchesWallpaper`; a search hit in a subfolder applies directly, and a folder hit exits search and navigates. Escape closes the inline row, then clears the query, then exits search, then closes; outside clicks close without applying. The old `wallpaper` namespace and `wallpaper-thumbnails.sh` worker are gone; the `~/.cache/quickshell/wallpaper-previews` directory is orphaned and can be deleted.
  - **Wallpaper IPC Owner**: `FilePicker.qml` is the only `IpcHandler` for the `wallpaper` target and must stay so: Quickshell keeps the first registration and logs `Handler was registered but will not be used because another handler is registered for target wallpaper` for a second, which the removed separate `WallpaperPicker` triggered on every reload. Add wallpaper methods to that handler instead of a second component; `filePicker` and `wallpaper` sharing one `Scope` is intentional.
  - **Deferred Service Split**: `hyprsunset/Schedule.js` and `hyprsunset/StateStore.qml` are planned but not created; `HyprsunsetService.qml` still owns schedule helpers and persistence inline, so do not assume those files exist. `audio/AudioParser.js` and `hyprsunset/Solar.js` do exist (steps 85/84) and must stay stateless: every input (parsed JSON, device kind, calendar date, coordinates, `locationAvailable`) arrives as a parameter, and `AudioService.parseDevices/parseCards` keep the JSON guards, `null` returns and `failed to parse` diagnostics in QML.
  - **Pure JS Testability**: All `.js` libraries start with `.pragma library` and are loaded through QML imports (`import "audio/AudioParser.js" as AudioParser`, `import "hyprsunset/Solar.js" as Solar`, `import "ShortcutParser.js" as ShortcutParser`). Do not add `require`, QML types, timers, service properties or `console.warn` to them; the services/panels wrap them instead. To compare changes under node, strip only the `.pragma` line in a `/tmp/opencode/` wrapper (never the repo file) and expose the functions via `module.exports`.
  - **Zen Opacity Rule**: `hyprland.lua` defines the named rule `zen-opacity` (`hl.window_rule({ name = "zen-opacity", match = { class = "^(zen|zen-alpha|zen-browser)$" }, opacity = "0.95 0.7" })`), so Zen windows get 0.95 opacity when focused and 0.7 when not. It must stay a call: an earlier version assigned the table (`hl.window_rule = { ... }`), which registered nothing and replaced the API function with a table for the rest of the config, including `user.lua`. Verify after edits with `hyprctl configerrors` (empty), `hyprctl eval 'error("TYPE=" .. type(hl.window_rule))'` (`function`, not `table`) and `hyprctl getprop class:zen opacity` (`0.95`). Window rules have no positive `blur` effect (only `no_blur`), so blur is not set per window; `hyprctl keyword` and `setprop` are rejected in Lua-config mode, but `getprop` and `eval` work.
  - **GTK4 Blur**: GTK 4.24 (and newer) creates an `ext_background_effect_surface_v1` on every window and sends an empty blur region, which Hyprland 0.56+ reads as "the client manages its own effects" and therefore skips `decoration:blur` for the whole surface. The result is a translucent inactive GTK4 window (Nautilus, Loupe, GNOME apps) with the wallpaper sharp behind it. `hyprland.lua` sets `hl.env("GDK_WAYLAND_DISABLE", "ext_background_effect_manager_v1")` so GDK never binds the protocol and the compositor's opacity-driven blur comes back. GTK only reads it at process start, so existing GTK4 windows must be restarted (`nautilus -q`); applications started through systemd/dbus need the variable in the user manager (`systemctl --user set-environment …` plus `dbus-update-activation-environment --systemd …`). Verify with `GDK_WAYLAND_DISABLE=help gtk4-query-settings` (the interface is listed as a supported value) and visually behind an inactive GTK4 window. Do not "fix" this with `window { backdrop-filter: blur(...) }` in the GTK theme: it only covers clients that read `~/.config/gtk-4.0/gtk.css` and the file is user-owned.
  - **Launcher on lone SUPER**: `hyprland.lua` binds `SUPER + SUPER_L` (plus the `SUPER_R` twin) with `{ release = true }` to the launcher command, so tapping Super alone toggles the launcher and tapping it again closes it (`SUPER+D` opens the shortcut sheet instead). `release = true` is load-bearing: Hyprland then fires the bind only on the Super release and shadows it when any other key, scroll or mouse button was used while Super was held, which is what keeps `SUPER+Space` (layout switch), `SUPER+1…0` and `SUPER+scroll` (workspaces), `SUPER+drag` and app shortcuts from opening it. A plain bind fires on the Super press and therefore on every SUPER combo. The trigger must be the sided keysyms `SUPER_L`/`SUPER_R` (a modifier mask alone is not a trigger, and `Super_R` does not match a `SUPER_L` bind). Verify after edits with `hyprctl binds` (`key` `SUPER_L`, `release: true`, `modmask` 64) and by tapping Super vs SUPER+Space/SUPER+1/SUPER+scroll and checking `hyprctl layers` for the `launcher` namespace.
  - **Shortcut Sheet**: `SUPER+D` opens the Quickshell cheat sheet, which parses `hyprctl binds -j` (`ShortcutParser.js`) into modifier sections. Under the Lua config, Hyprland reports `dispatcher` and `arg` but the `arg` is an internal index, not the command, so `exec_cmd` rows are only readable through the bind's `description`: every bind in `hyprland.lua` sets one, and `user.lua.example` documents the option. Rows without a description fall back to a generic dispatcher name, which is why new personal binds should carry `{ description = "…" }`. The parser maps modifier bits and gestures (`mouse:272`, `mouse_down`, `XF86*`, lid switch) to readable labels, sorts rows 1…9/0, then letters, then named keys, collapses the two lone-Super binds into one row, and hides `catch_all` binds. Escape, the close button, an outside click and the IPC `close` method all dismiss it; the list is rebuilt on every open and filtered as you type.

  - **Portal File Picker**: `config/quickshell/scripts/portal-filechooser.py` is the only writer of the portal answer; `setup_portal()` in `tools/kolir.py` owns `~/.local/share/xdg-desktop-portal/portals/kolir.portal`, the D-Bus `.service` and (when absent) `~/.config/xdg-desktop-portal/hyprland-portals.conf`. The backend must answer `OpenFile`/`SaveFile`/`SaveFiles` **asynchronously** (`dbus.service.method(..., async_callbacks=("reply", "error"))`): a synchronous `OpenFile` deadlocks the portal's `Request.Close`, which the portal calls while holding the request lock and waiting for `Close` before it can process the `OpenFile` return. The shell's `{"cancelled":true}` result is response `1`, not `0` with empty URIs (Qt treats `0` as accept and returns an empty path). The portal unexports a request when the app calls `Request.Close` and deliberately emits **no** `Response`; tests must not wait for one after `Close`. `GTK_USE_PORTAL=1` covers GTK and Firefox; Qt needs `QT_QPA_PLATFORMTHEME=xdgdesktopportal` (both set in `hyprland.lua`). Qt queries the portal's `FileChooser.version` asynchronously, so a dialog opened in the first milliseconds may still fall back to the native Qt dialog; `xdg-desktop-portal.service` reads `hyprland-portals.conf` only at startup, so restart it after `kolir setup` (setup calls `busctl ReloadConfig` for the D-Bus service file and prints the restart note). If the shell is down, the backend answers `1` and tries `notify-send`; that notification only appears while a notification daemon is running.
