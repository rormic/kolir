# AGENTS.md — Desktop Environment Reference

## 1. Overview
`kolir` is an Arch Linux desktop configuration for a Wayland session built on Hyprland (configured with Lua) and a custom Quickshell (QML) shell. The shell is Material Design 3–inspired: the bar is a full-screen top-layer surface that paints the bar strip and hosts an embedded settings popout, while a separate bottom-layer frame surface fills the window gaps and frames the desktop below windows. The shell also owns a separate sound popup and a full-screen wallpaper grid. Matugen extracts a neutral Material 3 palette from the current wallpaper and reactively updates Hyprland, Foot, GTK, and Quickshell colors. Machine-specific Hyprland settings live in `~/.config/hypr/user.lua`; `kolir setup` (from `tools/kolir.py`) deploys the symlinks and per-user glue once, and later updates are just a `git pull`. Packaging is phase 2 and not yet available.

## 2. Directory Map
- [config/hypr/hyprland.lua](file:///home/sakura/.local/share/kolir/config/hypr/hyprland.lua): Shared Hyprland config using the Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.layer_rule`, `hl.animation`). - [config/hypr/user.lua.example](file:///home/sakura/.local/share/kolir/config/hypr/user.lua.example): Template for the untracked machine-specific file (`monitors`, autostart, cursor/env, personal binds, overrides).
- [config/hypr/hyprsunset.conf](file:///home/sakura/.local/share/kolir/config/hypr/hyprsunset.conf): Valid hyprlang config for the blue-light filter. Runtime control and the automatic schedule are owned by Quickshell (`HyprsunsetService`), so native `profile { ... }` blocks should stay commented out.
- [config/hypr/scripts/](file:///home/sakura/.local/share/kolir/config/hypr/scripts): Helper scripts, all `kebab-case`:
  - `lib/root.sh`: POSIX root resolution shared by every helper (`kolir_root [script_dir]`). Order: `$KOLIR_ROOT`, then the physical root above `<dir>/config/hypr/scripts` (works through the `~/.config/hypr/scripts` symlink), then `/usr/share/kolir`. Callers pass `$SCRIPT_DIR`; `KOLIR_DIR` is still accepted as a legacy override by `brightness.sh` and `screen-record.sh`.
  - `qs-ipc.sh` / `launch-shell.sh`: resolve the root through `lib/root.sh` and `exec qs -p <root>/config/quickshell …`; use them instead of hardcoding a checkout path in binds or autostart.
  - `lib/monitors.sh`: shared monitor selection sourced by zsh and sh callers. `kolir_monitor_name` / `kolir_focused_monitor_name` resolve `$KOLIR_MONITOR`, then the focused monitor from `hyprctl monitors -j`, then the first monitor, and only `kolir_monitor_name` falls back to `DP-1`; `kolir_monitor_geometry` / `kolir_focused_monitor_geometry` return `x,y wxh`.
  - `lib/awww.sh`: version-tolerant wallpaper lookup. `kolir_awww_wallpaper_path <monitor>` asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first (also the cache root), decoding both the NUL-separated 0.12.x layout and the older one-piece layout; failures name the awww version, path, and entries found.
  - `lib/mpvpaper.sh`: video-wallpaper lifecycle. One mpvpaper process owns an output; `kolir_mpvpaper_start/restart/stop` track its pid in `$XDG_RUNTIME_DIR/kolir/mpvpaper.pid`, validate the live process through `/proc` before signalling it, run it as `mpvpaper -o 'no-audio loop hwdec=auto-safe panscan=1.0' <monitor> <video>` with a log at `~/.cache/kolir/mpvpaper.log`, and report a failed start instead of saving it. mpvpaper has no stop command, so the pid file is the only owner.
  - `lib/wallpaper.sh`: backend state and dispatch. The state file `~/.cache/quickshell/wallpaper.json` (`{"backend":"awww","image":"…","video":"…"}`) is written only by `set-wallpaper.sh`/`wallpaper-backend.sh`; `kolir_wallpaper_backend`, `kolir_wallpaper_is_video/kind`, `kolir_wallpaper_source` (live video when mpvpaper is really playing, otherwise awww with the saved image as fallback) and `kolir_wallpaper_image` (caches a one-second video frame under `~/.cache/kolir/wallpaper-frames` for Matugen) live here. Callers source `lib/awww.sh` and `lib/mpvpaper.sh` first.
  - `set-wallpaper.sh`: dispatches on the extension. Images use `awww img -t random --transition-fps 180` after stopping mpvpaper; videos restart mpvpaper and save the video path; both write the backend state. Silent exit 0 on an empty/cancelled picker, explicit errors otherwise.
  - `wallpaper-backend.sh`: switches `awww`/`mpvpaper` without touching the files. Switching to video replays the saved clip, switching to images stops the player and restores the last image, and the script is idempotent so `WallpaperService` can call it on every shell start to restore a live video.
  - `open-wallpaper-picker.sh`: primary wallpaper trigger. Toggles the Quickshell `wallpaper` panel through `qs … ipc call wallpaper toggle`; when no shell answers (or `qs` is missing) it `exec`s `select-wallpaper.sh`, so Zenity remains the fallback.
  - `select-wallpaper.sh` / `random-wallpaper.sh`: pick a wallpaper with Zenity or `find`+`shuf` (videos too), then call `set-wallpaper.sh` and `generate-colors.sh`; Random follows the active backend and falls back to an image when the video library is empty.
  - `generate-colors.sh`: sources `lib/monitors.sh` + `lib/awww.sh` + `lib/mpvpaper.sh` + `lib/wallpaper.sh` + `lib/theme.sh`, resolves the active wallpaper for the selected monitor (a cached frame for video), applies the persisted Appearance choice (scheme type, contrast, mode), then runs Matugen.
  - `toggle-theme.sh`: flips the resolved light/dark theme, syncs the persisted Appearance mode, applies GTK/KDE theme names through `lib/theme.sh`, and regenerates colors.
  - `lib/theme.sh`: shared light/dark application (`kolir_write_theme_state`, `kolir_apply_theme_mode`, `kolir_apply_system_theme`) plus `kolir_sync_appearance_mode` for `toggle-theme.sh`. POSIX; sourced by `generate-colors.sh` and `toggle-theme.sh`.
  - `brightness.sh`: forwards `up`/`down` to the Quickshell `brightness` IPC target, which drives both the internal panel (`brightnessctl`) and the external monitor (`ddcutil`); it falls back to `brightnessctl -c backlight -e4 -n2 set 5%±` only when no shell answers.
  - `screen-record.sh`: recording toggle/setup/start with `wf-recorder` (fallback `wl-screenrec`), audio mixing, encoder selection, and state files under `$XDG_RUNTIME_DIR/kolir`. It sources `lib/monitors.sh`, `screen-record/audio.sh`, `screen-record/encoders.sh`, and `screen-record/monitors.sh` through `SCRIPT_DIR=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)`.

## 3. Data Flow
```
Wallpaper (SUPER+CTRL+T grid / SUPER+CTRL+ALT+T random)
        ├─> open-wallpaper-picker.sh
        │     ├─> qs ipc call wallpaper toggle  (WallpaperPicker.qml)
        │     │     ├─> wallpaper-thumbnails.sh  ──> ~/.cache/quickshell/wallpaper-previews
        │     │     └─> selection / Random
        │     └─> select-wallpaper.sh (Zenity fallback when no shell answers)
        └─> set-wallpaper.sh (awww img for images, mpvpaper for videos)
              └─> generate-colors.sh
Theme toggle (Settings → Appearance, or toggle-theme.sh directly)
        └─> toggle-theme.sh (~/.cache/current_theme, GTK/KDE theme)
              └─> generate-colors.sh
Appearance page (SettingsMenu → AppearancePage.qml)
        └─> AppearanceService.setType/setContrast/setMode
              ├─> ~/.cache/quickshell/appearance.json
              └─> generate-colors.sh with KOLIR_MATUGEN_TYPE/CONTRAST/MODE
                    └─> ~/.config/quickshell/colors.json ──> Colors.qml (live)
generate-colors.sh
  selects the monitor ($KOLIR_MONITOR, then focused, then first, then DP-1)
  resolves the wallpaper (awww query -j, then the version-tolerant cache scan)
  selects the config ($KOLIR_MATUGEN_CONFIG, ~/.config/matugen/config.toml, repo copy)
  pre-validates every template input with python3 + tomllib
  reads ~/.cache/current_theme (creates it as dark when missing)
  reads ~/.cache/quickshell/appearance.json (env KOLIR_MATUGEN_* wins)
    scheme type: one of the ten matugen --type values (default scheme-neutral)
    contrast: -1..1 (default 0)
    mode: auto → sunrise/sunset from HyprsunsetService, light/dark explicit
  runs: matugen image <path> --source-color-index 0 --mode <mode> --type <type> --contrast <c>
        ├─> ~/.config/foot/colors.ini
        ├─> ~/.cache/terminal-sequences  ──> tee /dev/pts/* (live Foot)
        ├─> ~/.config/hypr/colors.lua    ──> hyprctl reload
        ├─> ~/.config/quickshell/colors.json

The lock background/glow step is skipped when `ffmpeg` is missing; it renders at the geometry reported by `kolir_monitor_geometry` (falling back to 2560x1440 when Hyprland cannot report a size), which keeps the lock image matched to the monitor after the earlier geometry bug.

## 4. Conventions
- **Naming**: QML files and types are `PascalCase`; JavaScript modules are `camelCase`; directories are lowercase except the existing `nightLight/` feature directory; Hyprland shell scripts and `screen-record/` helper modules are `kebab-case`. Preserve IPC targets, layer namespaces, JSON keys, and CLI arguments exactly.
- **Shared Components**: Reusable UI primitives live in `config/quickshell/bar/components/` (`Surface.qml`, `Pill.qml`, `IconButton.qml`, `AppIcon.qml`, `ProgressIndicator.qml`, `VolumeSlider.qml`, `CopyableValue.qml`, `StateLayer.qml`, `EmbeddedSheet.qml`). Prefer these over duplicating surface styling. `CopyableValue` is a read-only `Text` that copies its `value` through `wl-copy` and shows a hover copy glyph that turns into a check; use it for detail strings in settings instead of plain `Text`. Keep the owner's click area off such values: in `EthernetCard` the collapse/expand `MouseArea` covers only the summary row, because a card-wide one renders the values unclickable.
- **Singletons**: Visual tokens live in `config/quickshell/theme/` (`Colors`, `Dimensions`, `Typography`, `Icons`, `Motion`); runtime services and path contracts live in `config/quickshell/services/` (`AppearanceService`, `AudioService`, `BatteryService`, `BrightnessService`, `CaffeineService`, `DeviceBatteryService`, `EventSoundService`, `HyprsunsetService`, `ShellPaths`, `WallpaperService`). Both directories have their own `qmldir`; import both (`../theme` + `../services`, or the matching `../../` path) when a file needs them.
- **Constants**: `Dimensions` holds repeated geometry and shared metrics; `Typography` holds fonts and type scale; `Icons` holds Material Symbols names; `Motion` holds repeated UI animation roles (`color`, `theme`, `press`, `scale`, `fade`, `move`, `workspace`, `rotate`, `spin`, `popupEnter`, `popupExit`, `listEnter`, `listExit`, `osd`) plus the shared easings (`themeEasing`). Popup-specific sizes, optical offsets, process intervals and thresholds stay as local `readonly` properties. Domain constants (FPS, bitrate, CRF, temperatures, search scores, NOAA coefficients) stay local to their feature. Do not tokenize `0`/`1`, SVG coordinates, mathematical coefficients, accent-dot coordinates, or one-off optical tweaks.
- **Paths**: Every path outside the shell config goes through `ShellPaths` (`chassisType`, `hyprScripts`, `currentTheme`, `colorsJson`, `appearanceState`, `hyprsunsetState`, `deviceBatteryScript`, `deviceBatteryState`, `eventSound`, `usbWatch`, `runtimeDir`, `runtimeStateDir`, `recordingState`, `caffeineState`, `clipboardPreviewDir`, `wallpaperDir`, `wallpaperPreviewDir`, `wallpaperState`, `palettePreviews`, `palettePreviewsCache`, `cliphistStore`, `cliphistWatch`, `cliphistPreviews`, `pactlSubscribe`, `quickNoteScript`, `wallpaperThumbnails`, `completeDirs`, `listFiles`). Do not build `HOME`-based paths in QML. Shell scripts resolve the installation root through `config/hypr/scripts/lib/root.sh` (`kolir_root`), and Python through `resolve_root()` in `tools/kolir.py`; never hardcode `~/.local/share/kolir`. Binds and autostart call `sh ~/.config/hypr/scripts/qs-ipc.sh …` or `sh ~/.config/hypr/scripts/launch-shell.sh`.
- **Root & Setup**: `$KOLIR_ROOT` wins, then the physical checkout/package around the script, then `/usr/share/kolir`. `kolir setup` is idempotent: it never silently overwrites user-owned files (`user.lua`, `matugen/config.toml`, real template directories, `gtk.css` stubs, `~/.zshrc`, generated colors) and backs up every managed path it replaces to `<path>.bak.YYYYmmdd-HHMMSS` (`.1`, `.2` on collision). `--dry-run` writes nothing; re-running a configured machine reports "no changes".
- **Styling**: Use `Colors.<role>` (Material Design 3 tokens) with `Colors.withAlpha(color, opacity)` or `Colors.stateLayer(color, opacity)`. Dimensions belong in `Dimensions.*` (including `Dimensions.progress.*` for progress indicators), fonts/weights in `Typography.*`, and icon ligatures in `Icons.*`. Never hardcode colors. Palette changes crossfade through `Colors.qml` itself (one `Behavior` per color, `Motion.theme` plus `Motion.themeEasing`), so never duplicate that animation in a component: a component-level `Behavior on color` must stay for its own hover/press transitions only. `on*` colors (`onPrimary`, `onSurface`, …) cannot carry `Behavior on onPrimary` (QML reads it as a signal handler), which is why their animated value lives in a private `_on*` property with a public writable alias.
- **Hover State Layers**: A hover/selected tint is a state layer over the container, so `bar/components/StateLayer.qml` paints it as its own fill and fades its `opacity`, instead of animating `color` between the base and `Colors.stateLayer(...)`. `ColorAnimation` interpolates the alpha channel too, so an opaque `surfaceContainerHigh` turning into a 12–16 % state layer passes through a bright, still-opaque grey — the control visibly flashes once on hover-in and once on hover-out. `StateLayer` fills the parent (inheriting its `radius`) and takes `shown`, `tint`, `strength` and `duration`; settings rows (`strength: 0.14`), caffeine chips, the add-device and scan buttons, temperature presets, schedule mode chips, codec chips and the mute button all use it. Put the layer after the container's own colour/border and before the content so the label stays on top.
- **Frame Geometry**: `Frame.qml` assumes `Dimensions.frame.thickness` equals Hyprland's `general.gaps_out` (currently `4`), and `Dimensions.frame.radius` equals `decoration.rounding + border_size` (`28 + 2 = 30`). The frame path starts at `Dimensions.bar.height` because `Bar.qml` paints the 30px bar strip above it. Keep these in sync when changing gaps, rounding, or border size.
- **IPC Handlers**: Modules expose actions via `IpcHandler { target: "<name>" }`. Current targets: `launcher`, `brightness`, `volume`, `settings`, `nowPlaying`, `recording`, `recordingSetup`, `hyprsunset`, `nightLight`, `caffeine`, `appearance` (`setType`, `setContrast`, `setMode`, `setCrossfade`, `regenerate`, `status`), `shortcuts` (`toggle`, `open`, `close`), `wallpaper` (`toggle`, `open`, `close`, `random`, `openDir`, `up`, `home`, `editPath`, `setBackend <awww|mpvpaper>`, `backendStatus`), `filePicker` (`open <json>`, `cancel <id>`, `accept`, `toggleIndex <n>`, `status`). Trigger them with `qs -p <config_dir> ipc call <target> <method> [args]`.
- **Layer Namespaces**: `frame`, `bar`, `launcher`, `notifications`, `volume-osd`, `brightness-osd`, `recording-setup`, `shortcuts`, `wallpaper`, and `filepicker`. `hyprland.lua` currently adds blur rules for `launcher`, `recording-setup`, `shortcuts`, and `filepicker`; `frame` is a Bottom-layer decorative surface and needs no blur rule, `bar` must not have one (its strip and the settings sheet are opaque, and Hyprland's blur eats the layer's painted edge, which let the blurred wallpaper show through the sheet's shoulder), and `wallpaper` deliberately has none because a full-screen blur pass on every scroll frame is what made the grid sluggish. `filepicker` keeps its blur on the translucent panel itself (0.80 `surfaceContainerLow`); the full-screen layer stays transparent outside the panel, so the desktop around the picker is neither blurred nor dimmed. `OsdPanel` receives its namespace from the wrapper (`volume-osd` / `brightness-osd`).
- **Bar vs. Panels**:
  1. For a top-bar widget, add `<Widget>.qml` under `config/quickshell/bar/components/` and instantiate it in `Bar.qml`.
  2. For a standalone overlay, add a component under its own `config/quickshell/<name>/` directory and instantiate it in `ShellRoot` (`shell.qml`); give it a `WlrLayershell.namespace` and add layer rules in `hyprland.lua` when blur/anim is needed. The wallpaper picker and the shortcut sheet follow this pattern with a full-screen Overlay surface and `WlrKeyboardFocus.Exclusive`, so keys reach the panel and an outside click can dismiss it.
  3. Settings belongs inside `SettingsMenu.qml` because the popout is drawn in the bar surface: add a `MainPage.entries` item, a page component, and a height in `heightForPage()`. All three embedded sheets derive from `bar/components/EmbeddedSheet.qml`, which owns the modal scrim, the pour-shaped panel (mirrored for the right-hand sheets), the corner reveal on `Motion.sheetEnter`/`sheetExit` and the dismissal layer, so they cannot drift apart; a sheet keeps only its content and its `open()`/`close()` side effects and drives the motion through `revealOpen()`/`revealClose()`, with `didClose` for state resets and `dismissalRequested` for outside clicks. Keep that height at least as tall as the page's resting content (mirror its `implicitHeight`), otherwise the page opens with a sliver of scroll: the Internet page carries a `Flickable` for the expanded Ethernet details and the connection form, but its resting body (Ethernet, Wi-Fi, actions, 220 px network list) must fit exactly, so `internetHeight` and `InternetPage.implicitHeight` are both `546`; `appearanceHeight` and `AppearancePage.implicitHeight` are both `744`, which fits the ten circular swatches without dead space. The bar expands its input mask and enables `WlrKeyboardFocus.OnDemand` while settings is open. Page navigation inside the settings sheet is a shared-axis slide (`pageProgress`/`incomingPage`/`pageDirection` plus `Motion.pageForward`/`pageBack`), so reverse navigation runs the same transition backwards. `BrightnessPopup.qml` and `VolumePopup.qml` follow the same embedded pattern for the night-light and sound sheets, mirrored to the right screen edge. All sheets are flush with the physical screen edge on their anchor side (settings left, the other two right), so while one is open its opaque body covers the decorative frame ring and the compositor's active-window border instead of outlining the panel with a foreign colour; `Bar.qml` keeps the three sheets mutually exclusive and shares the modal mask/`OnDemand` focus condition between them.
  4. Focus-grabbing popups (for example `TrayMenu`) use `PopupWindow` + `HyprlandFocusGrab` rather than a layer-shell window.
  5. The decorative screen frame belongs in `bar/Frame.qml` on `WlrLayer.Bottom` with an empty `mask`; keep it below windows and click-through. Do not move it into the top-layer `Bar` surface, or the window border is clipped at the rounded cut-out.
- **Recording Helpers**: `screen-record.sh` stays the lifecycle/CLI owner. `lib/monitors.sh` owns shared monitor selection (`KOLIR_MONITOR`, focused, first), `screen-record/audio.sh` owns PipeWire/Pulse helpers, `encoders.sh` owns encoder/quality selection, and `screen-record/monitors.sh` owns Hyprland geometry/FPS helpers. Source them from `SCRIPT_DIR`; do not hardcode repo or home paths.

- **Known Quirks & Pitfalls**:
  - **Monitor Selection**: Wallpaper/color scripts and the recorder share `config/hypr/scripts/lib/monitors.sh`; set `KOLIR_MONITOR=<output>` to override detection (`hyprctl monitors -j` focused, then first). Only `kolir_monitor_name` falls back to `DP-1` when Hyprland cannot be queried, so the author's machine keeps working without configuration while other ports are detected. Keep new scripts on this helper instead of hardcoding an output name.
  - **awww Cache Layout**: `lib/awww.sh` never assumes an awww version directory. It asks `awww query -j` first, then scans `<cache>/awww/<version>/<monitor>` newest-first, accepts the NUL-separated 0.12.x encoding and the older one-piece encoding, and only returns paths that exist. Tested against awww 0.12.1; older/newer releases still work as long as `awww query -j` or one of those cache encodings is available, otherwise the script prints the version, path, and entries it found and exits 1.
  - **Matugen entries**: The tracked `config/matugen/config.toml` now defines `foot`, `foot-live`, `hyprland`, `quickshell`, `gtk3`, and `gtk4`. Obsidian is template-only (`templates/obsidian.css`) and gets a `[templates.obsidian]` block only when the user enables it; there is no default vault. `zen` entries remain a local customization outside the repo. `kolir setup` copies the tracked config only when `~/.config/matugen/config.toml` is absent, links missing templates into a real local templates directory, and replaces a config symlink with a local copy (with a backup) before adding the Obsidian block, so a checkout is never modified through a link.
  - **Setup gating**: setup refuses to run as root, writes nothing under `--dry-run`, and reports "no changes" on a configured machine. It never overwrites `user.lua`, an existing matugen config, real template files, existing `gtk.css`, or `~/.zshrc` (the latter is opt-in with `--zsh`); managed replacements are backed up to `<path>.bak.YYYYmmdd-HHMMSS`. A change of `<root>` requires a setup rerun because the symlinks and the Foot loader contain absolute paths.
  - **Auto-reload**: `setup --auto-reload` renders the units directly into `~/.config/systemd/user/` (watching `.version` and the git ref, running `python3 <root>/tools/kolir.py reload` in a checkout or `/usr/bin/kolir reload` in a package), verifies them with `systemd-analyze --user verify`, and enables `kolir-reload.path`; `--no-systemd` writes the units but skips systemctl. Because a systemd user unit may not inherit `WAYLAND_DISPLAY`, `reload` warns and skips the shell restart when the graphical environment is absent instead of failing.
  - **Lua Configuration**: Hyprland uses the modern Lua API (`hl.config`, `hl.bind`, `hl.window_rule`, `hl.layer_rule`), not traditional `hyprland.conf` directives.
  - **Dispatch from QML**: `Hyprland.dispatch()` forwards its argument to `hyprctl dispatch`, which in Lua-config mode wraps it as `hl.dispatch(<argument>)` and parses it as Lua. Legacy dispatcher strings such as `workspace 3` fail with `')' expected near '3'`, so `bar/components/Workspaces.qml` clicks send `hl.dsp.focus({ workspace = <id> })`. A plain bind fires on the Super press and therefore on every SUPER combo. The trigger must be the sided keysyms `SUPER_L`/`SUPER_R` (a modifier mask alone is not a trigger, and `Super_R` does not match a `SUPER_L` bind). Verify after edits with `hyprctl binds` (`key` `SUPER_L`, `release: true`, `modmask` 64) and by tapping Super vs SUPER+Space/SUPER+1/SUPER+scroll and checking `hyprctl layers` for the `launcher` namespace.
  - **Shortcut Sheet**: `SUPER+D` opens the Quickshell cheat sheet, which parses `hyprctl binds -j` (`ShortcutParser.js`) into modifier sections. Under the Lua config, Hyprland reports `dispatcher` and `arg` but the `arg` is an internal index, not the command, so `exec_cmd` rows are only readable through the bind's `description`: every bind in `hyprland.lua` sets one, and `user.lua.example` documents the option. Rows without a description fall back to a generic dispatcher name, which is why new personal binds should carry `{ description = "…" }`. The parser maps modifier bits and gestures (`mouse:272`, `mouse_down`, `XF86*`, lid switch) to readable labels, sorts rows 1…9/0, then letters, then named keys, collapses the two lone-Super binds into one row, and hides `catch_all` binds. Escape, the close button, an outside click and the IPC `close` method all dismiss it; the list is rebuilt on every open and filtered as you type.

  - **Portal File Picker**: `config/quickshell/scripts/portal-filechooser.py` is the only writer of the portal answer; `setup_portal()` in `tools/kolir.py` owns `~/.local/share/xdg-desktop-portal/portals/kolir.portal`, the D-Bus `.service` and (when absent) `~/.config/xdg-desktop-portal/hyprland-portals.conf`. The backend must answer `OpenFile`/`SaveFile`/`SaveFiles` **asynchronously** (`dbus.service.method(..., async_callbacks=("reply", "error"))`): a synchronous `OpenFile` deadlocks the portal's `Request.Close`, which the portal calls while holding the request lock and waiting for `Close` before it can process the `OpenFile` return. The shell's `{"cancelled":true}` result is response `1`, not `0` with empty URIs (Qt treats `0` as accept and returns an empty path). The portal unexports a request when the app calls `Request.Close` and deliberately emits **no** `Response`; tests must not wait for one after `Close`. `GTK_USE_PORTAL=1` covers GTK and Firefox; Qt needs `QT_QPA_PLATFORMTHEME=xdgdesktopportal` (both set in `hyprland.lua`). Qt queries the portal's `FileChooser.version` asynchronously, so a dialog opened in the first milliseconds may still fall back to the native Qt dialog; `xdg-desktop-portal.service` reads `hyprland-portals.conf` only at startup, so restart it after `kolir setup` (setup calls `busctl ReloadConfig` for the D-Bus service file and prints the restart note). If the shell is down, the backend answers `1` and tries `notify-send`; that notification only appears while a notification daemon is running.
